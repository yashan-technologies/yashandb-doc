## 版本信息

**版本号**：v23.5.2.100

**发版日期**：2026 年 4 月 17 日

## 版本定位

YashanDB数据库v23.5.2版本定位为架构版本，新增向量存储与检索功能、优化共享集群多机并行查询与单算子执行性能以及增强MySQL兼容性与产品化功能，补齐租户资源管理和运维监控能力，配套数据迁移、监控运维和开发者工具，为金融核心系统国产化替代提供高可靠、高性能、高兼容的一站式数据平台，满足支撑各类企业应用。

## 特性更新

YashanDB v23.5.2版本继承自YashanDB v23.5.1版本和v23.4.7版本全部发布的功能，同时新增了以下关键特性。

### 新增向量存储与检索功能

该版本新增向量存储与检索能力，可为企业级AI应用提供高性能、高可用的向量数据处理服务，支撑检索增强生成（RAG）、推荐系统、语义搜索等AI原生场景，助力客户快速构建智能化应用。

- 数据类型

    原生支持向量数据类型，最大维度可达65535维，支持DENSE存储格式和32位、64位浮点数存储。

- SQL运算

    支持CREATE TABLE、ALTER TABLE、CREATE INDEX等基础DDL操作，支持INSERT、UPDATE和DELETE操作及数据批量导入，支持在单条SQL语句中完成向量相似度计算+标量过滤+空间查询的混合操作，提供隐式转换、显式转换函数及向量描述函数。

- 向量索引与函数

    支持精确搜索和近似最近邻搜索，支持L2欧氏距离、内积和余弦相似度计算及其操作符，支持HNSW索引，索引列最大维度为4096。

- 驱动与协议

    原生SQL支持：提供C驱动及YASQL接口，支持Python SDK对向量数据库进行操作，仅崖山驱动协议支持向量。

- 性能

    Ann-BenchMark 100万数据测试模型下，召回率0.95以上、QPS近一千，性能持平主流向量数据库。

### 租户能力增强

- 租户资源管理能力完善

  - 支持cgroup v2：在v23.5.2版本支持cgroup v2，更好地适配和兼容高版本cgroup能力。

  - 主备CDB资源管理：在主备CDB部署环境下实现完整的租户资源管理能力，支持CPU、内存、IO全部资源的控制和管理，确保资源变更操作在主备环境间的一致性。

- 租户支持内存在线扩展

  通过新增CDB_MAX_MEMORY_SIZE参数，可调大该参数实现在不重启数据库实例、不影响业务运行的前提下动态调整租户内存配额，优化了DATA_BUFFER_SIZE、VM_BUFFER_SIZE配置参数，可通过ALTER SYSTEM在线设置生效，实现资源变更实时生效、业务无感知。

- 共享集群租户能力完善

  在v23.5.1的基础上补齐和完善了以下能力：备份恢复能力（归档备份、PITR等）、支持VIP和SCAN IP能力、PDB支持IO FENCE、全库闪回等能力。

### 功能增强

- 二级分区支持Interval组合

  新增二级分区与Interval分区的组合能力，允许将一级分区设置为Interval分区类型，实现interval-range、interval-hash、interval-list组合分区，实现分区的自动扩展管理，减少DBA日常运维工作量。

- MySQL兼容功能增强

  - 在YashanDB（mysql模式）中，索引对NULL值的处理对齐MySQL。

    支持使用NULL值创建复合唯一索引，不会触发唯一索引冲突报错，兼容MySQL的索引对NULL值处理的行为。

  - YashanDB（mysql模式）新增支持ON UPDATE CURRENT_TIMESTAMP关键字。

    支持为TIMESTAMP、DATETIME类型字段设置自动更新规则，当记录被UPDATE语句修改且未显式更新该字段时，该字段会自动更新为当前系统时间戳，简化数据更新时间的维护流程。


### 性能优化

#### SQL性能增强

- 新增ROWID过滤条件下支持Nested Loops Join路径

  当SQL语句中使用ROWID作为IN子查询的过滤条件时，优化器能够生成基于ROWID的Nested Loops Join执行计划，在返回数据量场景下性能优于传统Hash Join执行计划。

- 复杂DML优化：存在DML操作且复杂查询的大数据量场景下，通过对DELETE、CREATE AS SELECT操作进行批量执行架构适配，使优化器可自适应选择批量和并行执行框架，提升DML性能。

  - DELETE带复杂查询融合

  - CREATE AS SELECT支持融合

- 索引扫描支持批量执行

  新增索引扫描算子支持批量执行能力，该版本包含覆盖INDEX_FAST_FULL_SCAN、INDEX FULL/RANGE/SKIP SCAN以及INDEX ROWID/UNIQUE SCAN等多种扫描算子，有效提升大数据量查询性能。

- SORT算子优化，新增K-Way Merge Path算法

  对SORT排序算子进行底层架构升级，实现K-Way Merge Path高性能并行排序算法，构建大端序排序键二进制编码体系，支持排序键向UINT64高效转换，实现惰性归并、并行归并、一次IO、无中间临时文件的全新排序执行流程，实现整体排序吞吐量2~3倍提升。

- CBO使用内存优化

  通过缩减临时结构体体积、最大化结构体复用、优先使用函数栈内存、独立内存上下文管理堆内存、笛卡尔积路径裁剪等手段，降低多表关联时动态规划算法的内存消耗。使在9表、10表关联的场景下，将关联顺序生成算法从贪心算法调整为动态规划最优规划，降低CBO优化器JOIN关联内存占用，解决了关联顺序非最优、执行效率偏低的问题。

- RuntimeFilter支持批量化和并行化

  对行存执行引擎的RuntimeFilter体系进行批量框架适配，在大数据量场景下，可将过滤逻辑下沉至基础谓词执行层，实现批量、并行、流水线化的谓词计算与分发，提升Hash Join与多表关联查询的并行吞吐能力。同步完善 Autotrace 统计监控体系，支持Runtime Filter执行指标展示，提升可观测性与诊断能力。

#### 共享集群性能与稳定性增强

- 引入MTTR能力，实现系统在长时间稳定数据库性能压力下保持业务稳定可用。

-  新增多机查询能力，支持跨节点分区表、Hash Join、聚集函数等，充分利用多机CPU/内存/IO资源，加速海量数据计算。

### 高可用能力增强

- 全库闪回增强，备机/备集群可开启全库闪回能力

  在对性能要求严苛的业务系统上，用户希望开启全库闪回功能且不影响主库性能。该版本实现备库全库闪回功能，备库进行闪回后允许正常地进行数据查询、导出，获取历史数据后可轻松将其恢复成正常的物理备库，降低数据验证、数据找回成本。

- 共享集群高可用能力完善

  - 支持共享集群自动Failover：在一主多备部署场景下支持自动Failover切换，保证在主集群所有实例故障不可用时实现自动Failover，降低系统故障时间，减少RTO恢复时间。

  - 集群RTO优化：经过针对性优化，在数据库节点故障、YCS节点故障、网络故障等场景下，可在tpmC：54W测压力下集群内故障RTO小于10秒，集群间主备RTO小于30秒，满足金融级高可用指标诉求。


### 安全能力增强

- 登录告警功能

  用户每次成功登录时，将登录时间、IP地址、登录方式等信息写入审计日志，用户下次登录时将本次登录信息与上次登录信息进行比对，关键信息发生变化时向用户发出告警或提示，提醒用户注意账户可能存在的异常访问风险。

- 数据脱敏增强

  - 支持邮箱地址前缀脱敏，保留邮箱域名部分，对用户名部分进行脱敏处理。

  - 支持乱序脱敏，保持邮箱用户名部分的字符集合不变，对字符顺序进行随机重排。

  - 支持随机字符替代脱敏，将邮箱用户名部分替换为随机生成的等长字符（字母、数字组合）。

  - 支持正则表达式脱敏，支持用户自定义正则表达式规则，灵活匹配邮箱中的特定模式进行脱敏。

### 运维能力&易用性增强

- 支持ASH功能

  该版本通过数据库活动会话周期性采样，持续记录会话状态、等待事件、SQL执行信息等关键性能数据，并实现V$ACTIVE_SESSION_HISTORY视图，同时提供内置高级包DBMS_WORKLOAD_REPOSITORY，可生成ASH报告，帮助DBA高效定位性能瓶颈，显著提升数据库运维效率。

- AWR支持Segment Statistics统计项

  新增V$SEGMENT_STATISTICS相关视图，用于实时统计所有表、索引、分区、LOB段的物理读写、逻辑读写、全表扫描、锁等待、缓存命中等性能指标值，对AWR报告进行增强，新增Segment Statistics统计项，帮助数据库管理员从对象粒度精准定位I/O热点和存储瓶颈。

- 支持记录补丁和版本升级的视图

  新增DBA_REGISTRY_HISTORY系统视图，用于完整记录数据库所有补丁安装、版本升级的历史操作信息，帮助数据库管理员清晰追溯数据库组件变更轨迹，确保变更过程可审计、可回溯。

- JDBC支持CallableStatement按名称绑定参数

  新增按名称绑定参数的能力，解决位置绑定带来的参数顺序依赖、可读性差、维护困难等痛点，提升存储过程/函数调用的灵活性与可维护性。

| ---- | ---- | ---- |
| 1 | 节点数扩容时，现存所有主备库需处于正常可用状态，增加备库后数量不得超过规模约束 | 单机部署 |
| 2 | 节点数缩容时，不得直接删除主库，且不支持将所有主备库全部删除 | 单机部署 |
| 3 | DN/MN组内节点数扩容时，现存所有节点需处于正常可用状态，且主备角色正常 | 存算一体分布式集群部署 |
| 4 | DN/MN组内节点数缩容时，不得直接删除组内主节点，且不支持将组内所有节点全部删除 | 存算一体分布式集群部署 |
| 5 | 统计信息收集过程中，如果存在CN故障，则需要恢复CN后重新收集 | 存算一体分布式集群部署 |
| 6 | 扩容CN后，需要重新收集统计信息，如果有使用OUTLINE，则需要在收集统计信息完成后重建OUTLINE | 存算一体分布式集群部署 |
| 7 | INSERT INTO SELECT FROM外部表，只支持插入复制表的行表 | 存算一体分布式集群部署 |
| 8 | DROP USER失败或部分成功，则该用户不允许登录，也不允许创建该用户下的表，视图，索引，AC，DBLINK对象 | 存算一体分布式集群部署 |
| 9 | 主备集群中备集群仅一个实例是OPEN状态 | 共享集群部署 |
| 10 | 执行BLOB转字符串时，若BLOB不是合法的UTF8编码，行存引擎会忽略不合法的字符，列存引擎会返回错误 | 单机部署、共享集群部署、存算一体分布式集群部署 |
| 11 | SQLMAP原始语句及映射语句长度不得超过32000字节 | 单机部署、共享集群部署、存算一体分布式集群部署 |
| 12 | 在容器数据库的根容器上执行全局数据查询时，PDB不感知当前根容器会话上未提交的事务 | 单机部署、共享集群部署 |
| 13 | 在容器数据库的根容器上执行全局数据查询时，若查询列项中存在LOB类型列，整个查询结果集将为NULL | 单机部署、共享集群部署 |
| 14 | 在容器数据库的根容器上执行全局查询PDB信息时，若存在不同兼容模式的PDB时，此次查询不会返回MySQL模式的PDB信息 | 单机部署、共享集群部署 |
