## 版本定位

YashanDB v23.5.4.100是YashanDB发布的AI首版本，目标是打造AI-Native数据库。在原有企业级能力基础上，本版本面向AI时代的数据库范式变革，围绕三大方向全面升级：

- 以原生多模态统一架构突破传统“拼接式”多模态的结构性缺陷，让所有数据模态共享统一内核，为RAG、知识图谱、智能搜索等AI应用提供多模态数据的统一存储与融合查询能力。

- 引入内核级数据沙箱技术，实现“像管理代码一样管理数据”，为AI智能体提供低成本、并行化的数据实验环境，让AI的“无限尝试”成为可能。

- 扩展模型管理与AI函数生态，使数据库从数据存储引擎进化为AI推理底座，支持数据不出库完成Embedding向量化、LLM生成、Rerank重排等AI推理，大幅简化AI应用的数据管道。

#### 图模型

YashanDB基于SQL 2023 SQL/PGQ标准，将图模型构建为关系数据之上的语义抽象层，实现“一套存储、双模查询”：

- 零冗余存储：图并非独立引擎，节点与边的物理数据直接存储于普通SQL表，表列即属性，无任何数据复制。

- 实时一致性：底层表上的INSERT/UPDATE/DELETE实时反映到图视图，图与关系数据零延迟同步，无需ETL或物化刷新。
- 智能查询重写：图模式自动转换为JOIN + 递归CTE，可以直接复用现有索引。
- 高性能执行：基于外键消除与批量并行优化技术，图查询性能表现优异。

图创建示例：

```sql
-- 创建属性图
CREATE PROPERTY GRAPH graph_name
VERTEX TABLES (
    table_name KEY (col1, col2) LABEL label_name PROPERTIES (col3, ...)
)
EDGE TABLES (
    edge_table KEY (edge_pk)
    SOURCE KEY (src_col1, src_col2) REFERENCES vertex_table(src_col1, src_col2)
    DESTINATION KEY (dst_col1, dst_col2) REFERENCES vertex_table(dst_col1, dst_col2)
    LABEL edge_label PROPERTIES (prop1, ...)
);
```

图查询示例：

```sql
-- 图查询（GRAPH_TABLE）
SELECT * FROM GRAPH_TABLE(graph_name
    MATCH (v is label_name)-[e is edge_label]->(f is node_label)
    COLUMNS(e.column_name)
);
```

#### 全文模型

YashanDB基于倒排索引构建全文检索能力，提供原生的文本搜索体验：

- 丰富的布尔检索：支持AND/OR/NOT及组合表达式，灵活表达复杂查询意图。

- 智能分词：中英文混合分词、大小写不敏感、停用词可配置。内置歧义消解，提升召回准确率。
- 多类型文本支持：原生支持CHAR、VARCHAR、CLOB三种文本列类型，覆盖结构化与非结构化文本场景。
- LIKE零成本加速：LIKE表达式在分词可覆盖时自动转写为全文索引扫描，零回表、零业务SQL改造，应用无感升级。

全文检索函数如下表所示：

|函数|功能|
|---|---|
|contains(column, '表达式')|在指定列中搜索关键词|

|操作符|说明|
|---|---|
|  `&`  （AND）|逻辑与，两词都必须出现|
|  `|`  （OR）|逻辑或，两词任一出现即可|
|  `~`  （NOT）|逻辑非，排除包含该词的文档|
|  `"phrase"`  |短语精确匹配|
|  `=`  |等价匹配|

#### 文档模型

YashanDB通过JSON数据类型，提供半结构化的文档存储与查询能力，灵活应对Schema多变的业务场景：

- 二进制原生存储：以原生二进制而非文本存储，对高频访问路径预计算偏移量，查询时无需完整解析文档即可直接定位嵌套字段。

-  丰富的路径函数：提供符合SQL/JSON标准的路径表达式及JSON_EXISTS、JSON_VALUE、JSON_QUERY、JSON_TABLE等函数，支持嵌套字段的提取和过滤。
- JSON函数索引加速：基于函数索引为JSON路径建立B+ 树，将嵌套字段检索从全文档扫描转为索引定位，查询性能大幅提升。

相关的接口如下表所示：

|函数|功能|
|---|---|
|  JSON(text) <br/> JSON_PARSE(text)  |将文本解析为JSON类型|
|  JSON_QUERY(json, '$.path' [RETURNING type] [PRETTY] [WITH &#124; WITHOUT ARRAY WRAPPER])  |按路径检索JSON片段|
|  JSON_VALUE(json, '$.path' [RETURNING type])  |按路径提取单个标量值|
|  JSON_EXISTS(json, '$.path')  |判断路径是否存在|
|  JSON_ARRAY_LENGTH(json)  |返回数组元素个数|
|  JSON_ARRAY_GET(json, index)  |按索引取数组元素|
|  JSON_SERIALIZE(json [RETURNING type] [PRETTY])  |将JSON序列化为文本|
|  JSON_TABLE(json, '$.path' COLUMNS (...))  |将JSON展开为虚拟关系表|
|  JSON_EXTRACT(json_col, '$.path')  |路径匹配多个部分|

索引示例：

```sql
-- JSON函数索引创建

    JSON_VALUE(json_col, '$.field' RETURNING VARCHAR(100))
);
-- 索引查询
select * from table_name where JSON_VALUE(json_col, '$.field' RETURNING VARCHAR(100)) = 'china';
```

#### 非结构化文件管理

YashanDB将文件提升为与表同等地位的“一等公民”，文件不是数据库的外部引用，而是数据库内的原生存储对象：

- 层次目录语义：保留与Linux文件系统一致的目录结构，文件以原生方式存在于数据库内部，无需借助外部对象存储或文件系统挂载。
- 事务一致性：文件的CREATE/WRITE/REMOVE与普通DML共享同一套ACID与MVCC机制，可与业务表在同一事务中原子提交或回滚。
- 统一安全与运维：文件访问受数据库权限体系统一管控，操作记入全局审计日志；全量/增量备份与PITR同时覆盖结构化数据与文件，无类型差异。

DBMS_FS高级包接口如下表所示：

|类别|接口|功能|
|---|---|---|
|卷管理|  CREATE_VOLUME(name, tablespace, bucket, size)<br/>DROP_VOLUME(name[, force])<br/>SET_VOLUME(name)<br/> GET_VOLUME(out name)  |创建/删除/设置/获取存储卷|
|目录操作|  MKDIR(path)<br/> RMDIR(path[, recursive])<br/>LISTDIR(path, out entries, out count)  |创建/删除/列出目录|
|文件操作|  CREATE(path)<br/>WRITE(path, content) <br/>READ(path, offset, len, out buf, out len)<br/>REMOVE(path)<br/>EXIST(path, out flag)<br/>STAT(path, out filestat)  |写入/读取/删除/检查存在/获取元数据|

存储卷示例：

```sql
CREATE TABLESPACE ts_name DATABUCKET 'bucket_name' MAXSIZE 1G;
EXEC DBMS_FS.CREATE_VOLUME('vol_name', 'ts_name', 'bucket_name', 1073741824);
EXEC DBMS_FS.SET_VOLUME('vol_name');
```

#### 空间模型

YashanDB的空间模型是内核原生的GIS引擎，从数据类型、空间函数、空间索引到查询优化器深度集成。

- 类型体系：支持Point、LINESTRING、POLYGON、MULTIPOINT、MULTILINESTRING、MULTIPOLYGON、GEOMETRY COLLECTION数据类型。

- R-Tree空间索引：通过最小外包矩形（MBR）近似技术，查询时先通过树的层次结构快速排除不相交的MBR，仅在少量候选对象上做精确几何计算。

空间数据类型：

|数据类型|说明|
|---|---|
|  GEOMETRY  |表明该列可以为任意子类型|
|  GEOMETRY(subtype, srid)  |指定子类型和坐标系，其中srid可缺省，缺省时默认为0，例如`GEOMETRY(point, 4326)`  |

主要的空间函数：

|函数|说明|
|---|---|
|  ST_GeomFromText(wkt, srid)  |根据输入的WKT格式的数据构造Geometry对象|
|  ST_AsText(geom, maxdecimaldigits)  |支持将Geometry对象以WKT格式输出|
|  ST_Contains(geom1, geom2)  |判断geom1和geom2是否存在包含关系|
|  ST_Collect(geomCol)  |将geomCol这一列的geom数据聚合成一个大的几何对象|
|  ST_MakeValid(geom)  |将无效几何转换为有效几何|

#### 时序模型

以YashanDB为统一业务入口，深度集时序组件，实现时序数据的一体化安装部署、关系数据与时序数据的跨模融合分析，支撑工业物联网系统开发和应用：

- 时序-关系联邦：通过TIME_SERIES_TABLE表函数支持时序数据与关系数据的关联查询。

- 数据模型：同时支持层级树模型与结构化表模型。层级树模型采用`root.company.factory.device.测点`式路径命名，基于PBTree元数据管理亿级时间序列，支持 5 类 15 种序列级权限控制。结构化表模型支持标准SQL语法、免模式写入、动态静态数据统一管理，时间/标签/测点/属性四维融合。
- 时序查询能力：提供降采样（高频数据按周期聚合，如每 5 分钟取均值）、时序分段（按变化阈值/中断间隔分段，如统计设备开机时长）、数据补齐修复（`valueFill`缺值填补、`valueRepair`错值修复）、UDF（UDSF/UDAF/UDTF）、趋势搜索等能力。

#### 多模态关联能力

YashanDB在同一SQL语义下支持各模态数据的融合查询，多模态数据可在一个语句中联合访问、过滤与计算，例如：

|融合场景|技术实现|业务价值|
|---|---|---|
|向量 + 图联合推理|图遍历中叠加向量相似度过滤，关系路径可达AND语义相似|企业风控（资金链关联+行业语义）、智能推荐（社交关系+兴趣相似）|
|关系 + 向量深度融合|优化器协同B+树索引和HNSW向量索引，“先过滤、再检索”|结构化条件将向量检索范围压缩两个数量级，精准度与召回质量双重保障|
|关系 + 图深度JOIN|图节点与关系表在统一存储引擎内直接关联，混合图路径和结构化字段条件|一个SQL完成图遍历+关联查询+聚合计算，无需跨库手动合并|
|多模态联合查询|跨模态JOIN + 全模态索引感知 + 跨模态谓词下推 + 统一快照隔离|一次SQL完成关系表过滤 + JSON提取 + 向量排序 + 图关联 + 聚合计算|

#### 多模态联合查询示例

```sql
drop table if exists tb_company;
create table tb_company(id int, name varchar(200), embedding vector(3));
CREATE VECTOR INDEX vidx1 ON tb_company (embedding) ORGANIZATION NEIGHBOR GRAPH DISTANCE COSINE;
create search index sidx2 on tb_company(name);
insert into tb_company values 
	(1, 'oceanbase', '[1,0,0]'),
	(2, 'orcale database', '[1,0,3]'),
	(3, 'yashan database', '[1,0,2]'),
	(4, 'tidb', '[1,0,1]');
commit;

select id, name from tb_company where contains(name, 'database') > 0 ;
select id, name from tb_company order by cosine_distance(embedding, to_vector('[1, 1, 1]', 3)) FETCH APPROXIMATE FIRST 2 ROWS ONLY;
select id, name from tb_company where contains(name, 'database') > 0 union (select id, name from tb_company order by cosine_distance(embedding, to_vector('[1, 1, 1]', 3)) FETCH APPROXIMATE FIRST 2 ROWS ONLY);

create or replace view entity as select id, name from tb_company where contains(name, 'database') > 0 and id > 1 union (select id, name from tb_company order by cosine_distance(embedding, to_vector('[1, 1, 1]', 3)) FETCH APPROXIMATE FIRST 2 ROWS ONLY);

drop table if exists relation;
create table relation(r_id int, s_entity_id int, d_entity_id int, label varchar(20));
insert into relation values(1, 1, 2, 'label1');
insert into relation values(2, 1, 3, 'label2');
insert into relation values(3, 1, 4, 'label3');
insert into relation values(4, 3, 4, 'label4');
insert into relation values(5, 2, 3, 'label5');
insert into relation values(6, 3, 2, 'label6');
commit;

drop property graph if exists entity_graph;
create property graph entity_graph
VERTEX TABLES (
    entity key (id)
	LABEL entity_prop
	propertities (name)
)
EDGE TABLES (
	relation key (r_id)
	source key (s_entity_id) references entity(id)
	destination key (d_entity_id) references entity(id)
	LABEL relation_prop
	propertities (label)
);

SELECT aname, label_num, bname
FROM GRAPH_TABLE(entity_graph
    MATCH (a is entity_prop)-[r is relation_prop]->{1,2}(b is entity_prop)
    COLUMNS(a.name as aname, count(r.label) as label_num, b.name as bname)
);

SELECT aname, label, bname
FROM GRAPH_TABLE(entity_graph
    MATCH (a is entity_prop)-[r is relation_prop]->(b is entity_prop)
    COLUMNS(a.name as aname, r.label as label, b.name as bname)
);
```

### 数据分支

YashanDB在内核中扩展了原生的数据沙箱引擎，通过引入分支（Branching）技术，为用户提供了一种便捷、轻量且安全的数据环境管理能力，让用户能够“像管理代码一样管理数据”：

- 便捷：通过DBMS_BRANCH高级包提供完整的分支生命周期管理接口。

- 轻量：采用写时拷贝（Copy-on-Write）技术，新分支创建时共享父分支的数据块，只有在写入时才真正复制被修改的数据块。瞬时创建、存储共享、成本不随分支数量线性增长。
- 安全：每个分支拥有独立的数据视图，事务隔离、连接隔离、权限隔离天然保障。误操作可通过重置或恢复功能回滚。

相关接口如下表所示：

|接口|功能|
|---|---|
|  CREATE(name, parent, checkout, default)  |创建分支（可指定父分支，可创建后立即切换）|
|  CURRENT()  |获取当前分支|
|  CHECKOUT(name)  |切换分支|
|  RENAME(old_name, new_name)  |重命名分支|
|  LIST()  |列举分支|
|  RESET()  |重置当前分支|
|  RESTORE(timestamp_or_scn)  |恢复分支到指定时间点|
|  FREEZE(name) <br/> ACTIVATE(name)  |冻结/激活分支|
|  SET_RESOURCE(name, util_limit, memory)  |设置分支资源限制（util_limit为并发数，memory为内存上限）|
|  SET_EXPIRATION(name, timestamp)  |设置分支过期时间|
|  DELETE(name)  |删除分支|
