## 规划系统盘（共享集群部署）

共享集群部署中，如需从23.2.x.x及以前版本离线升级至23.4.x.x及以上版本，必须执行本操作。

1. 在共享存储上规划系统盘，具体操作请查阅[磁盘划分](../安装部署/安装前准备/配置存储设备.md#DiskPartitioning)。

2. 在tmp_upgrade目录新建disk_config.toml文件，参考[共享集群升级配置文件](../../工具手册/yasboot/配置文件/共享集群升级配置文件.md)并结合实际磁盘规划进行文件内容编辑，确认无误后保存退出。

    ```shell
    $ vi disk_config.toml
    
    [[group]]
        group_id = 1                    # 共享集群组ID
        disk_found_path = "/dev/yfs"    # 指定磁盘发现路径，即数据盘的上一层目录，数据盘信息可通过yfscmd show disk命令查询
        system_data = ["/dev/yfs/sys0", "/dev/yfs/sys1", "/dev/yfs/sys2"]   # 指定为规划的系统盘路径
    
    [[group]]                           # 主备集群部署时，备集群参考主集群的示例修改，若无可删除
        group_id = 2        
        disk_found_path = "/dev/yfs2"
        system_data = ["/dev/yfs2/sys0", "/dev/yfs2/sys1", "/dev/yfs2/sys2"]
    ```

## 检查滚动升级环境

如需进行[滚动升级](./升级操作/滚动升级.md)，须确保当前数据库满足以下条件：  

- 数据库为yashan模式。  
  
    通过以下SQL语句查看数据库模式：  
    
    ```sql
    show parameter compat_vector
  
    name                                                              value                                                            
    ----------------------------------------------------------------  ---------------------------------------------------------------- 
    COMPAT_VECTOR                                                     yashan                                                           
    ```

    若当前环境为mysql模式，请使用[离线升级](./升级操作/离线升级.md)。  

- 数据库不存在身份列。

    通过以下SQL语句查看数据库中身份列数量：  

    ```sql
    select count(*) from DBA_TAB_COLS where IDENTITY_COLUMN = 'Y';
    
                count(*) 
    --------------------- 
                        0
    ```

    若当前数据库中存在身份列，请使用[离线升级](./升级操作/离线升级.md)。  

- 数据库不存在虚拟列。

    通过以下SQL语句查看数据库中虚拟列数量：  

    ```sql
    select count(*) from DBA_TAB_COLS where VIRTUAL_COLUMN = 'Y';
    
                count(*) 
    --------------------- 
                        0
    ```

    若当前数据库中存在虚拟列，请使用[离线升级](./升级操作/离线升级.md)。  
  
- 数据库不存在LSC表。

    通过以下SQL语句查看数据库中LSC表的数量：  

    ```sql
    select count(*) from DBA_TABLES where TABLE_TYPE = 'LSC';
    
                count(*) 
    --------------------- 
                        0
    ```

    若当前数据库中存在LSC表，[滚动升级](./升级操作/滚动升级.md)仅适用于兼容版本，跨非兼容版本的升级操作请使用[离线升级](./升级操作/离线升级.md)。

## 上传新版本安装包

路径、安装包名称等请替换为实际值。

1. 以安装用户登录数据库安装服务器。

2. 创建一个空目录，该目录将作为升级安装包的临时存放路径。

    ```shell
    $ cd /home/yashan
    $ mkdir tmp_upgrade20250930
    ```
    > **Note**:
    >
    > tmp_upgrade20250930仅为示例值，实际操作时建议采用新版本号或操作日期命名该目录，便于管理与区分。
    
3. 将新版安装包上传至/home/yashan/tmp_upgrade中。

4. 进入升级安装包的存放目录并解压安装包。

    ```shell
    $ cd tmp_upgrade
    $ tar zxf yashandb-{新版本号}-linux-x86_64.tar.gz
    ```

## 检查hosts.toml文件

hosts.toml文件的默认路径为/home/yashan/install/hosts.toml。

### 检查yasom信息

如果升级前执行过yasom相关的切换操作，请确保升级时hosts.toml中om的LISTEN_ADDR为当前主yasom。

1. 查看当前环境中yasom相关信息。

    ```shell
    $ yasboot process yasom status -c yashandb
    +------------------------------------------------------------------------------------------------------------------------------------+
    | hostid   | pid   | ipaddr       | primary           | secondary | local_yasom_addr  | role    | backup_num | max_seq | auto_repair |
    +------------------------------------------------------------------------------------------------------------------------------------+
    | host0001 | -     | 192.168.1.2  | 192.168.1.3:1675  | []        | -                 | -       | 2          | 54      | -           |
    +----------+-------+--------------+-------------------+-----------+-------------------+---------+------------+---------+-------------+
    | host0002 | 27584 | 192.168.1.3  | 192.168.1.3:1675  | []        | 192.168.1.3:1675  | primary | 2          | 54      | off         |
    +----------+-------+--------------+-------------------+-----------+-------------------+---------+------------+---------+-------------+
    ```

    根据回显可知，当前环境中yasom的LISTEN_ADDR为`192.168.1.3:1675`、所在服务器hostid为`host0002`。  

2. 确认role为primary的yasom的local_yasom_addr与hosts.toml中om的LISTEN_ADDR和hostid是否相同。若不同，请手动修改hosts.toml中om的LISTEN_ADDR、hostid与主yasom的一致。

    ```toml
    $ cat hosts.toml
    
    ……
    [om]
      hostid = "host0001"	
      [om.config]	
        LISTEN_ADDR = "192.168.1.2:1675"
    ……
    # hosts.toml文件中yasom的LISTEN_ADDR、hostid均与实际不一致，需修改
    
    $ vi hosts.toml
    
    ……
    [om]
      hostid = "host0002"	
      [om.config]	
        LISTEN_ADDR = "192.168.1.3:1675"
    ……
    ```

### 检查服务器信息

如果升级前执行过新增服务器的扩容操作，需确保新增的服务器的信息已追加到hosts.toml文件中。

## 确认临时目录的权限及空间

### 滚动升级 

[滚动升级](升级操作/滚动升级)时会自动创建安装新版本数据库的目录，请确保操作用户拥有创建该目录的权限，且具备充足的存储空间。

<span id="space" name="space"></span>

### 离线升级 

[离线升级](升级操作/离线升级)时会自动进行数据库备份，备份范围包括当前数据库的控制文件、redo文件、SYSTEM表空间文件、SYSAUX表空间文件以及UNDO表空间文件。备份目录可自定义按需规划（升级前手动创建），也可使用默认目录（升级过程中自动创建）。

若升级失败，执行离线升级回退时需使用该备份集。

#### 容量估算 

备份路径的容量需高于备份刚需容量和额外预留容量的总和，系统会先检测容量是否满足要求再根据检测结果判断是否继续执行后续操作。

| 容量分类| 容量估算（查询）方法 |
|-------------|-------------------------|
| 备份刚需容量 | 方式一：使用SQL语句查询并统计各文件的大小<br/>`SELECT (SELECT SUM(BYTES) FROM V$CONTROLFILE) +  (SELECT SUM(USED_BLOCKS * BLOCK_SIZE) FROM V$LOGFILE) +  (SELECT SUM(BYTES) FROM DBA_DATA_FILES WHERE TABLESPACE_NAME IN ('SYSTEM', 'SYSAUX', 'UNDO')) AS total_capacity FROM DUAL;`<br/><br/>方式二：根据各服务器中$YASDB_DATA/dbfiles路径的总容量估算 |
| 额外预留容量                          | 默认值为5G，可通过--backup-reserved-space参数自定义指定预留容量      |

#### 自定义备份路径及权限要求 

如需使用自定义的备份路径，需在升级前创建符合容量的路径并完成相应的权限配置，升级时需通过--backup-path参数指定该路径作为备份路径。

| 部署形态 | 备份位置 | 权限要求 |
|--------------------|-------------|-------------------------|
| 单机部署<br/>存算一体分布式部署 | 在每台服务器上自定义创建相应路径，每台服务器上的路径应一致 | 安装用户对该路径具备读写权限 |
| 共享集群部署 | 在主实例所在服务器上自定义创建相应路径 | 安装用户对该路径具备读写权限 |

升级成功或回退成功后，该目录会自动清空。

#### 默认备份路径及权限要求 

如需使用默认的备份路径，无需手动创建，但需确保升级操作用户具备创建路径的权限，以及默认备份路径所在父目录${新版本的YASDB_HOME}具备足够的容量。

| 部署形态 | 备份位置 |
|--------------------|-------------|
| 单机部署<br/>存算一体分布式部署 | 每台服务器的${新版本的YASDB_HOME}/upgrade_tmp/backup |
| 共享集群部署 | 主实例所在服务器的${新版本的YASDB_HOME}/upgrade_tmp/backup |

升级成功或回退成功后，该目录会自动删除。

## 暂时终止守护进程

升级前请检查并终止各实例所在服务器上的守护进程，若已配置开机自启动，需先暂时[关闭自启动](../安装部署/安装后初始环境/配置开机自启动.md#disable)。

> **Caution**:
>
> 此步骤仅需终止与YashanDB相关的守护进程，无需终止其他应用相关的或系统本身的monit进程。

```shell
# 执行yasboot monit status命令或yasboot monit summary命令确认是否存在monit进程
$ yasboot monit status -c yashandb

# 若存在，需终止YashanDB相关的守护进程
$ yasboot monit stop -c yashandb
+---------------------------------------------------------------------------------------------------------+
| type | uuid             | name            | hostid | index    | status  | return_code | progress | cost |

+------+------------------+-----------------+--------+----------+---------+-------------+----------+------+
task completed, status: SUCCESS
```

## 暂时关闭yasom仲裁选主

若当前环境为单机一主一备部署、主备集群部署或存算一体分布式高可用部署（DN组内节点为一主一备），需要执行当前操作检查并关闭yasom仲裁选主再执行后续操作。

1. 执行如下命令，检查yasom仲裁选主是否开启：

    ```shell
    $ yasboot election config show -c yashandb
    group 1
      Protection Mode: MAXIMUM PROTECTION
      Members:
        [1-1:1] - Primary database
          [1-2:2] - Physical standby database
                      Transport Lag: 0 seconds
                      Apply Lag:     0 seconds
                      Apply Rate:    3.79 MByte/s

      Properties:
        FailoverThreshold      = 9
        FailoverAutoReinstate  = false
        ZeroDataLossMode       = true

    Automatic Failover: Enabled in Zero Data Loss Mode # Enabled表示已开启yasom仲裁选主
    ```

2. 若已开启，需执行如下命令关闭yasom仲裁选主：

    ```shell
    $ yasboot election enable off -c yashandb
    ```

升级完成后，请按需还原相关配置，具体操作请查阅[yasom仲裁选主](../../高可用/自动选主配置/yasom仲裁选主.md)。

## 检查并开启操作系统认证

升级前请检查并确保已开启[操作系统认证](../../产品安全/身份标识与鉴别/操作系统认证/00操作系统认证.md)功能，且已为安装用户开通操作系统认证。

1. 验证操作系统认证：

    ```shell
    $ yasql / as sysdba

    YashanDB SQL Enterprise Edition Release {version_number} x86_64

    Connected to:
    YashanDB Server Enterprise Edition Release {version_number} x86_64 - Linux

    SQL> SELECT SYS_CONTEXT ( 'USERENV' , 'SESSION_USER' ) FROM DUAL;

    SYS_CONTEXT('USERENV                                             
    ---------------------------------------------------------------- 
    SYS      
    ```

    仅当本地无法免密登录成功时，需进行后续操作进一步检查并完成相应配置。

2. 执行如下命令，检查操作系统认证功能是否开启：

    ```shell
    # 检查是否存在yasdb_net.ini文件以及文件中ENABLE_LOCAL_OSAUTH的配置
    $ cat $YASDB_DATA/config/yasdb_net.ini
    ```
    仅当文件存在且文件中配置了ENABLE_LOCAL_OSAUTH = off时表示功能已关闭。此时，需执行以下操作完成配置：
    
    ```shell
    # 将ENABLE_LOCAL_OSAUTH的值修改为on
    $ vi $YASDB_DATA/config/yasdb_net.ini
    ```
    保存并退出，重启数据库使配置生效。

3. 执行如下命令，检查是否已为安装用户开通操作系统认证：

    ```shell    
    # 检查安装用户是否已加入YASDBA组
    $ groups
    yashan YASDBA
    ```
    若回显信息提示安装用户已加入YASDBA组则表示已为安装用户开通操作系统认证，否则需执行以下操作完成配置：（groupadd命令、usermod命令需使用root用户或sudo权限的用户执行）
    
    ```shell
    # 检查是否存在YASDBA组    
    $ getent group YASDBA

    # 若不存在则新建YASDBA组
    $ sudo groupadd YASDBA

    # 将安装用户加入YASDBA组
    $ sudo usermod -aG YASDBA yashan
    ```

::: tabs

instance_status字段为open表示对应实例处于OPEN状态，mounted表示对于实例处于MOUNT阶段，started表示实例处于NOMOUNT阶段。

| host0002 | db        | 1-2:2  | 49529 | open            | normal          | standby       | 192.168.1.3:1688 | /data/yashan/yasdb_data/db-1-2 |

共享集群部署中，升级前请确保YFS的所有磁盘组均处于正常挂载状态，可通过如下方式检查磁盘组状态：

::: tabs
== yfscmd命令

## 全量备份

YashanDB提供两种备份的方式，分别是通过SQL语句和使用yasrman工具，如需了解更多有关备份的语法及说明请查阅[备份与恢复](../../数据库管理/备份与恢复/00备份与恢复)。

- 使用SQL语句：适用于单机部署和共享集群部署

  SQL语句执行备份需登录数据库实例进行操作，可通过执行如下语句执行全量备份：

  ```sql
  BACKUP DATABASE FULL FORMAT '/home/yashan/full_20221123' TAG 'full' PARALLELISM 8 COMPRESSION ALGORITHM ZSTD LOW;
  ```

- 使用yasrman工具：适用于所有部署形态

  使用yasrman工具进行全量备份须确保在yasrman工具所在服务器上操作，可通过执行如下命令执行全量备份：

  ```shell
  # 单机/共享集群/分布式集群部署
  $ yasrman sys/********@192.168.1.2:1688 -c "BACKUP DATABASE TAG 'full_backup' FULL FORMAT 'full_001' PARALLELISM 8 COMPRESSION ALGORITHM ZSTD LOW" -D /home/yashan/catalog
  
  # 存算一体分布式集群部署
  $ yasrman sys/********@192.168.1.2:1688 -c "BACKUP CLUSTER TAG 'full_1' FORMAT 'full_bak_1' PARALLELISM 8 COMPRESSION ALGORITHM ZSTD LOW" -D /home/yashan/catalog
  ```
