本步骤仅适用于使用共享集群部署和分布式集群部署场景，其他场景请略过。

在共享集群部署中，采用NVMe-oF分布式存储设备时，服务器被分为两类：部署实例的服务器（以下简称实例服务器）和挂载NVMe SSD的服务器（以下简称存储服务器）。

在分布式集群部署中，服务器则被分为计算节点服务器（以下简称CN服务器）和数据节点服务器（以下简称DN服务器）两类，其中DN服务器上将挂载NVMe SSD。

## 磁盘划分

崖山文件系统管理（YFS）以磁盘作为存储管理的逻辑单元，并根据使用目的区别为如下两类：

- **系统盘**
  
   用于集群管理，仅支持1、2、3或5块**相同大小**的磁盘，每块磁盘容量至少1G（当系统盘数量为1块且AU Size需配置为32M时，要求系统盘大小至少为2G），此类磁盘的绝对路径将作为--system-data参数的值，以`,`分隔多个磁盘进行配置，例如`--system-data /dev/yfs/sys0,/dev/yfs/sys1,/dev/yfs/sys2`。绝对路径由本文下述配置生成。
	
	规划的系统盘个数会影响系统盘组的冗余度（redundancy），1、2/3或5块系统盘分别对应的冗余度为EXTERNAL、NORMAL或HIGH。
	
	规划的系统盘在安装后无法再更改，请在此步进行确定，如无法确定可咨询我们的技术支持。

- **数据盘**

   用于保存集群业务数据，1块或多块**相同大小**的磁盘，请根据实际业务需求规划其数量和容量，此类磁盘的绝对路径将作为--data参数的值，以`,`分隔多个磁盘进行配置，例如`--data /dev/yfs/data0,/dev/yfs/data1,/dev/yfs/data2`。绝对路径由本文下述配置生成。
	
	考虑到数据盘组的冗余度，可按实际需求量的倍数规划数据盘的数量。也可在后期运行过程中再根据情况增加数据盘。
		

在对共享磁盘阵列或NVMe SSD做磁盘划分时，划分单元的用途和容量应与上述两类磁盘进行对应，例如规划3个2G大小系统盘，则需要在共享磁盘阵列划分3个2G大小的LUN，或者在NVMe SSD上划分3个2G大小的命名空间。本文不对存储设备的磁盘划分提供操作指引，请根据厂商提供的安装指导操作。

## 共享集群（共享存储）部署下绑定磁盘

请在共享集群部署中的**所有服务器**上执行下述操作。本标题下所述操作执行结束即完成共享集群（共享存储）部署下的存储设备配置，本文档其他内容请略过。

- 绑定目录和磁盘的绝对路径均将作为`yasboot package ce gen`命令的相应参数值，如有修改，请在执行`yasboot package ce gen`时使用实际值。

#### 方式一：通过多路径绑定 



##### 步骤1：生成配置文件

1. 以root用户登录服务器。

2. 在root目录下创建名称为`genDevRuleByUUID.sh`的脚本：

   ```shell
   # cd ~
   # vi genDevRuleByUUID.sh
   ```

3. 输入如下内容，并根据部署环境修改`DEVICES`为各设备路径，修改`TARGETS`为各设备绑定名称，名称应与设备路径一一对应，修改`YFS_DISK_DIR`为绑定目录，保存并退出。



   ::: tabs
   == CentOS

```shell
#/bin/bash

# 请修改为各设备路径
DEVICES=("/dev/mapper/lun01-data0" "/dev/mapper/lun03-sys0" "/dev/mapper/lun04-sys1" "/dev/mapper/lun05-sys2")
# 请按DEVICES数组顺序指定这些设备绑定的名称，且建议指定为与业务相关的名称
TARGETS=("data0"                   "sys0"                   "sys1"                   "sys2")
# 指定绑定的目录
YFS_DISK_DIR="yfs"

# 请保持默认，请确保yashan用户已存在
USER="yashan"
GROUP="yashan"
UGROUP="$USER:$GROUP"

if [ ${#TARGETS[@]} != ${#DEVICES[@]} ]
then
    echo "DEVICES and TARGETS count does not match"
    exit 1
fi

if [ ${#TARGETS[@]} == 0 ]
then
    echo "no targets found"
    exit 1
fi

curDir=$(cd "$(dirname "$0")";pwd)
rm -f $curDir/yashan-device-rule.rules

count=${#TARGETS[@]}

for ((i = 0; i < $count; i ++))
do
    device=${DEVICES[$i]}
    target_name=${TARGETS[$i]}
    target="${YFS_DISK_DIR}/${target_name}"
    
    str1="$device:`udevadm info --query=all --name=$device | grep DM_UUID`"
    str2=${str1#*=}
    echo "KERNEL==\"dm-*\",ENV{DM_UUID}==\"${str2}\",SYMLINK+=\"$target\",OWNER=\"$USER\",GROUP=\"$GROUP\",MODE=\"0666\",OPTIONS:=\"nowatch\",RUN+=\"/bin/sh -c 'chown -R $UGROUP $target'\""  >> $curDir/yashan-device-rule.rules
done
```

##### 步骤2：绑定存储设备

1. 将配置文件移动至/etc/udev/rules.d目录下。

   ```shell
   # cp yashan-device-rule.rules /etc/udev/rules.d/yashan-device-rule.rules
   ```

   ```shell
   # udevadm trigger --sysname-match=sdf
   ```

##### 步骤3：检查绑定结果

1. 执行如下命令，确认所有绑定已生效，用户和组均为`yashan`：

   ```shell
   # ls -l /dev/yfs/*
   lrw-rw-rw- 1 yashan yashan 7 Jul 11 14:44 data0 -> ../dm-5
   lrw-rw-rw- 1 yashan yashan 7 Jul 11 14:44 sys0 -> ../dm-7
   lrw-rw-rw- 1 yashan yashan 7 Jul 11 14:44 sys1 -> ../dm-4
   lrw-rw-rw- 1 yashan yashan 7 Jul 11 14:44 sys2 -> ../dm-6
   ```

   并检查它们指向设备的用户和组均为`yashan`，且权限为`0666`：

   ```shell
   # ls -l /dev/dm-4
   brw-rw-rw- 1 yashan yashan 253, 4 Jul 11 14:44 /dev/dm-4

   # 其他设备类似
   ```

2. 在集群所有服务器上执行以下命令，确认各服务器上**所有**绑定的多路径WWID一致。

   ```shell
   # 对比各服务器上的输出结果是否对应一致
   # /lib/udev/scsi_id --whitelisted  --device=/dev/yfs/data
   # /lib/udev/scsi_id --whitelisted  --device=/dev/yfs/sys0
   # /lib/udev/scsi_id --whitelisted  --device=/dev/yfs/sys1
   # /lib/udev/scsi_id --whitelisted  --device=/dev/yfs/sys2
   ```
   若两台服务器上同一路经所对应的WWID不一致，说明其挂载的磁阵不是同一个LUN，需联系网络管理员处理。

##### 步骤3：检查绑定结果

1. 执行如下命令，确认所有绑定已生效，用户和组均为`yashan`：

   ```shell
   # ls -l /dev/yfs/*
   lrw-rw-rw- 1 yashan yashan 7 Jul 11 14:44 data0 -> ../dm-5
   lrw-rw-rw- 1 yashan yashan 7 Jul 11 14:44 sys0 -> ../dm-7
   ```

   ```shell
   # /lib/udev/scsi_id --whitelisted  --device=/dev/yfs/data
   ```

### 重新绑定

   ```shell

   ```


   ```shell
   # udevadm info --query=all --name=/dev/sdf
   ```

## 共享集群（分布式存储）/分布式集群部署下磁盘映射

共享集群（分布式存储）部署时，需要以root用户或具备sudo权限的用户登录所有存储服务器，对服务器上已挂载的所有NVMe-oF盘进行映射。

分布式集群部署时，需要以root用户或具备sudo权限的用户登录所有DN服务器，对服务器上已挂载的所有NVMe-oF盘进行映射。

假设NVMe SSD已按如下所示划分磁盘并挂载至存储服务器/DN服务器：

| NVMe-oF盘路径| 磁盘用途| 所在服务器|
|--------|--------------------------------------|--------|
| /dev/nvme0n1 | 系统盘 | 172.16.1.4 |
| /dev/nvme0n2 | 系统盘 | 172.16.1.4 |
| /dev/nvme0n1 | 系统盘 | 172.16.1.5 |
| /dev/nvme0n3 | 数据盘 | 172.16.1.5 |

### 手动执行 

手动映射NVMe-oF盘需要安装nvme-cli或nvmetcli工具，本文以使用nvmetcli工具为例。  

1. 加载NVMe相关模块和驱动。

   ::: tabs
   == 使用RDMA协议

```shell
# modprobe nvme_core
# modprobe nvmet
# modprobe nvmet_rdma
# modprobe nvme_fabrics
# lsmod | grep nvme
```
   == 使用TCP协议

```shell
# modprobe nvme_core
# modprobe nvmet
# modprobe nvmet_tcp
```
   :::

2. 安装NVMe管理工具nvmetcli，若已安装无需重复操作。

   ```shell
   # yum install -y nvmetcli
   ```

3. 启动nvmetcli配置目标端的子系统和NVMe端口。

   ```shell
   # nvmetcli
   ```

4. 进入subsystems目录，创建NVMe-oF子系统。

   > **Caution**:
   >
   > 子系统的名称必须为NVMe规范名称（NQN，NVMe Qualified Name），建议省略名称由系统自动生成。

   ```shell
   > cd /subsystems
   > create
   ```

   创建完成后，可以通过`ls`命令查看子系统信息，请记录新建的子系统的名称便于后续操作使用。  

   ```shell
   > ls
   /subsystems
   └──nqn.2014-08.org.nvmexpress:NVMf:uuid:5834f6e0-cb79-40ac-a7cc-f02524340742
   ```

5. 允许所有服务器访问上一步新建的子系统（子系统名称仅为示例）。

   ```shell
   > cd nqn.2014-08.org.nvmexpress:NVMf:uuid:5834f6e0-cb79-40ac-a7cc-f02524340742
   > set attr allow_any_host=1
   ```

6. 在新子系统下添加命名空间，命名空间ID必须为正整数。

   ```shell
   > cd namespaces/
   > create nsid=100
   ```

7. 设置新命名空间对应的设备路径，并将其启用。

   ```shell
   > cd 100
   > set device path=/dev/nvme0n1
   > enable
   ```

8. 给新子系统添加子系统端口并配置端口的IP协议版本`adrfam`、监听地址`traddr`、传输类型`trtype`以及传输端口`trsvcid`。

   其中，子系统端口ID必须为正整数，监听地址必须为[组网规划](./网络准备)子网中的IP地址（例如上表中的172.16.1.4）。传输端口`trsvcid`必须为按[端口规划](./网络准备.html#openports)中开放的端口号。

   ::: tabs
   == 使用RDMA协议

```shell
> cd /ports
> create portid=100
> cd 100/
> set addr adrfam=ipv4
> set addr traddr=172.16.1.4
> set addr trtype=rdma
> set addr trsvcid=1701
```
   == 使用TCP协议

```shell
> cd /ports
> create portid=100
> cd 100/
> set addr adrfam=ipv4
> set addr traddr=172.16.1.4   
> set addr trtype=tcp
> set addr trsvcid=1701
```
   :::

9. 关联NVMe-oF子系统和子系统端口，其中NVMe-oF子系统名称需为上面步骤中创建的子系统实际名称。

   ```shell
   > cd subsystems
   > create nqn.2014-08.org.nvmexpress:NVMf:uuid:5834f6e0-cb79-40ac-a7cc-f02524340742
   ```

10. 重复上述步骤4 - 9，映射其他NVMe-oF盘，建议为每个NVMe-oF盘创建一个独立的NVMe-oF子系统，命名空间ID唯一，便于后续识别。
   
   如希望取消已关联和已建立的子系统，参照以下命令执行：
   
   ```shell
   > cd /ports
   > delete 100
   > cd subsystems
   > delete nqn.2014-08.org.nvmexpress:NVMf:uuid:5834f6e0-cb79-40ac-a7cc-f02524340742
   ```
	
11. 重复上述所有步骤，在所有存储服务器（共享集群部署时）或DN服务器（分布式集群部署时）上完成本机器上的NVMe-oF盘映射。

### 通过脚本操作 

YashanDB安装包中会提供用于映射NVMe-oF盘的脚本nvmfAdd.sh，可以登录安装服务器（本文以172.16.1.2为例）获取该脚本至本服务器，通过脚本快速完成NVMe-oF盘映射操作。

nvmfAdd.sh脚本提供如下参数：

| 参数 | 是否必填 | 含义|
| ---------- | ------------ | ------------------------------------------------------------ |
| -h         | 否           | 查看帮助。 |
| -d         | 是           | 指定要添加的NVMe SSD硬盘路径。                                 |
| -i         | 是           | 指定本机的NVMe-oF所使用的IP地址。                              |
| -p         | 是           | 指定本机的NVMe-oF所使用的端口号。                              |
| -t         | 否           | 指定NVMe-oF的传输类型，可选为TCP或RDMA。默认情况下，如果操作系统内核版本高于5.0且加载了nvmet_tcp模块则为TCP，否则为RDMA。 |
| -nqn       | 否           | 指定待创建的NVMe-oF子系统名称，必须为NVMe规范名称。建议省略该参数，由脚本自动生成UUID4字符串再与前缀`nqn.2014-08.org.nvmexpress:NVMf:uuid:`拼接组成子系统名称。 |
| -nsid      | 否           | 指定待添加的命名空间ID，必须为正整数，省略时默认值为1。            |
| -nvmf-port | 否           | 指定待添加的子系统端口号，省略时默认为已使用的最大端口号+1，若无已使用的最大端口号则默认取1。 |

1. 登录安装服务器，获取nvmfAdd.sh脚本，上传到本服务器。

2. 加载NVMe相关模块和驱动。

   ::: tabs
   == 使用RDMA协议

```shell
# modprobe nvme_core
# modprobe nvmet
# modprobe nvmet_rdma
# modprobe nvme_fabrics
# lsmod | grep nvme
```
   == 使用TCP协议

```shell
# modprobe nvme_core
# modprobe nvmet
# modprobe nvmet_tcp
```
   :::

3. 进入nvmfAdd.sh脚本所在目录，检查脚本的执行权限，执行脚本映射NVMe-oF盘。

   其中，子系统端口ID必须为正整数，监听地址必须为[组网规划](./网络准备)子网中的IP地址（例如上表中的172.16.1.4）。传输端口必须为按[端口规划](./网络准备.html#openports)中开放的端口号。

   ::: tabs
   == 使用RDMA协议

```shell
# ls -l nvmfAdd.sh
# chmod +x nvmfAdd.sh
# nvmfAdd.sh -d /dev/nvme0n1 -i 172.16.1.4 -p 1701 -t rdma -nsid 100 -nvmf-port 100
# nvmfAdd.sh -d /dev/nvme0n2 -i 172.16.1.4 -p 1702 -t rdma -nsid 101 -nvmf-port 101   
```
   == 使用TCP协议

```shell
# ls -l nvmfAdd.sh
# chmod +x nvmfAdd.sh
# nvmfAdd.sh -d /dev/nvme0n1 -i 172.16.1.4 -p 1701 -t tcp -nsid 100 -nvmf-port 100
# nvmfAdd.sh -d /dev/nvme0n2 -i 172.16.1.4 -p 1702 -t tcp -nsid 101 -nvmf-port 101   
```
   :::

4. 重复上述所有步骤，在所有存储服务器（共享集群部署时）或DN服务器（分布式集群部署时）上完成本机器上的NVMe-oF盘映射。

	如希望取消已关联和已建立的子系统，参照以下命令执行：
	
   ```shell
   > cd /ports
   > delete 100
   > cd subsystems
   > delete nqn.2014-08.org.nvmexpress:NVMf:uuid:5834f6e0-cb79-40ac-a7cc-f02524340742
   ```

## 共享集群（分布式存储）部署下绑定磁盘

共享集群（分布式存储）部署时，需要以root用户或具备sudo权限的用户登录每一台实例服务器，对已成功连接的所有NVMe-oF盘进行绑定。

所有NVMe-oF盘应被绑定到服务器的同一目录下，该目录将作为--disk-found-path参数的值，本文采用默认值/dev/yfs作为示例。  

下表为绑定路径示例：

|  NVMe-oF盘| 磁盘用途| 规划绑定路径（示例值）|
|------------|--------------------------------------|--------|
| /dev/nvme4n1 | 系统盘 | /dev/yfs/sys0 |
| /dev/nvme3n1 | 系统盘 | /dev/yfs/sys1 |
| /dev/nvme1n1 | 系统盘 | /dev/yfs/sys2 |
| /dev/nvme2n1 | 数据盘 | /dev/yfs/data0 |



绑定目录（/dev/yfs）与磁盘名称（data0、sys0等）均为示例值，请根据实际业务需求调整，但命名时需注意：

- 绑定后磁盘的绝对路径（例如`/dev/yfs/sys0`）长度不得超过31字节。
- 绑定目录和磁盘的绝对路径均将作为`yasboot package ce gen`命令的相应参数值，如有修改，请在执行`yasboot package ce gen`时使用实际值。





### 步骤1：生成配置文件

1. 以root用户登录服务器。

2. 在root目录下创建名称为`genDevRuleByUUID.sh`的脚本：

   ```shell
   # cd ~
   # vi genDevRuleByUUID.sh
   ```

3. 输入如下内容，并根据部署环境修改`DEVICES`为各设备路径，修改`TARGETS`为各设备绑定名称，名称应与设备路径一一对应，修改`YFS_DISK_DIR`为绑定目录，保存并退出。



   ::: tabs
   == CentOS

```shell
#/bin/bash

# 请修改为各设备路径
DEVICES=("/dev/nvme2n1" "/dev/nvme4n1" "/dev/nvme3n1" "/dev/nvme1n1")
# 请按DEVICES数组顺序指定这些设备绑定的名称，且建议指定为与业务相关的名称
TARGETS=("data0"                   "sys0"                   "sys1"                   "sys2")
# 指定绑定的目录
YFS_DISK_DIR="yfs"

# 请保持默认，请确保yashan用户已存在
USER="yashan"
GROUP="yashan"
UGROUP="$USER:$GROUP"

if [ ${#TARGETS[@]} != ${#DEVICES[@]} ]
then
    echo "DEVICES and TARGETS count does not match"
    exit 1
fi

if [ ${#TARGETS[@]} == 0 ]
then
    echo "no targets found"
    exit 1
fi

curDir=$(cd "$(dirname "$0")";pwd)
rm -f $curDir/yashan-device-rule.rules

count=${#TARGETS[@]}

for ((i = 0; i < $count; i ++))
do
    device=${DEVICES[$i]}
    target_name=${TARGETS[$i]}
    target="${YFS_DISK_DIR}/${target_name}"
    
    str1="$device:`udevadm info --query=all --name=$device | grep DM_UUID`"
    str2=${str1#*=}
    echo "KERNEL==\"dm-*\",ENV{DM_UUID}==\"${str2}\",SYMLINK+=\"$target\",OWNER=\"$USER\",GROUP=\"$GROUP\",MODE=\"0666\",OPTIONS:=\"nowatch\",RUN+=\"/bin/sh -c 'chown -R $UGROUP $target'\""  >> $curDir/yashan-device-rule.rules
done
```

### 步骤2：绑定存储设备

1. 将配置文件移动至/etc/udev/rules.d目录下。

   ```shell
   # cp yashan-device-rule.rules /etc/udev/rules.d/yashan-device-rule.rules
   ```

2. 加载udev配置。

   ```shell
   # udevadm control --reload-rules
   ```

3. 绑定存储设备。

   ```shell
   ## 场景1：绑定规则文件中的所有设备
   # udevadm trigger
   
   ## 场景2：绑定规则文件中的某一设备
   # udevadm trigger --sysname-match=sdf
   ```

### 步骤3：检查绑定结果

1. 执行如下命令，确认所有绑定已生效，用户和组均为`yashan`：

   ```shell
   # ls -l /dev/yfs/*
   lrw-rw-rw- 1 yashan yashan 7 Jul 11 14:44 data0 -> ../dm-5
   lrw-rw-rw- 1 yashan yashan 7 Jul 11 14:44 sys0 -> ../dm-7
   lrw-rw-rw- 1 yashan yashan 7 Jul 11 14:44 sys1 -> ../dm-4
   lrw-rw-rw- 1 yashan yashan 7 Jul 11 14:44 sys2 -> ../dm-6
   ```

   并检查它们指向设备的用户和组均为`yashan`，且权限为`0666`：

   ```shell
   # ls -l /dev/dm-4
   brw-rw-rw- 1 yashan yashan 253, 4 Jul 11 14:44 /dev/dm-4

   # 其他设备类似
   ```

2. 在集群所有服务器上执行以下命令，确认各服务器上**所有**绑定的多路径WWID一致。

   ```shell
   # 对比各服务器上的输出结果是否对应一致
   # /lib/udev/scsi_id --whitelisted  --device=/dev/yfs/data
   # /lib/udev/scsi_id --whitelisted  --device=/dev/yfs/sys0
   # /lib/udev/scsi_id --whitelisted  --device=/dev/yfs/sys1
   # /lib/udev/scsi_id --whitelisted  --device=/dev/yfs/sys2
   ```
   若两台服务器上同一路经所对应的WWID不一致，说明其挂载的NVMe-oF盘不是同一个NVMe-oF盘，需联系网络管理员处理。




完成上述操作后，本服务器的存储设备在此步完成配置，可切换至剩余服务器重复上面步骤。

如需重新绑定，请参照共享集群（共享存储）部署下的[重新绑定](#rebinding)进行操作。
