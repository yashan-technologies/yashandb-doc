通过[yasrman](../../../工具手册/yasrman/00yasrman)工具可以执行如下恢复操作：

- 恢复整库：适用于所有部署形态，单机部署和共享集群/分布式集群部署的命令/用法完全一致。根据具体操作细节又可分为完整恢复整库和基于时间点恢复整库。yasrman工具执行RESTORE DATABASE命令默认包含RECOVER、OPEN数据库操作，执行完成之后数据库处于OPEN状态。

- 恢复表空间：适用于单机部署，若为主备高可用环境则只能连接主库执行相关操作，详见[表空间恢复](#rmanSpaceRestore)。

- 恢复归档日志：适用于单机部署和共享集群/分布式集群部署，且命令/用法完全一致，详见[归档恢复](#rmanArchiveFileRestore)。

|  操作| 操作场景| 备份集|
|--------------------|--------------|-------|
| [恢复整库](#restorealldb) | 在任意部署形态中，需要对数据库一步到位进行完全恢复时使用  | 全库备份集<br/>基于时间点的恢复（PITR）时，还需要归档日志文件或其备份集 |
| [恢复表空间](#rmanSpaceRestore)| 单机部署中，需要对指定表空间进行单独恢复时使用 | 表空间备份集，表空间RECOVER所需的归档日志 |
| [恢复归档日志](#rmanArchiveFileRestore) | 单机/共享集群/分布式集群部署中，基于时间点的恢复（PITR）的恢复过程中包含恢复归档，但已由yasrman自动执行，非必要无需手动恢复归档日志 | 归档日志文件的备份集 |

执行恢复操作要求：

- 目标数据库的部署状态（节点个数、节点监听地址、路径等信息）与备份集源数据库完全一致。

- 目标数据库与备份集源数据库为兼容版本（即版本号的前三个组成部分必须完全一致）。

当需恢复的数据量大或希望提升恢复效率时，可适当增大并发度，并发度默认为2。

恢复过程中，可以通过$YASDB\_DATA/log/run/run.log运行日志查看恢复过程的详细日志。

> **Caution**:
> 
> 在双复制组主备部署环境中，执行数据库恢复操作后的实例均会成为主库，若目标实例为备库且原主库存活则不可对该实例执行恢复操作，否则会出现双主导致部署状态或数据异常。如需重建备库请执行备库[BUILD](../../../开发手册/SQL参考手册/SQL语句/BUILD DATABASE.md)操作。

## 恢复整库

完整恢复整库是指将全库备份集中的备份文件，解压、解密恢复到数据库目录，然后回放备份集中的归档日志将数据库恢复到一致性状态，可将数据库完整恢复到备份时刻。

yasrman工具的restore database命令等同于如下SQL语句：

1. 执行RESTORE DATABASE语句。
2. 执行RECOVER DATABASE语句。
3. OPEN数据库。

基于时间点的恢复（PITR）是指基于数据库备份集还原的数据库文件和归档日志文件将数据库恢复到备份时间点至最新时间点期间某一时刻的状态。

yasrman工具的restore database …… until time ……命令等同于如下SQL语句：

1. 执行RESTORE DATABASE语句。
2. 执行RESTORE ARCHIVELOG语句。
3. 执行RECOVER DATABASE UNTIL语句。
4. 重置redo时间线并OPEN数据库。



### 操作说明

- 整库恢复仅SYS用户才可执行。

- 如果数据库备份集采用加密备份，恢复时需指定解密关键字及其解密密码。

- 在单机一主多备部署中，在对主库（尤其是故障场景中仅剩孤立主库时）执行恢复操作前，需要先关闭自动降备功能（将HA_ELECTION_LEADER_LEASE_ENABLED设置为FALSE），避免因未及时检测到备库心跳而触发自动降备，待恢复完成后再按需还原对应配置。

- 共享集群/分布式集群部署中，只能在主实例（V$INSTANCE视图中INSTANCE_ROLE字段为MASTER_ROLE的实例）上执行数据库恢复操作。

- 如果LSC表在备份集后生成了slice文件，在以下场景基于时间点恢复整库时可能导致恢复后该LSC表存在数据不一致现象：

  - 数据库原来的slice文件全部存在，但是使用老的时间点恢复，此时该LSC表会多出部分slice文件。

  - 数据库原来的slice文件被清理，使用基于时间点的恢复，LSC表可能丢失存储在slice文件中的数据。

- 恢复前数据库环境准备：

  - 数据库实例处于NOMOUNT阶段。

  - 需清空所有节点上实例的数据文件目录、归档文件目录以及bucket目录。

  - 如果备份集中存在加密对象，需先[打开对应的密钥钱包文件](../../../产品安全/加密支持/存储加密/密钥管理.md#openwallet)，再进行恢复操作。

### 完整恢复整库

直接基于全库备份的备份集恢复数据库。



示例（单机/共享集群/分布式集群部署）

```shell
$ yasrman sys/********@192.168.1.2:1688 \
-c "restore database from tag 'full_1'" \
-D /home/yashan/catalog
```

示例（存算一体分布式集群部署）

```shell
$ yasrman sys/********@192.168.1.2:1688 \
-c "restore cluster from tag 'full_1'" \
-D /home/yashan/catalog
```

### 基于时间点恢复整库

执行基于时间点恢复整库时会先使用全库备份的备份集恢复数据，若未达到目标时间点，系统会自动查找符合条件的归档日志文件（或其备份集）进行回放，直到达到目标时间点或直至回放完最新一条日志。如果回放完所有归档仍未达到目标时间点，会提示`the database cannot recover to the target time, and the current time of the database is {实际可回放到的最近时间点}`，此种情况下启动数据库时需执行ALTER DATABASE OPEN RESETLOGS重置redo日志号。



示例（单机/共享集群/分布式集群部署）

```shell
# 指定时间戳和数据库备份集
$ yasrman sys/********@192.168.1.2:1688 \
-c "restore database from tag 'full_1' until time '2023-11-13'" \
-D /home/yashan/catalog

# 指定时间戳和数据库ID
$ yasrman sys/********@192.168.1.2:1688 \
-c "restore database dbid 12573483 until time '2023-11-13 18:55:00'" \
-D /home/yashan/catalog

# 指定SCN和数据库备份集
$ yasrman sys/********@192.168.1.2:1688 \
-c "restore database from tag 'full_1' until scn 499833430256541696" \
-D /home/yashan/catalog
```

## 表空间恢复

表空间恢复是指将对应表空间备份集中的备份文件，解压、解密恢复到数据库目录，然后回放备份集中的归档日志将表空间恢复到一致性状态，可将表空间完整恢复到备份时刻。

表空间恢复操作仅适用于单机部署，若为主备高可用环境则只能连接主库执行相关操作。

### 操作说明

- 表空间恢复仅SYS超级用户或拥有SYSDBA、SYSBACKUP权限的用户才可执行。

- 如果数据库备份集采用加密备份，恢复时需指定解密关键字及其解密密码。

- 恢复前数据库环境准备：

  - 数据库已启动至MOUNT或OPEN阶段。
  
  - 目标表空间必须处于OFFLINE状态，该表空间下的所有数据文件需处于OFFLINE或RECOVER状态。

  - 如果备份集中存在加密对象，需先打开对应的密钥钱包文件，再进行恢复操作。

### 操作步骤

1. 执行RESTORE TABLESPACE基于指定的表空间备份集还原出相应文件。

2. 执行RECOVER TABLESPACE对表空间相关文件执行一致性恢复。

示例（单机部署）

```shell
-- 1. 执行RESTORE TABLESPACE
$ yasrman sys/********@192.168.1.2:1688 \
-c "restore tablespace spc_test from tag 'spc_test_bak' " \-D /home/yashan/catalog

 
-- 2. 执行RECOVER TABLESPACE
$ yasrman sys/********@192.168.1.2:1688 \
-c "recover tablespace spc_test maxsize 1280M " \
-D /home/yashan/catalog
```

## 归档恢复

若直接使用yasrman执行[基于时间点恢复整库](#untilTimeRestoreDb)，无需单独执行归档恢复，该操作仅可能作为采用[SQL语句](../SQL语句备份恢复/恢复.md)进行基于时间点恢复的中间步骤使用。

归档恢复是指在数据库完整恢复（RESTORE DATABASE）后但暂未进行日志恢复（RECOVER DATABASE）时，将归档备份集中的文件恢复到数据库的归档目录并注册到数据库中，尽可能补充数据库备份集中缺失的归档日志，使数据库恢复更多的数据。

> **Note**: 
>
> 归档文件RESTORE时会校验归档备份集和数据库版本是否一致。版本校验包括归档文件和数据库的DBID和RESTORE TIME是否一致，归档备份集的RESTORE TIME可查询视图DBA_BACKUP_SET或者使用yasrman list命令查看，待恢复目标数据库的RESTORE TIME可查看V$DATABASE视图。版本不一致的归档备份集不在可恢复范围内，扫描过程中会自动跳过。

共享集群环境下，各个实例的归档生成次序不一致，即各个实例同一时间的归档ASN不一致。使用归档恢复操作建议指定SCN或者TIME的区间限定恢复，避免漏恢复归档。

恢复范围指定方式以及压缩、加密等通用备份属性与使用SQL语句备份一致。

### 操作说明

- 共享集群/分布式集群部署中，只能在主实例（V$INSTANCE视图中INSTANCE_ROLE字段为MASTER_ROLE的实例）上执行归档恢复操作。

- 归档日志只能恢复成现有归档备份集的全集或子集，且指定恢复范围的方式（SCN、SEQUENCE或时间）不受备份范围指定方式约束。

- 如果归档备份集采用加密备份，恢复时需指定DECRYPTION关键字及解密密码。

- 恢复前数据库环境准备：

  - 数据库已完成RESTORE DATABASE且启动至MOUNT阶段，但暂未执行RECOVER DATABASE（需使用yasql命令执行restore）。

  - 确保恢复归档日志文件的目标路径存在，省略TO destpath时默认恢复至ARCHIVE_LOCAL_DEST参数所配置的路径（默认值为$YASDB_DATA/archive）。

### 操作示例

示例（单机/共享集群/分布式集群部署）

```shell
$ yasrman sys/********@192.168.1.2:1688 \
-c "restore archivelog all from tag 'arch_bak002'" \
-D /home/yashan/catalog

$ yasrman sys/********@192.168.1.2:1688 \
-c "restore archivelog sequence between 10 and 20" \
-D /home/yashan/catalog
```
