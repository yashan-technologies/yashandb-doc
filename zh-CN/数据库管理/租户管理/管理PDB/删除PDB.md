根据实际应用场景，删除PDB可能存在以下场景：

- 场景1：彻底删除不再使用的PDB。

- 场景2：作为PDB运维的前序操作临时删除PDB，例如重构备库前删除备PDB但保留元数据、恢复PDB数据前删除PDB但保留元数据。

## 场景1：彻底删除PDB

若确认无需再使用某个PDB，可将其彻底删除，避免资源浪费。若为主备部署，该场景表示彻底清理某个PDB的主备库。

> **Warn**:
>
> 删除PDB的同时会删除PDB相关的持久化文件且无法回滚，**请谨慎操作**。

### 前提条件

- 根容器处于OPEN状态。若为主备部署，则只要求主根容器处于OPEN状态且需登录主根容器执行相应操作。

- 目标PDB处于关闭状态。

## 场景2：作为PDB运维的前序操作临时删除PDB

作为PDB运维的前序操作，需要临时删除PDB的场景主要可能为以下几种：

- 作为[PDB恢复](../../备份与恢复/CDB备份与恢复/00CDB备份与恢复.md)的前序操作：指定KEEP METADATA关键字，保留PDB的元数据，归档日志文件默认保留。若进行PITR恢复则还需额外指定KEEP LOGFILE关键字保留目标PDB的redo日志文件。

- 作为[重新构建PDB备库](../../../高可用/修复异常备库.md)的前序操作：可同时指定KEEP METADATA关键字和INCLUDING ARCHIVELOG关键字，仅保留PDB的元数据。

### 前提条件

- 目标PDB所在根容器处于OPEN状态，例如待删除的PDB1备库位于主根容器上，则只要求主根容器处于OPEN状态。

- 目标PDB的状态要求：

    - 连接根容器执行：要求目标PDB处于关闭状态。

    - 直连目标PDB执行：要求其处于NOMOUNT阶段。

### 操作步骤 

1. （可选）若为主备部署，需先确认目标PDB的目标备库的位置。

    1. ) 以安装用户登录数据库安装服务器。


    2. ) 获取目标PDB信息，包括状态、名称、主备角色及其所在节点等。

        ```shell
        $ yasboot cluster status -c yashandb -d -p sys_password
        +-----------------------------------------------------------------------------------------------------------------------------------------------------------------------+
        | hostid   | nodeid | node_type | pdb_name       | pid   | instance_status | pdb_status | pdb_role | source_node | listen_address    | data_path                        |
        +-----------------------------------------------------------------------------------------------------------------------------------------------------------------------+
        | host0001 | 1-1:1  | cdb       | cdb$root       | 19053 | open            | open       | primary  | -           | 192.168.1.2:1688  | /data/yashan/yasdb_data/db-1-1 |
        +          +        +           +----------------+-------+-----------------+------------+----------+-------------+                   +                                  +
        |          |        |           | pdb1           | 12366 | open            | open       | primary  | -           |                   |                                  |
        +          +        +           +----------------+-------+-----------------+------------+----------+-------------+                   +                                  +
        |          |        |           | pdb2           | 29317 | open            | open       | primary  | -           |                   |                                  |
        +          +        +           +----------------+-------+-----------------+------------+----------+-------------+                   +                                  +
        +----------+--------+-----------+----------------+-------+-----------------+------------+----------+-------------+-------------------+----------------------------------+
        | host0002 | 1-2:2  | cdb       | cdb$root       | 7755  | open            | open       | standby  | 1-1:1       | 192.168.1.3:1688  | /data/yashan/yasdb_data/db-1-2 |
        +          +        +           +----------------+-------+-----------------+------------+----------+-------------+                   +                                  +
        |          |        |           | pdb1           | 12745 | open            | open       | standby  | unknown     |                   |                                  |
        +          +        +           +----------------+-------+-----------------+------------+----------+-------------+                   +                                  +
        |          |        |           | pdb2           | 31570 | open            | open       | standby  | 1-1:1       |                   |                                  |
        +          +        +           +----------------+-------+-----------------+------------+----------+-------------+                   +                                  +
        +----------+--------+-----------+----------------+-------+-----------------+------------+----------+-------------+-------------------+----------------------------------+
        ```

        本文将以需删除PDB2的备库为例进行后续介绍，由上述信息可知，其位于备根容器（`192.168.1.3:1688`）上。
    
    3. ) 若目标PDB处于运行中，需将其调整至合适的运行状态再执行后续操作。

        ```shell
        # 连接根容器执行删除操作时，需关闭PDB
        $ yasboot pdb stop -c yashandb -n 1-2 --pdb pdb2 -p sys_password

        # 直连PDB执行执行删除操作时，PDB需处于NOMOUNT阶段
        $ yasboot pdb restart -c yashandb -n 1-2 --pdb pdb2 -p sys_password -m nomount
        ```

2. 删除PDB但保留其元数据。

    ::: tabs
    == 连接根容器执行SQL语句

1. ) 以DBA用户连接并登录目标PDB所在根容器。
    ```shell
    $ yasql c##sales/********@192.168.1.3:1688
    YashanDB SQL Enterprise Edition Release {version_number} x86_64

    Connected to:
    YashanDB Server Enterprise Edition Release {version_number} x86_64 - Linux

    SQL> 
    ```


2. ) 执行DROP PLUGGABLE DATABASE语句并按需指定相应关键字保留所需文件：
    ```sql
    -- 保留元数据+归档日志文件+redo日志文件
    DROP PLUGGABLE DATABASE pdb2 KEEP LOGFILE KEEP METADATA;

    -- 保留元数据+归档日志文件
    DROP PLUGGABLE DATABASE pdb2 KEEP METADATA;

    -- 保留元数据
    DROP PLUGGABLE DATABASE pdb2 KEEP METADATA INCLUDING ARCHIVELOG;
    ```

    == 直连目标PDB执行SQL语句

1. ) 以sys用户登录目标PDB。
    
    ```shell
    $ yasql sys/********@192.168.1.3:1688/pdb1

    YashanDB SQL Enterprise Edition Release {version_number} x86_64

    Connected to:
    YashanDB Server Enterprise Edition Release {version_number} x86_64 - Linux

    SQL> 
    ```
    

2. ) 执行DROP DATABASE语句并按需指定相应关键字保留所需文件：
    ```sql
    -- 保留元数据+归档日志文件+redo日志文件
    DROP DATABASE KEEP LOGFILE KEEP METADATA;

    -- 保留元数据+归档日志文件
    DROP DATABASE KEEP METADATA;

    -- 保留元数据
    DROP DATABASE KEEP METADATA INCLUDING ARCHIVELOG;
    ```
