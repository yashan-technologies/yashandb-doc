## 功能简介

快照备库是YashanDB提供的一种特殊备库模式，基于当前环境中物理备库的瞬时数据镜像生成，是数据库提供的轻量化数据克隆能力。

快照备库具备以下特点：

- 始终接收redo日志（存储在STANDBY LOG文件中），不影响最大保护模式下主库的事务提交。

- 停止回放redo日志，数据版本固定且稳定。

- 允许读写，可以在不影响主库业务的情况下执行临时数据查询、业务校验、变更验证、数据回溯核查、离线统计分析及测试演练等操作。

- 支持随时转换回物理备库形态，系统将通过闪回技术将数据库恢复至转为快照备库的时间点，自动丢弃快照备库存续期间的所有写操作，全程不会产生数据冲突与数据错乱。转换完成后，目标备库将恢复标准物理备库能力，正常参与主备复制。

快照备库的运行要求如下：

- 配置至少3个STANDBY LOG文件，用于接收快照备库期间主库的所有redo日志。

- 无法进行表空间操作，包括添加/删除表空间、修改数据文件等。

- 无法进行在线redo日志管理操作，包括添加、删除、清空redo文件文件等。

- 无法进行备份恢复操作。

## 典型应用场景

快照备库适用于以下业务场景：

- **业务演练与测试**：在备库上执行完整的业务演练脚本，验证新功能上线后的系统表现，无需在生产环境进行风险操作。

- **功能验证与调试**：在隔离的备库环境中进行SQL语句调优、存储过程调试或应用兼容性验证，避免对核心业务产生影响。

- **快速构建测试环境**：利用现有备库资源快速搭建测试环境，无需额外采购硬件设备或进行复杂的数据复制，显著降低测试环境搭建成本。

- **问题复现与分析**：在快照备库上复现生产环境发现的问题，便于技术人员进行根因分析和修复方案验证。

## 构建快照备库

构建快照备库是指将角色为STANDBY的物理备库（非级联备）转换为快照备库。

### 前提条件

- 快照备库仅适用于单机部署。

- 若当前环境为单机单库部署，请先参考[备库扩缩容](../安装和升级/扩缩容/单机主备扩缩容/备库扩缩容.md)为已有环境创建新备库，初始时该备库默认为物理备库。

- 目标备库必须为物理备库（V$DATABASE视图的DATABASE_ROLE字段为STANDBY）。

- 转换过程中，需要将目标备库重启至MOUNT阶段。

- 已为目标备库规划STANDBY LOG文件的文件路径、文件数量以及存储空间。STANDBY LOG文件将用于接收快照备库期间主库的所有redo日志，请根据日常业务量进行容量评估与规划。

### 操作步骤

#### 步骤1：选定目标备库 

1. 以DBA用户连接并登录数据库。
    ```shell
    $ yasql sales/********@192.168.1.2:1688
    YashanDB SQL Enterprise Edition Release {version_number} x86_64

    Connected to:
    YashanDB Server Enterprise Edition Release {version_number} x86_64 - Linux

    SQL> 
    ```

2. 查看数据库的主备链路配置信息。

    ```sql
    -- 查看ARCHIVE_DEST_n配置
    SELECT NAME,VALUE FROM V$PARAMETER WHERE NAME LIKE 'ARCHIVE_DEST_%' AND VALUE IS NOT NULL;

    NAME                                                             VALUE                                                  
    ---------------------------------------------------------------- ----------------------------------------------------------------
    ARCHIVE_DEST_2                                                   SERVICE=192.168.1.3:1688 NODE_ID=1-2:2
    ARCHIVE_DEST_3                                                   SERVICE=192.168.1.4:1688 NODE_ID=1-3:3

    SELECT database_role, open_mode FROM v$database;

    DATABASE_ROLE        OPEN_MODE
    -------------------- -----------------
    STANDBY              READ_ONLY
    ```

    根据配置信息选择待构建为快照备库的目标备库（本文以备库1-3为例）。

3. 以DBA用户连接并登录目标备库。

4. 检查并确认其数据库角色。

   ```sql
   SELECT database_role, open_mode FROM v$database;

   DATABASE_ROLE        OPEN_MODE
   -------------------- -----------------
   STANDBY              READ_ONLY
   ```
   若DATABASE_ROLE不为STANDBY则需选择其他备库进行后续操作。


#### 步骤2：执行转换

1. 以安装用户登录目标备库所在服务器。

2. 重启目标备库至MOUNT阶段。

   ```shell
   $ yasboot node restart -c yashandb -n 1-3 -m mount
   ```

3. 以sys用户连接并登录目标备库。

   ```shell
   # 以sys用户免密登录
   $ yasql / as sysdba

   # 或密码认证登录
   $ yasql sys/********@192.168.1.4:1688
   ```

4. 将目标备库转换为快照备库。

   ```sql
   ALTER DATABASE CONVERT TO SNAPSHOT STANDBY;
   ```

5. 在目标备库上创建至少3个STANDBY LOG文件。

   ```sql
   ALTER DATABASE ADD STANDBY LOGFILE '?/dbfiles/standby_redo1' SIZE 512M;
   ALTER DATABASE ADD STANDBY LOGFILE '?/dbfiles/standby_redo2' SIZE 512M;
   ALTER DATABASE ADD STANDBY LOGFILE '?/dbfiles/standby_redo3' SIZE 512M;
   ```

6. 启动目标备库至OPEN。

   ```sql
   ALTER DATABASE OPEN;
   ```

7. 确认转换结果。

   ```sql
   SELECT database_role, open_mode FROM v$database;

   DATABASE_ROLE        OPEN_MODE
   -------------------- -----------------
   SNAPSHOT_STANDBY     READ_WRITE
   ```
   
   - DATABASE_ROLE = SNAPSHOT_STANDBY：表示快照备库转换已成功。当前备库处于读写模式，可正常执行读写业务。

   - DATABASE_ROLE = SNAPSHOT_PREPARE：表示正处于快照备库转换过程中，当前备库正处于准备阶段。若查询结果仍为此状态，可通过V$RECOVERY_PROGRESS视图查看转换进度。

      ```sql
      SELECT item, units, value FROM v$recovery_progress;
      ```

## 监测快照备库运行状态

在快照备库运行期间，运维人员需要关注以下关键指标：

- 存储空间使用情况。

   快照备库运行期间会持续写入数据，需要监控表空间大小：

   ```sql
   SELECT tablespace_name, SUM(bytes) / 1024 / 1024 AS size_mb
   FROM dba_data_files
   GROUP BY tablespace_name;
   TABLESPACE_NAME                                                      SIZE_MB 
   ---------------------------------------------------------------- ----------- 
   SYSTEM                                                                    64
   SYSAUX                                                                    64
   TEMP                                                                      64
   SWAP                                                                      64
   USERS                                                                     64
   UNDO                                                                     128
   ```

   如果表空间使用率接近阈值，需要及时清理数据或扩充存储。

- STANDBY LOG日志状态。

   监控STANDBY LOG文件的使用情况，避免日志文件频繁切换影响性能：

   ```sql
   SELECT id, type, sequence#, block_count, used_blocks, status FROM v$logfile;

             ID TYPE         SEQUENCE#           BLOCK_COUNT           USED_BLOCKS STATUS
   ------------ --------- ------------ --------------------- --------------------- ---------
            0 ONLINE              65                 32768                 32768 INACTIVE
            1 ONLINE              66                 32768                 26090 CURRENT
            2 ONLINE              63                 32768                  6238 INACTIVE
            3 ONLINE              64                 32768                 32768 INACTIVE
          128 STANDBY              3                131072                   177 CURRENT
          129 STANDBY              0                131072                     0 NEW
          130 STANDBY              0                131072                     0 NEW
   ```

## 将快照备库转回物理备库

将快照备库转换回物理备库，继续接收并回放主库redo日志。

### 操作场景

在以下场景中，需要将快照备库转回物理备库：

- 测试/验证完成：在快照备库上完成业务测试、功能验证或问题复现后，需要恢复备库的主备复制功能。

- 数据同步需求：业务需要恢复主备数据同步，确保持续接收并回放主库redo日志。

- 作为正式备库：快照备库在完成临时任务后，需要继续作为生产环境的备库运行。

### 前提条件

- 目标备库必须为快照备库（V$DATABASE视图的DATABASE_ROLE字段为SNAPSHOT_STANDBY）。

- 转换过程中，需要将目标备库重启至MOUNT阶段。

- 归档日志：需要确保主库归档日志保持完整，用于转换时执行Flashback恢复。

### 操作步骤

1. 以DBA用户连接并登录目标备库。

2. 检查并确认其数据库角色。

   ```sql
   SELECT database_role, open_mode FROM v$database;

   DATABASE_ROLE        OPEN_MODE
   -------------------- -----------------
   SNAPSHOT_STANDBY     READ_WRITE

   exit
   ```

3. 以安装用户登录目标备库所在服务器。

4. 重启目标备库至MOUNT阶段。

   ```shell
   $ yasboot node restart -c yashandb -n 1-3 -m mount
   ```

5. 以sys用户连接并登录目标备库。

   ```shell
   # 以sys用户免密登录
   $ yasql / as sysdba

   # 或密码认证登录
   $ yasql sys/********@192.168.1.4:1688
   ```

6. 将目标备库转换为物理备库。

   ```sql
   ALTER DATABASE CONVERT TO PHYSICAL STANDBY;
   ```

7. 启动目标备库至OPEN。

   ```sql
   ALTER DATABASE OPEN;
   ```

8. 确认转换结果。

   ```sql
   SELECT database_role, open_mode FROM v$database;

   DATABASE_ROLE        OPEN_MODE
   -------------------- -----------------
   STANDBY               READ_ONLY
   ```

   - DATABASE_ROLE = STANDBY：表示快照备库已成功转换回物理备库，当前备库恢复物理备库原有特性，持续接收并回放主库redo日志。

   - DATABASE_ROLE = SNAPSHOT_PREPARE：表示正处于快照备库转换过程中，当前备库正处于准备阶段。若查询结果仍为此状态，可通过V$RECOVERY_PROGRESS视图查看转换进度。

      ```sql
      SELECT item, units, value FROM v$recovery_progress;
      ```
