YashanDB通过数据库实例内部的一个工作线程处理客户端发来的连接请求，该线程称为连接监听器。

## 管理监听器运行模式 



连接监听器的工作模式分为：

- 正常运行模式：接受新的连接，默认为该模式，可通过ALTER SYSTEM语句进行模式调整。

- 维护模式：保持现有连接，阻止新的连接（本地连接除外）。监听器进入维护模式后，将仅允许本地连接会话接入数据库，直到再次调整为正常运行模式或重启数据库。



### 适用场景 

- 数据库维护：在进行数据库维护操作期间，设置为维护模式可拒绝新的远程连接，确保维护操作不受新连接干扰。
- 紧急熔断：当发生连接风暴等异常情况时，可快速停止接收新连接，防止数据库过载。
- 版本升级：在不停机升级场景下，可先设置维护模式，待所有会话结束后再进行升级。

### 操作步骤 

1. 以DBA用户连接并登录数据库。
    ```shell
    $ yasql sales/********@192.168.1.2:1688
    YashanDB SQL Enterprise Edition Release {version_number} x86_64

    Connected to:
    YashanDB Server Enterprise Edition Release {version_number} x86_64 - Linux

    SQL> 
    ```


2. 执行[ALTER SYSTEM](../../开发手册/SQL参考手册/SQL语句/ALTER SYSTEM.md)语句调整连接监听器的运行模式，配置立即生效。

    ```sql
    -- 将连接监听器设置为维护模式
    ALTER SYSTEM LISTENER STOP;

    -- 将连接监听器设置为正常运行模式
    ALTER SYSTEM LISTENER START;
    ```

    将连接监听器设置为维护模式后，仅本地连接可正常使用，其他场景则会提示`listener closed`。

## 管理监听日志配置 

在YashanDB中，是否记录监听日志由`LSNR_LOG`参数的取值控制，默认`LSNR_LOG = ON`（即会记录日志）。因此，安装YashanDB时会自动创建监听日志文件$YASDB_DATA/log/listener/listener.log，所有对YashanDB的连接请求（包括远程TCP连接和UDS本地连接，且不论成功与否）都将记录在监听日志中。

日志内容包含时间戳、协议类型、IP地址、端口号、用户名和连接状态等信息，详细的日志查看方法与内容示例请查看[监听日志管理](../../数据库管理/运行监控/日志管理/监听日志管理)。

### 适用场景 

- 安全审计：记录所有对数据库的连接请求，满足安全合规要求。
- 攻击检测：检测诸如连接风暴类的网络攻击行为，及时发现异常连接。
- 问题排查：当客户端连接出现异常时，通过日志分析定位问题原因。

> **Note**:
>
> 非必要不建议关闭监听日志，仅在日志记录对性能产生明显影响且安全风险可控时才可考虑关闭。

### 操作步骤 

1. 以DBA用户连接并登录数据库。
    ```shell
    $ yasql sales/********@192.168.1.2:1688
    YashanDB SQL Enterprise Edition Release {version_number} x86_64

    Connected to:
    YashanDB Server Enterprise Edition Release {version_number} x86_64 - Linux

    SQL> 
    ```


2. 执行[ALTER SYSTEM](../../开发手册/SQL参考手册/SQL语句/ALTER SYSTEM.md)语句调整LSNR_LOG参数值。

    ```sql
    --查看当前监听日志配置
    SHOW PARAMETER LSNR_LOG;
    NAME             VALUE
    ---------------- ----------
    LSNR_LOG         OFF

    -- OFF表示未记录监听日志，可以按需开启
    ALTER SYSTEM SET LSNR_LOG= ON SCOPE=SPFILE;

    -- 若后续无需记录监听日志，可按需关闭
    ALTER SYSTEM SET LSNR_LOG= OFF SCOPE=SPFILE;
    ```

3. 重启数据库使配置生效。
