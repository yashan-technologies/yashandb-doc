在日常使用过程中，数据库管理员可按需增/删/改自定义表空间，关于表空间管理的详细语法描述请参考开发手册[CREATE TABLESPACE](../../../../开发手册/SQL参考手册/SQL语句/CREATE TABLESPACE)、[ALTER TABLESPACE](../../../../开发手册/SQL参考手册/SQL语句/ALTER TABLESPACE)、[DROP TABLESPACE](../../../../开发手册/SQL参考手册/SQL语句/DROP TABLESPACE)。

## 创建表空间

数据库管理员在接收到一个创建表空间的申请时，需要从以下方面进行考量：

- 表空间所服务的业务属性：

  - HEAP表和TAC表采取段页式结构，挂载普通数据文件

    ```sql
    -- 不指定DATAFILE将默认创建一个数据文件
    CREATE TABLESPACE tablespace_name;
    ```

  - LSC表的稳态数据采取对象结构，需挂载数据桶

    ```sql
    -- LSC的表空间必须指定DATABUCKET
    CREATE TABLESPACE tablespace_name DATABUCKET 'lscfile1','lscfile2';
    ```

  - 对敏感数据或核心数据可定义为加密表空间

    ```sql
    -- 加密属性在创建表空间时确定，后续不可更改
    CREATE TABLESPACE tablespace_name DATABUCKET 'lscfile1','lscfile2' ENCRYPTION ENCRYPT;
    ```

  - 对极高性能要求的表空间可定义为MMS表空间，同时配置MMS_DATA_LOADERS参数确定预加载策略

    ```sql
    CREATE TABLESPACE tablespace_name MEMORY MAPPED;
    ```

- 表空间的存储属性：

  - 确定数据文件初始值、扩展值和最大值，默认由系统自动决定

    ```sql
    CREATE TABLESPACE yashan1 DATAFILE 'yashan1' SIZE 4M AUTOEXTEND ON NEXT 4M MAXSIZE 1G; 
    ```

  - 确定extent大小，默认由系统自动决定

    ```sql
    CREATE TABLESPACE yashan1 DATAFILE 'yashan1' SIZE 4M AUTOEXTEND ON NEXT 4M MAXSIZE 1G EXTENT UNIFORM SIZE 64K; 
    ```

  - 对于MMS表空间，确定是否启用大页内存，启用大页内存的前提是操作系统配置大页内存

    ```sql
    -- 重启生效
    ALTER SYSTEM SET MMS_USE_LARGE_PAGES=true SCOPE=BOTH;
    ```

## 表空间运维

### offline与online

当某个表空间不再使用，或者不想被访问到时，可将其进行脱机：

```sql
-- 默认要求脱机的表空间中的所有数据文件均为脱机
ALTER TABLESPACE yashan OFFLINE;

-- TEMPORARY选项允许脱机的表空间中有数据文件已脱机
ALTER TABLESPACE yashan OFFLINE TEMPORARY;

-- IMMEDIATE立即脱机，存在数据风险，后续不能被online
ALTER TABLESPACE yashan OFFLINE IMMEDIATE;
```

通过online操作可以恢复被脱机的表空间：

```sql
ALTER TABLESPACE yashan ONLINE;
```

### 增删数据文件

表空间可挂载的数据文件数量和数据桶数量存在规格约束（YashanDB为64），管理员需关注该限制，避免达到上限（达到上限后将无法增加数据文件，且无法通过删除数据文件的方式释放数量）。当已达到上限仍需增加数据文件或数据桶时，通过创建新的表空间来解决。

增加数据桶时还需考虑BUCKET_RESERVED_SPACE参数，该参数用于控制数据桶占用所在磁盘的空间上限。

```sql
-- 默认由系统决定新增的数据文件的属性，临时文件需使用TEMPFILE关键字
ALTER TABLESPACE yashan ADD DATAFILE;

ALTER TABLESPACE yashan DROP DATAFILE 'yashan1';

ALTER TABLESPACE lsc_tb ADD DATABUCKET 'lscfile3','lscfile4';

ALTER TABLESPACE lsc_tb DROP DATABUCKET 'lscfile3';
```

### 空闲空间回收

对单机部署和存算一体分布式集群部署中的表空间进行收缩，可以回收其空闲空间，供其他表空间使用。

示例（单机、存算一体分布式集群部署）

```sql
-- 不指定KEEP时，系统将最大化收缩表空间
ALTER TABLESPACE SYSTEM SHRINK SPACE KEEP 100M;
ALTER TABLESPACE SYSTEM SHRINK SPACE;
```

### 分布式表空间故障恢复

存算一体分布式集群部署中执行表空间DDL时出现节点故障，YashanDB提供自动恢复功能。

```sql
-- 为确认系统是否正常，可在CN节点查询GV$TABLESPACE、GV$DATAFILE和GV$DATABUCKET视图获取节点tablespace和datafile、bucketfile文件状态
SELECT * FROM GV$TABLESPACE WHERE name = UPPER('TABLESPACENAME') ORDER BY group_id;
SELECT * FROM GV$DATAFILE WHERE name LIKE '%DATAFILENAME' ORDER BY group_id;
SELECT * FROM GV$DATABUCKET WHERE url LIKE '%BUCKETFILENAME' ORDER BY group_id;
```

Datafile、Bucketfile文件目录为：

- Datafile文件默认目录：`${YASDB_DATA}/节点名/dbfiles/`
- Bucketfile文件默认目录：`${YASDB_DATA}/节点名/local_fs/`
- 若指定了目录路径，则文件目录以实际为准：`${YASDB_DATA}/节点名/指定目录/`

#### CREATE TABLESPACE时故障

如果创建表空间时出现节点故障，具体情况和解决方案如下所示：

- 仅在MN节点（group_id为1）有TABLESPACE和Datafile或Databucket记录，GV$PUB_STAT视图没有异常TABLESPACE相关DDL记录，说明仅MN节点出现故障：

  1. 需重启MN节点并手动在CN节点上执行如下语句：

     ```sql
     DROP TABLESPACE IF EXISTS tablespace_name including contents AND datafiles;
     ```

  2. 查询GV$TABLESPACE、GV$DATAFILE和GV$DATABUCKET视图，确认没有对应的TABLESPACE。

  3. 检查MN节点下的Datafile和Databucket文件夹，确认是否存在对应的TABLESPACE文件残留，若有则需手动清理相关文件夹。

  4. 重启后，再次执行CREATE TABLESPACE语句。

- MN节点、部分CN/DN节点有TABLESPACE和Datafile或Databucket记录，MN节点中GV$PUB_STAT视图有异常TABLESPACE相关DDL推送记录，说明是部分CN/DN节点出现故障：

  1. 重启故障节点。
  
  2. 等待片刻后，在MN节点中查询GV$PUB_STAT视图，如没有发现异常TABLESPACE相关的DDL记录，则表示恢复成功；如仍查询到异常DDL记录，可通过ERR_MSG字段查看失败原因：若显示DN资源不足，则需要重新合理分配资源。

- 所有节点都没有TABLESPACE和Datafile或Databucket记录，MN节点中GV$PUB_STAT视图没有异常TABLESPACE相关DDL记录，说明仅MN节点出现故障：
  
  1. 重启MN节点。
  
  2. 再次执行CREATE TABLESPACE语句。

#### DROP TABLESPACE时故障

删除表空间时出现节点故障，具体情况和解决方案如下所示：

- MN节点有TABLESPACE和Datafile或Databucket记录，说明仅MN节点出现故障：

  1. 重启MN节点，并手动在CN节点上执行如下语句：

     ```sql
     DROP TABLESPACE IF EXISTS tablespace_name including contents AND datafiles;
     ```

- MN节点不存在TABLESPACE，CN/DN节点有TABLESPACE和Datafile或Databucket记录，说明是部分CN/DN节点出现故障：

  1. 重启故障节点即可恢复。

#### ALTER TABLESPACE ADD(DATAFILE|TEMPFILE)时故障

  1. 需重启MN节点并手动在CN节点上执行如下语句：

     ```sql

     ```

  2. 查询GV$TABLESPACE、GV$DATAFILE和GV$DATABUCKET视图，确认没有对应的TABLESPACE。
