*imp* is the import utility for YashanDB, providing the ability to import data via files.

The metadata file is generated by the [exp](../exp/00exp) tool and contains the schema, indexes, constraints, and all other metadata and data. It can be used for data migration or backup restoration between homogeneous databases.

This tool supports various import modes, including FULL (import the entire file), FROMUSER (import data from a specified user), and TABLES (import specified tables).

The objects that can be imported with the *imp* tool include:

- Users
- SEQUENCE
- AC
- Synonyms
- Views/Materialized Views
- Tables (excluding tables with virtual columns)
- Indexes/Partition Indexes
- Primary Keys
- Foreign Keys
- Audit Policies/Enabling
- Privileges
- PROFILE
- OUTLINE
- PACKAGE(BODY)/PROCEDURE/FUNCTION/TRIGGER/JOB/LIBRARY/TYPE(BODY)
- DATABASE LINK

Additionally, the constraints, dependencies (e.g., TABLEs that views depend on), and column attributes of the objects will also be imported.

> **Note**:
>
> - For tables with UDT columns, the following restrictions apply for metadata import:
>   - For tables referencing TYPES, a warning will be issued during import, but the import will continue.
>   - In TABLES mode, indirectly used TYPES will not be imported.
>   - In FROMUSER or TABLES mode, if the TYPES used by the imported tables from different users do not exist, a warning will be issued, but the import will continue.
> - Import statement length limitation: If the import statement exceeds 2M (e.g., view creation statement), an alert will occur, and this object cannot be imported, but the import process will not be interrupted.

## Privilege Requirements

The execution command of the *imp* tool requires the input of the database user/password.

When importing the metadata file, this user is the one performing the import operation, not the import objects. The privilege rules for this operational user are as follows:

- No privilege requirements when importing objects under this user.
- When importing objects under other users, the user must have DBA role.

***Example***

```sql
-- Grant DBA role to user sales
GRANT DBA TO sales;

-- Import user sale0
imp sales/sales file=export.dump fromuser=sales0

-- Import the tables under user sale0
imp sales/sales file=export.dump tables=area fromuser=sales0
```

> **Note**: 
>
> The higher version of the *imp* tool does not support connections to lower version databases for imports. Please use version-compatible tools for data migration operations.
