## Disk Partitioning

Yashan File System (YFS) uses disks as the logical units for storage management, and distinguishes them into the following two categories based on their usage purposes:

- **System Disk**
  
   Used for cluster management, only supporting 1, 2, 3, or 5 disks of the **same size**, with each disk having a minimum capacity of 1G (if the number of system disks is 1 and AU Size needs to be configured to 32M, the system disk size must be at least 2G). The absolute path of these disks will serve as the value of the --system-data parameter, separated by commas, such as `--system-data /dev/yfs/sys0,/dev/yfs/sys1,/dev/yfs/sys2`. The absolute path is generated by the configuration described below in this document.
	
	The number of planned system disks will affect the redundancy of the system disk group, with 1, 2/3, or 5 system disks corresponding to EXTERNAL, NORMAL, or HIGH redundancy.
	
	The planned system disks cannot be changed after installation. Please confirm at this step. If you cannot determine, please consult our technical support.

- **Data Disk**

   Used to store cluster business data, it can be configured with 1 or more disks of the **same size**. The quantity and capacity should be planned according to the actual business needs. The absolute path of these disks will serve as the value of the --data parameter, separated by commas, such as `--data /dev/yfs/data0,/dev/yfs/data1,/dev/yfs/data2`.The absolute path is generated by the configuration described below in this document.
	
	Considering the redundancy of data disk groups, the number of data disks can be planned as a multiple of the actual demand. Data disks can also be added later during operation according to circumstances.
		

When performing disk partitioning on shared disk arrays or NVMe SSDs, the purpose and capacity of the partitioning units should correspond to the above two types of disks. For example, if planning 3 system disks of 2G size, you need to partition 3 LUNs of 2G size on the shared disk array, or partition 3 namespaces of 2G size on the NVMe SSD. This document does not provide operational guidance for disk partitioning of storage devices; please operate according to the installation guidance provided by the vendor.

####  Method One: Multipath Binding



##### Step 1: Generate Configuration File

1. Log in to the server as the root user.

2. Create a script named `genDevRuleByUUID.sh` in the root directory:

   ```shell
   # cd ~
   # vi genDevRuleByUUID.sh
   ```

3. Input the following content and modify `DEVICES` to the paths of each device, change `TARGETS` to the binding names of each device, ensuring names correspond to device paths, and modify `YFS_DISK_DIR` to the binding directory. Save and exit. 



   ::: tabs
   == CentOS

```shell
#/bin/bash

# Please change to the paths of each device
DEVICES=("/dev/mapper/lun01-data0" "/dev/mapper/lun03-sys0" "/dev/mapper/lun04-sys1" "/dev/mapper/lun05-sys2")
# Please specify the names for binding these devices in the same order as the DEVICES array, ideally related to the business
TARGETS=("data0"                   "sys0"                   "sys1"                   "sys2")
# Specify the binding directory
YFS_DISK_DIR="yfs"

# Keep default; ensure the yashan user exists
USER="yashan"
GROUP="yashan"
UGROUP="$USER:$GROUP"

if [ ${#TARGETS[@]} != ${#DEVICES[@]} ]
then
    echo "DEVICES and TARGETS count does not match"
    exit 1
fi

if [ ${#TARGETS[@]} == 0 ]
then
    echo "no targets found"
    exit 1
fi

curDir=$(cd "$(dirname "$0")";pwd)
rm -f $curDir/yashan-device-rule.rules

count=${#TARGETS[@]}

for ((i = 0; i < $count; i ++))
do
    device=${DEVICES[$i]}
    target_name=${TARGETS[$i]}
    target="${YFS_DISK_DIR}/${target_name}"
    
    str1="$device:`udevadm info --query=all --name=$device | grep DM_UUID`"
    str2=${str1#*=}
    echo "KERNEL==\"dm-*\",ENV{DM_UUID}==\"${str2}\",SYMLINK+=\"$target\",OWNER=\"$USER\",GROUP=\"$GROUP\",MODE=\"0666\",OPTIONS:=\"nowatch\",RUN+=\"/bin/sh -c 'chown -R $UGROUP $target'\""  >> $curDir/yashan-device-rule.rules
done
```

###  Manual Operation

Manual mapping of NVMe-oF disks requires installing nvme-cli or nvmetcli tools. This chapter uses nvmetcli tool as an example.  

1. Load NVMe-related modules and drivers.

   ::: tabs

## Binding Disks for YAC (Distributed Storage) Deployment

In YAC (distributed storage) deployment, you need to log in to each instance server as root user or a user with sudo privileges, and bind all successfully connected NVMe-oF disks.

All NVMe-oF disks should be bound to the same directory on the server, which will serve as the value for the --disk-found-path parameter. This document uses the default value /dev/yfs as an example.

The following table shows binding path examples:

|NVMe-oF Disk |Disk Usage |Planned Binding Path (Example Value) |
|------------|--------------------------------------|--------|
| /dev/nvme4n1 | System Disk | /dev/yfs/sys0 |
| /dev/nvme3n1 | System Disk | /dev/yfs/sys1 |
| /dev/nvme1n1 | System Disk | /dev/yfs/sys2 |
| /dev/nvme2n1 | Data Disk | /dev/yfs/data0 |



The binding directory (/dev/yfs) and disk names (data0, sys0, etc.) are example values. Please adjust according to actual business needs, but keep in mind:

- The absolute path length of the disk after binding (e.g., `/dev/yfs/sys0`) must not exceed 31 bytes.
- Both the binding directory and the absolute paths of the disks will be used as corresponding parameter values in the `yasboot package ce gen` command. If there are modifications, please use the actual values when executing `yasboot package ce gen`.





### Step 1: Generate Configuration File

1. Log in to the server as the root user.

2. Create a script named `genDevRuleByUUID.sh` in the root directory:

   ```shell
   # cd ~
   # vi genDevRuleByUUID.sh
   ```

3. Input the following content and modify `DEVICES` to the paths of each device, change `TARGETS` to the binding names of each device, ensuring names correspond to device paths, and modify `YFS_DISK_DIR` to the binding directory. Save and exit. 



   ::: tabs
   == CentOS

```shell
#/bin/bash

# Please change to the paths of each device
DEVICES=("/dev/nvme2n1" "/dev/nvme4n1" "/dev/nvme3n1" "/dev/nvme1n1")
# Please specify the names for binding these devices in the same order as the DEVICES array, ideally related to the business
TARGETS=("data0"                   "sys0"                   "sys1"                   "sys2")
# Specify the binding directory
YFS_DISK_DIR="yfs"

# Keep default; ensure the yashan user exists
USER="yashan"
GROUP="yashan"
UGROUP="$USER:$GROUP"

if [ ${#TARGETS[@]} != ${#DEVICES[@]} ]
then
    echo "DEVICES and TARGETS count does not match"
    exit 1
fi

if [ ${#TARGETS[@]} == 0 ]
then
    echo "no targets found"
    exit 1
fi

curDir=$(cd "$(dirname "$0")";pwd)
rm -f $curDir/yashan-device-rule.rules

count=${#TARGETS[@]}

for ((i = 0; i < $count; i ++))
do
    device=${DEVICES[$i]}
    target_name=${TARGETS[$i]}
    target="${YFS_DISK_DIR}/${target_name}"
    
    str1="$device:`udevadm info --query=all --name=$device | grep DM_UUID`"
    str2=${str1#*=}
    echo "KERNEL==\"dm-*\",ENV{DM_UUID}==\"${str2}\",SYMLINK+=\"$target\",OWNER=\"$USER\",GROUP=\"$GROUP\",MODE=\"0666\",OPTIONS:=\"nowatch\",RUN+=\"/bin/sh -c 'chown -R $UGROUP $target'\""  >> $curDir/yashan-device-rule.rules
done
```
