This view displays all redo file information.  
Under YACs, it shows the redo file information for all instances.

|Column Name |Type |Description |
| --- | --- | --- |
| THREAD# | TINYINT | Instance number |
| ID  | INTEGER | Redo file ID |
| NAME | VARCHAR(255) | Redo file path |
| BLOCK\_SIZE | INTEGER | Page size of the redo file (unit: bytes) |
| BLOCK\_COUNT | BIGINT | Total number of pages in the redo file |
| USED\_BLOCKS | BIGINT | Number of pages used in the redo file |
| SEQUENCE# | INTEGER | Sequence number of the redo file, this sequence number increments |
| STATUS | VARCHAR(8) | Status of the redo file<br>*   NEW: The file has not written any redo logs, it is a newly created redo file or has been initialized<br>*   INACTIVE: The redo file in this status contains pages of redo that have been written to disk. This status of redo file can be reused<br>*   ACTIVE: The redo file in this status contains pages of redo that have not been written to disk, or the redo has not been archived yet. Therefore, files in this status cannot be reused<br>*   CURRENT: The currently used redo file |
| TYPE | VARCHAR(8) | Type of the redo file<br>*   ONLINE: Indicates an ONLINE file, used to store redo generated by the primary database<br>*   STANDBY: Indicates a STANDBY file, used to store redo files generated by the logical standby database |
| ARCHIVED  | VARCHAR(3) | Whether the redo file has been archived<br>*   YES: The redo file has been archived<br>*   NO: The redo file has not been archived |
| HEALTH | VARCHAR(32) | Health status of the redo file during database loading<br>*   NORMAL: The redo file is normal<br>*   MISSING: The redo file is missing<br>*   HEAD_CURRUPTED: The header of the redo file is corrupted |
