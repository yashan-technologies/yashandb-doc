## Version Positioning

YashanDB v23.4.10 enriches new features and continues performance optimization based on v23.4.9, serving as a version available for long-term service support.

## Version Information

**Version Number**: v23.4.10.100

**Release Date**: May 9, 2026

## New Features

YashanDB v23.4.10 inherits all functionalities released in YashanDB v23.4.9 and adds the following key features:

### SQL Engine Enhancements

- SQL Function Enhancements:

    - Views support FOR UPDATE functionality: This release enhances the FOR UPDATE capability for views, supporting WAIT, NOWAIT integer, SKIP LOCKED clauses, and is compatible with Oracle database syntax. By extending the lock parsing and execution module for view queries, the FOR UPDATE operation on views is correctly mapped to base table row locks, uniformly supporting row-level locking control. Users can directly use SELECT ... FOR UPDATE WAIT (wait for specified seconds before timeout), NOWAIT integer (return immediately or wait for specified seconds before timeout), and SKIP LOCKED (skip locked rows) in view queries to achieve row-level locking and concurrency control on the result set returned by the view. In high-concurrency scenarios, SKIP LOCKED can effectively avoid lock contention blocking and improve task processing efficiency, while WAIT/NOWAIT provides more flexible timeout control, enhancing system controllability and stability.

    - Added support for correct parsing of numeric constants, character constants, and keywords without separation as two tokens: This release enhances the text segmentation capability of the Lexer, improving SQL parsing ability in Oracle-compatible mode for scenarios where numeric constants, character constants, and keywords are adjacent. By optimizing the Token identification and segmentation logic in the lexical analysis phase, when numeric constants (e.g., 123, 3.14) or character constants (e.g., 'abc') have no space separation from subsequent keywords (e.g., OR, AND), the parser can correctly identify and segment them into two independent syntactic units. Users can now execute SQL statements such as `SELECT 1 FROM DUAL WHERE 1=1AND 0<>1;`, which are consistent with Oracle behavior, without manually adding spaces between constants and keywords. This capability effectively reduces the syntax compatibility cost when migrating SQL scripts from Oracle, reduces parsing errors caused by missing spaces, and improves the database's ability to directly execute historical business SQL.

    - Added support for UNIQUE keyword for deduplication (mutually synonymous with DISTINCT): This release adds support for using the UNIQUE keyword as a synonym for DISTINCT. By extending the SQL syntax parsing module, UNIQUE and DISTINCT are recognized as equivalent deduplication identifiers in SELECT clauses, using the same deduplication execution logic for processing. This provides more flexible deduplication syntax options and enhances SQL writing convenience.

    - Added USERENV parameter to SYS_CONTEXT: This release enhances the SYS_CONTEXT system function capability by adding support for multiple session context attributes under the USERENV namespace. By extending the access capability of `SYS_CONTEXT('USERENV', 'parameter_name')`, users can now obtain database session-level dedicated environment information, including database unique name, instance name, session identifier, date format, and other key attributes. These attributes allow quick access to session context information without needing to query complex system views, improving development efficiency and system observability.

    - TO_NUMBER function supports CLOB type: This release enhances the type conversion capability of the TO_NUMBER function by adding support for CLOB type as an input parameter. When CLOB contains valid numeric content, it can be directly converted and returned as NUMBER type. This enhancement simplifies the process of extracting numeric values from large text fields, avoids explicit type conversion intermediate steps, and improves development efficiency and execution performance.

    - Added support for DBA_JOBS_RUNNING view to view currently running jobs: This release introduces the DBA_JOBS_RUNNING system view for viewing currently running background job information. It captures currently executing jobs and their related attributes in real time. Users can query the DBA_JOBS_RUNNING view to obtain a list of running jobs, including key information such as job ID (JOB), session ID (SID), instance ID (INSTANCE_ID), and start time (START_DATE). This enables real-time monitoring of job execution status and quick identification of long-running jobs, effectively improving operational observability for background jobs.

    - Listener log supports configuring log cleanup policies: This release enhances the Listener Log management capability by adding support for time-based and file count-based log cleanup policy configuration. Through new independent configuration items, users can flexibly set individual log file size and total file count. When logs are full, they will automatically be cyclically overwritten. The default does not set a cleanup policy, requiring users to actively configure as needed, avoiding impact on existing operational habits.

- PL Capability Enhancements:

    - Function overloads support using bind parameters: Previously, YashanDB's PL did not support bind parameters for overloaded functions in packages (PKG) and user-defined types (UDT). There was a constraint where calling overloaded functions through bind variables could not match to specific function implementations. This release enhances the PL engine's parsing capability for function overloads, supporting correct identification and matching of overloaded functions in bind parameter scenarios. This bridges the behavioral difference with Oracle in overloaded function bind parameter scenarios and improves PL flexibility in using overloaded functions.

    - Static SQL supports LOCK TABLE functionality: This release enhances the capability to explicitly lock tables in stored procedures by adding support for directly using LOCK TABLE syntax in static SQL, compatible with Oracle PL/SQL behavior. There is no longer a need to implement it indirectly through dynamic SQL (such as EXECUTE IMMEDIATE). This capability simplifies the writing of lock control logic in stored procedures and improves code readability and execution efficiency.

    - Lexical parsing supports special characters: This release enhances the PL lexical parser's handling capability for special characters when accessing record attributes, supporting newline access between record type values returned by function calls and attribute names. By optimizing the whitespace character (space, newline, tab) processing logic in the lexical analysis phase, when parsing attribute access expressions connected by dots (.), newlines and other whitespace characters are allowed before and after the dot. This capability solves parsing failure issues caused by code formatting line breaks, allowing developers to freely adjust line break positions according to code style, improving code writing flexibility and readability, and reducing adaptation costs when migrating applications from Oracle.

    - DBMS_PARAM system package supports TPCC test optimization recommendation parameters: This release enhances the DBMS_PARAM system package capability. DBMS_PARAM.OPTIMIZE adds a new SCENE parameter value to support automated parameter recommendation and optimization for TPCC test scenarios. Users can specify the target environment (small, medium, large specification) CPU core count and memory size. The system package automatically calculates and recommends suitable database IO and memory-related parameter configurations, enabling rapid TPCC test optimization and quick tuning to optimal test results.

    - PL supports local variable caching: Added support for PL local variable caching capability, which automatically adjusts multi-level access complex UDT access expressions to be cached as local common variables, uniformly reusing variable results, and avoiding additional calculation and access overhead from multiple multi-level UDT accesses. This simplifies implementation, controls the scope of changes, and ensures engine execution efficiency. After optimization, it effectively solves the poor performance issue of multi-level nested UDT repeated access, greatly reducing redundant expression calculation logic. In loop iteration scenarios, the more repeated complex variable accesses, the more significant the performance improvement, overall PL loop statement execution efficiency and runtime performance are significantly improved.


### YAC Capabilities

- DDL operation capability enhancement: In actual business, if a large number of deletions (Delete/Drop/Truncate) cause "holes" in the tablespace, in order to reduce these holes and improve storage utilization, YAC supports the tablespace shrink space function, allowing businesses to more effectively reduce holes, improve storage utilization while reducing storage risks.

- YAC high availability capability improvement: Supports automatic failover switching in one-primary-multi-standby deployment scenarios, ensuring automatic failover when all instances of the primary cluster fail, reducing system failure time and RTO recovery time.

- YFS capability enhancement: In YFS multi-replica management, it is generally required that each replica's disk size be consistent, otherwise it will affect striping and cause disk usage waste. However, in external redundancy (single replica), there is no multi-replica management mechanism constraint. Considering the actual business usage and changes in disk procurement specifications, it supports online addition of disks with different sizes from existing ones under external redundancy, facilitating business scaling.

### MySQL Compatibility

- YashanDB (mysql mode) supports creating multiple indexes on the same column: This release enhances the capability to create multiple indexes on the same column in mysql mode, allowing the same column to simultaneously have multiple index types including primary key, unique constraint, foreign key corresponding indexes, and regular indexes. Users can create multiple indexes or constraints on the same column when executing CREATE TABLE statements in mysql mode, or add different types of indexes to an existing table, covering various query scenarios such as equality queries, sorting, and unique constraint scenarios. This reduces adaptation costs when migrating applications from MySQL, provides more flexible index design space, and enriches business scenarios.

- YashanDB (mysql mode) supports REGEXP/RLIKE regular expression matching: This release enhances regular expression matching capability in mysql mode by adding support for REGEXP and RLIKE operators, used for complex text validation, fuzzy search, data cleaning and filtering, log/text analysis, and other scenarios. By extending SQL syntax to support REGEXP and RLIKE as synonyms for REGEXP_LIKE, it achieves pattern matching capability based on regular expression standards. This can improve development efficiency and query expression ability in fuzzy search and text validation scenarios.

- YashanDB (mysql mode) supports sql_mode ONLY_FULL_GROUP_BY ORDER BY usage: This release enhances the GROUP BY and ORDER BY behavior under ONLY_FULL_GROUP_BY SQL mode in mysql mode, supporting the appearance of non-GROUP BY fields in projection columns and ORDER BY clauses, representing the corresponding field value from the top record of each group. By extending the execution logic of group queries, when ONLY_FULL_GROUP_BY mode is enabled, it no longer strictly rejects non-GROUP BY fields in projection columns and ORDER BY, but adopts a "select any record from the group" value strategy consistent with MySQL's native behavior, returning the corresponding field value from that record. This provides a more concise SQL writing method and improves query expression convenience.

### Drivers

- JDBC supports escaped scalar function fn LENGTH: This release enhances the JDBC driver's escaped function handling capability by adding support for recognition and replacement of `{fn LENGTH(parameter)}` escape syntax, converting it to YashanDB executable `LENGTH(parameter)` SQL statements. By adding an SQL syntax preprocessor at the JDBC driver layer, the original SQL is parsed before being sent to the server. It identifies `{fn LENGTH(XXX)}` structured escaped function calls and replaces them with the database's natively supported `LENGTH(XXX)` function. This improves the overall compatibility of the JDBC driver.

- ADO.NET Driver Capability Enhancements:

    - ADO.NET driver supports 32-bit runtime environment: This release adds support for 32-bit runtime environment, enabling the ADO.NET driver to run normally on 32-bit operating systems and applications. This solves the pain point of some customers who cannot upgrade to 64-bit environments due to historical reasons and cannot use the ADO.NET driver, expanding the driver's applicable scenarios and platform coverage, and improving the product's compatibility in diverse runtime environments.

    - ADO.NET driver supports thread safety and handle release order protection: This release enhances the ADO.NET driver's threading capability, ensuring that driver instances will not experience data races, object state confusion, connection leaks, or memory double-free issues during multi-threaded concurrent calls. It can safely share and reuse driver instances in multi-threaded environments, where multiple threads can simultaneously initiate database operation requests without causing program crashes, memory CORE, or resource leaks. This improves the stability and reliability of the ADO.NET driver in high-concurrency business scenarios, providing a safe and reliable access foundation for building multi-threaded database applications.
