## Version Positioning

YashanDB v23.4.8 enriches new features and continues performance optimization based on v23.4.7, serving as a version available for long-term service support.

## Version Information

**Version Number**: v23.4.8.100

**Release Date**: April 17, 2026

## New Features

YashanDB v23.4.8 inherits all functionalities released in YashanDB v23.4.7 and adds the following key features:

### SQL Engine Enhancements

- Optimized SQL Pool plan-related memory release and reuse capabilities: This release optimizes the release strategy and reuse capability for plan memory management in the SQL Pool (Shared Pool). By enhancing the active release mechanism of PlanGroup, refining resource tracking views, adjusting the LRU eviction algorithm, and optimizing memory dynamic adjustment capability between Share Pools, it effectively solves issues such as long-term plan memory occupation, cold data inability to be evicted, and hot spot lock contention. It can improve shared pool memory utilization efficiency and overall system stability, reduce memory occupation and fragmentation, decrease hot spot lock contention, and improve plan cache hit rate.

- Enhanced deadlock log with bound parameter output: This release enhances the deadlock log output capability by adding support for bound parameter values. When the SMON background thread detects a deadlock, the system automatically captures the bound parameter values in the SQL statement that caused the deadlock, as well as related session information, and outputs it with an upper limit of 2000 bytes. Now, users can obtain the actual bound parameter values (not just placeholders) in the deadlock log, as well as session context information such as Session ID (SID) and Serial Number (SERIAL#) when the deadlock occurred. This improvement enhances the efficiency of locating deadlock issues. Users can quickly identify the specific data and sessions causing the deadlock without additional tracing, reducing the difficulty of troubleshooting.
