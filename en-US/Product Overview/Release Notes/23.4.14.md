## Version Positioning

YashanDB v23.4.14 enriches new features and continues performance optimization based on v23.4.10, making it a version that can be used for long-term service support.

## Version Information

**Version**: v23.4.14.100

**Release Date**: July 16, 2026

## New Features

YashanDB v23.4.14 inherits all features released in YashanDB v23.4.10 and adds the following key features:

### SQL Engine Enhancements

#### System Packages

- Added the UTL_SMTP system package: provides service interfaces based on the SMTP protocol for sending emails.

- Added the DBMS_PROFILER system package: supports line-level performance analysis for PL programs, including information such as code execution count, execution time, code coverage, and time consumption ratio.

- Added the DBMS_LOCK system package: supports user-defined locks for concurrent control of shared resources. It supports creating, acquiring, and releasing locks, as well as setting lock wait times.

- Added the DBMS_SYSTEM system package: implements the KSDWRT function to support writing user-defined information to trace files or runtime logs.

- Enhanced the DBMS_CRYPTO system package: added support for PAD_ZERO, PAD_PKCS5, and CHAIN_ECB constants to meet padding and mode requirements in different encryption scenarios.

- Enhanced the DBMS_XMLGEN system package: added support for the SetRowSetTag and SetRowTag functions, enabling custom setting of row tag and rowset tag names in XML documents.

#### Built-in Functions

- Added the TO_NCHAR conversion function: converts various data types into national character set (NCHAR/NVARCHAR2) format, addressing data type conversion issues in Oracle-to-YashanDB migration scenarios.

- Added the CORR built-in function: calculates the linear correlation coefficient between two numeric variables to measure the strength and direction of variable correlation (the result ranges from -1 to 1).

- Added the XMLELEMENT built-in function: converts data in the database into XML-format elements for constructing XML documents or returning XML-structured data in query results.

- Added the XMLSERIALIZE built-in function: serializes XMLTYPE data into plain text (VARCHAR2/CLOB/STRING) or a binary large object (BLOB).

- Enhanced the TABLE function: input parameters now support the SELECT pipeline function TABLE(XXX) syntax. When a pipeline function is called in the projection list of a SELECT statement rather than in the FROM clause, the pipeline function degrades from streaming execution mode to normal function execution mode.

- Expanded and optimized the LEAD and LAG window functions:

    - Supports window frame definitions containing ROWS BETWEEN and RANGES BETWEEN.

    - Supports batch and parallel execution.

- Expanded specifications for some numeric functions: added the MATH_FUNC_RETURN_DECIMAL parameter to control whether the return types of logarithmic, exponential, and trigonometric functions on numeric types (INT, NUMBER, etc.) are fully compatible with Oracle. When set to TRUE, functions whose input parameters do not include FLOAT/DOUBLE return the NUMBER type and validate invalid input values. When set to FALSE (default), functions return the DOUBLE type and retain the original behavior.

#### Syntax Features

- Supports JOIN USING syntax: supports using the USING clause instead of the ON clause to specify equi-join conditions, simplifying SQL writing for multi-table equi-joins.

- Supports DML constant parameterization: DML statements support constant parameterization for cursor_sharing, controlling whether SQL statements automatically replace literals with bind variables to determine whether execution plans can be shared. The supported scope is aligned with DQL statement behavior.

- Enhanced bind variable syntax: in bind variable scenarios, spaces are supported after the colon (for example, `: 1`, `: user`), improving SQL writing flexibility.

- Enhanced user-defined aggregate functions: user-defined aggregate functions support the DISTINCT keyword to deduplicate parameters, improving the usability of user-defined aggregate functions.

- Expanded and optimized expressions in the GROUP BY clause:

    - If a column is equivalent to a scalar, it can still be used as a grouping column even if it is not declared after GROUP BY.

    - If a subquery contains a column equivalent to a non-GROUP BY column in the projection list, it is allowed to be returned in the projection list.

    - If a subquery contains a column equivalent to a non-ORDER BY column in the projection list, it is allowed to be returned in the projection list.

#### Performance Optimization

- Multi-Version Plan Optimization:

    - Runtime statistics aggregated at the plan granularity: supports querying runtime statistics for each execution plan operator through the V$SQL_PLAN_STATISTICS, V$SQL, and V$SQLAREA views.

    - Adjusted the PLAN_HASH_VALUE algorithm: it depends only on the plan tree shape, operator type, and accessed objects, and is unrelated to specific data.

- Filter sort optimization: optimized the Filter sorting algorithm, improved cost calculation logic, and replaced quicksort with stable and better-performing merge sort to improve the accuracy of CBO execution plan selection.

- Static SQL optimization in loops: introduced a session-level cursor cache mechanism that caches frequently executed static SQL in PL using an LRU strategy, reducing repeated parsing and context loading overhead and improving execution performance.

- Shared CTE optimization: optimized shared CTE execution in views and DBLink scenarios, allowing CTEs defined in views and CTEs containing DBLinks to use the shared reuse mechanism and achieve performance aligned with direct CTE execution.

- Supports scalar subquery-to-join transformation on the left table: when the left table in an SQL statement is used for correlated comparison with a scalar subquery, scalar subqueries are supported for join execution in left-table scenarios by swapping the non-subquery side to the right table, improving query performance.

- UDF execution optimization: when PL code contains loops (FOR/WHILE/LOOP) and functions are called within them, function preparation results are cached during the first execution and directly reused in subsequent iterations, significantly improving performance.

- INSERT … ON DUPLICATE KEY UPDATE optimization: supports pre-checking conflicting rows through primary key indexes, quickly separating data into INSERT rows and UPDATE rows, avoiding rollback overhead caused by failed INSERT operations due to conflicts. Batch insertion of INSERT rows reduces the overhead of repeatedly searching for free space.

- Transaction optimization: introduced a concurrent transaction scheduling strategy that can precisely wake queued transactions in order, avoiding unnecessary rereads and lock contention and resolving performance degradation in hot data concurrent update scenarios.

#### MySQL Compatibility

- In YashanDB (mysql mode), operations on LOB/TEXT types are supported in Filter, ORDER BY, DISTINCT, and GROUP BY scenarios.

- In YashanDB (mysql mode), column aliases are supported in the GROUP BY and HAVING clauses.

### Storage Engine Enhancements

- Enhanced ALTER SEQUENCE: supports syntax and functionality for specifying (START WITH) and resetting (RESTART) the starting value of a sequence.

- Enhanced ALTER SYSTEM KILL SESSION: supports batch termination of sessions that are executing transactions or sessions with no active transactions, and supports executing the corresponding session termination commands through *yasboot*. Internal connection sessions (such as sessions established by YStream clients) are preserved.

- Optimized B-tree index data deletion: when concurrently deleting B-tree index data, automatic block splitting is supported when xslots are insufficient, solving deadlock issues in highly concurrent scenarios.

- Optimized LOB index management: supports LOB INDEX COALESCE to reclaim free pages, reduce invalid buffer acquisition operations, and alleviate performance degradation in LOB operation business scenarios.

- Optimized SEQUENCE: optimized the access mechanism for SEQUENCE value retrieval in YAC Deployment, resolving GC issues when obtaining nextval for SEQUENCE in multi-instance scenarios, and improving performance and scalability.

- Optimized full table scans in YAC Deployment: introduced the SharedOwner mechanism to optimize multi-instance serial full table scan performance.

### High Availability Enhancements

- Supports *yasom* high availability: in Standalone One-Primary/Multi-Standby Deployment (Non-Cascade Standby), *yasom* high availability has been implemented, that is, *yasom* Primary-Standby Leader Election. After the *yasom* Primary-Standby Leader Election feature is enabled, standby *yasom* automatically detects whether the primary *yasom* is operating normally. Once a fault is detected, Leader Election is triggered and *yasom* role switch can be completed without manual intervention. The *yasom* Primary-Standby Leader Election feature depends on YCM for implementation and normal operation.

    - Stores key metadata remotely: uses the YCM background database to store the heartbeat table that records heartbeat information of primary and standby *yasom* and information related to Primary-Standby Leader Election.

    - Fault isolation: faults in the target database are completely isolated from faults in *yasom* Primary-Standby Leader Election metadata.

- Supports *yasom* Election in One-Primary/Multi-Standby Deployment (Dual-Center): for dual-center scenarios with 2 nodes deployed in each center, supports automatic and manual primary-standby switching through monitored arbitration while satisfying RPO=0 and RTO<30s. When the Primary Database fails, failover preferentially switches to a Standby Database in the same center. Whether switching automatically within the same center or across centers, the prerequisite of RPO=0 must be satisfied. If this cannot be satisfied, automatic switching is not performed and manual intervention is required (*yasom* arbitration must be disabled first).

- Supports upgrade in database environments with cascade standby: supports upgrade in deployment scenarios with cascade standby and supports manual one-click rollback after upgrade failure.

    - Offline upgrade: supports cross-major-version upgrade. The entire database environment needs to be stopped for the upgrade operation, and after software upgrade is completed on all nodes, the environment must be restarted to ensure data consistency.

    - Online rolling upgrade: supports upgrade only between compatible versions (for example, 23.4.14.100 -> 23.4.14.101). During the upgrade, the database can continue providing services. Nodes are upgraded one by one, and business continuity is ensured through primary/standby switchover.

- Supports add/remove management of cascade standby databases in Standalone (Primary-Standby) Deployment: when the data volume of the parent standby database in the current environment is 0 or 1, supports add/remove management of cascade standby databases in the following scenarios.

    - In Standalone One-Primary/Multi-Standby Deployment with cascade standby: supports adding a new cascade standby to a Standby Database or removing an existing cascade standby.

    - In Dual Rep-Group Primary-Standby Deployment: supports online scale out and scale in of non-primary nodes (that is, cascade standbys) in the standby replication group.

- Optimized Primary-Standby Cluster Scale Out: supports directly adding YCS nodes during standby cluster scale out without waiting for switchover to complete, while ensuring bidirectional mutual exclusion between add node and switchover/failover, and adapting to the cleanup process when standby cluster scale out fails.

### O&M Capability and Usability Enhancements

- Supports ASH functionality: this version periodically samples database active sessions, continuously records key performance data such as session states, wait events, and SQL execution information, implements the V$ACTIVE_SESSION_HISTORY view, and provides the built-in advanced package DBMS_WORKLOAD_REPOSITORY to generate ASH reports, helping DBAs efficiently locate performance bottlenecks and significantly improving database O&M efficiency.

- AWR supports Segment Statistics: added V$SEGMENT_STATISTICS related views for real-time statistics of performance metrics such as physical reads and writes, logical reads and writes, full table scans, lock waits, and buffer cache hit rates for all tables, indexes, partitions, and LOB segments. The AWR report is enhanced with the new Segment Statistics item to help database administrators accurately locate I/O hotspots and storage bottlenecks at the object granularity.

- Enhanced deadlock log diagnostics: deadlock logs support outputting bind variable information and can be configured to enable or disable this feature (enabled by default), helping users quickly locate root causes of deadlocks.

- Supports DBA_HIST views: the DBA_HIST_SQLTEXT view is used to display historical SQL text, the DBA_HIST_SQLSTAT view is used to display SQL execution statistics, and the DBA_HIST_SQL_PLAN view is used to display historical SQL execution plans.

- Enhanced V$SESSION: added the `PLSQL_ENTRY_OBJECT_ID`, `PLSQL_ENTRY_SUBPROGRAM_ID`, `PLSQL_OBJECT_ID`, `PLSQL_SUBPROGRAM_ID`, and `LAST_CALL_ET` fields to display PL object information executed by the current session and the elapsed time since the last call, helping users locate where SQL statements are called in stored procedures.

- Enhanced V$SQLAREA: added the `PROGRAM_ID` and `PROGRAM_LINE#` fields to display the PL object ID and line number associated with an SQL statement, which is helpful for SQL performance analysis and audit tracing.

- Enhanced V$PARAMETER: added the `ISDEFAULT`, `ISSES_MODIFIABLE`, `ISSYS_MODIFIABLE`, and `ISMODIFIED` fields, allowing users to more conveniently determine whether a parameter is a default value, whether session-level modification is supported, whether system-level modification is supported, and whether the parameter has been modified since startup, which helps with daily O&M and parameter status inspection.

### Driver Enhancements

- JDBC version consolidation: LTS and LTS patch versions use a unified JDBC version, avoiding maintenance and support of multiple JDBC branches.

- JDBC capability enhancement: supports UDT types as output parameter types for stored procedures.

- C driver adaptation optimization based on Sysbench: adds YashanDB database support for Sysbench, enabling Sysbench to perform various benchmark tests on YashanDB, including driver support, build integration, standards compatibility, error handling, and support for combined scenarios.

- ODBC capability enhancement: SQLSetStmtAttr and SQLGetStmtAttr interfaces support row-wise parameter binding (SQL_ATTR_ROW_BIND_TYPE/SQL_ATTR_PARAM_BIND_TYPE).

### Tool Enhancements

- Enhanced *exp*/*imp* tool capabilities: improved support for export and import scenarios involving hidden columns and auto-increment columns.

    - Added a parameter to specify whether hidden columns are processed. It is enabled by default, meaning hidden columns are exported/imported.

    - For ALWAYS auto-increment columns, the tool can directly import ALWAYS auto-increment column data during import.

    - For BY DEFAULT auto-increment columns, START WITH is adjusted to the maximum value in the column plus 1 during import.

- Performance optimization for *exp* export: when exporting table data in `--csv` format without LOB columns (including XML, JSON, etc.), supports concurrent execution of single-table fetch and decoder, improving performance by approximately 50%.

- Enhanced *yasql*: supports set time on to display the time when Enter is pressed after executing an SQL command. This time is obtained by the client from the current system time, is not affected by the current time zone parameter, and defaults to the `HH24:MI:SS` format.
