## Version Information

**Version Number**: v23.5.2.100

**Release Date**: Apr 17, 2026

## Version Positioning

YashanDB v23.5.2 version is positioned as an architectural release, adding vector storage and retrieval capabilities, optimizing YAC multi-node parallel query and single operator execution performance, enhancing MySQL compatibility and productization features, supplementing tenant resource management and operations monitoring capabilities, providing data migration, monitoring operations and developer tools, providing a one-stop data platform with high reliability, high performance, and high compatibility for domestic replacement of financial core systems, meeting the needs of various enterprise applications.

## Feature Updates

YashanDB v23.5.2 version inherits all released features from YashanDB v23.5.1 and v23.4.7 versions, while adding the following key features.

### Vector Storage and Retrieval

This version adds vector storage and retrieval capabilities, providing high-performance and high-availability vector data processing services for enterprise-level AI applications, supporting Retrieval Augmented Generation (RAG), recommendation systems, semantic search and other AI-native scenarios, helping customers quickly build intelligent applications.

- Data Types

    Natively supports vector data types with maximum dimension up to 65535, supporting DENSE storage format and 32-bit and 64-bit floating point storage.

- SQL Operations

    Supports basic DDL operations such as CREATE TABLE, ALTER TABLE, and CREATE INDEX, supports INSERT, UPDATE and DELETE operations and batch data import, supports completing vector similarity calculation + scalar filtering + spatial query hybrid operations in a single SQL statement, providing implicit conversion, explicit conversion functions and vector description functions.

- Vector Index and Functions

    Supports exact search and approximate nearest neighbor search, supports L2 Euclidean distance, inner product and cosine similarity calculations and their operators, supports HNSW index with maximum index column dimension of 4096.

- Drivers and Protocols

    Native SQL support: Provides C driver and YASQL interface, supports Python SDK for vector database operations, only YashanDB driver protocol supports vectors.

- Performance

    Under Ann-BenchMark 1 million data test model, recall rate above 0.95, QPS close to one thousand, performance on par with mainstream vector databases

### Tenant Capability Enhancement

- Tenant Resource Management Capability Improvement

  - cgroup v2 Support: v23.5.2 version supports cgroup v2, better adapting to and compatible with higher version cgroup capabilities.

  - Primary-Standby CDB Resource Management: Achieves complete tenant resource management capability in primary-standby CDB deployment environment, supporting CPU, memory, and IO resource control and management, ensuring resource change operations consistency between primary and standby environments.

- Tenant Memory Online Expansion Support

  Through new CDB_MAX_MEMORY_SIZE parameter, can increase this parameter to dynamically adjust tenant memory quota without restarting database instances or affecting business operations, optimized DATA_BUFFER_SIZE and VM_BUFFER_SIZE configuration parameters, can take effect online through ALTER SYSTEM, achieving real-time resource changes without business perception.

- YAC Tenant Capability Improvement

  Based on v23.5.1, supplemented and improved the following capabilities: backup recovery capabilities (archive backup, PITR, etc.), VIP and SCAN IP support, PDB IO FENCE support, full database flashback, etc.

### Feature Enhancements

- Composite Partition with Interval Support

  Added composite partition and Interval partition capability, allowing first-level partitions to be set as Interval partition type, implementing interval-range, interval-hash, interval-list composite partitions, achieving automatic partition expansion management and reducing DBA daily operations workload.

- MySQL Compatibility Feature Enhancement

    In YashanDB (mysql mode), index handling for NULL values is aligned with MySQL.

    Supports creating composite unique indexes with NULL values without triggering unique index conflict errors, compatible with MySQL's index handling behavior for NULL values.

    YashanDB (mysql mode) adds support for ON UPDATE CURRENT_TIMESTAMP keyword.

    Supports setting automatic update rules for TIMESTAMP and DATETIME fields. When a record is modified by UPDATE statement and the field is not explicitly updated, the field automatically updates to current system timestamp, simplifying data update time maintenance process.


### Performance Optimization

#### SQL Performance Enhancements

- ROWID Filter Nested Loops Join Support

  When SQL statements use ROWID as a filtering condition in IN subqueries, the optimizer can generate ROWID-based Nested Loops Join execution plans, providing better performance than traditional Hash Join execution plans in scenarios returning data volumes.

- Complex DML Optimization: In large data volume scenarios with DML operations and complex queries, batch execution architecture adaptation for DELETE and CREATE AS SELECT operations enables the optimizer to adaptively select batch and parallel execution frameworks, improving DML performance.

  - DELETE with Complex Query Fusion

  - CREATE AS SELECT Fusion Support

- Batch Execution Support for Index Scan

  Added batch execution support for index scan operators, covering INDEX_FAST_FULL_SCAN, INDEX FULL/RANGE/SKIP SCAN, and INDEX ROWID/UNIQUE SCAN, effectively improving large data volume query performance.

- SORT Operator Optimization, Added K-Way Merge Path Algorithm

  Upgrades the underlying architecture of the SORT operator to implement the K-Way Merge Path high-performance parallel sorting algorithm, builds a big-endian binary encoding system for sort keys, supports efficient conversion of sort keys to UINT64, implements a new sorting execution process with lazy merging, parallel merging, single I/O, and no intermediate temporary files, achieving a 2~3x improvement in overall sorting throughput.

- CBO Memory Optimization

  Reduces memory consumption of dynamic programming algorithms during multi-table joins by reducing temporary struct size, maximizing struct reuse, prioritizing function stack memory, independent memory context management for heap memory, and Cartesian product path pruning. In scenarios with 9-table and 10-table joins, adjusts the join order generation algorithm from greedy algorithm to dynamic programming optimal planning, reducing CBO optimizer JOIN memory usage and solving the problem of non-optimal join order and low execution efficiency.

- RuntimeFilter Batch and Parallel Support

  Adapts the row-store execution engine RuntimeFilter system to batch framework. In large data volume scenarios, filtering logic can be pushed down to the basic predicate execution layer, implementing batch, parallel, and pipelined predicate calculation and distribution, improving Hash Join and multi-table join query parallel throughput. Simultaneously improves the Autotrace statistics monitoring system, supporting Runtime Filter execution metrics display, enhancing observability and diagnostic capabilities.

#### YAC Performance and Stability Enhancement

-  Introduced MTTR capability to ensure system remains stable and available under sustained database performance pressure.

-  Added multi-node query capability, supporting cross-node partitioned tables, Hash Join, aggregate functions, fully utilizing multi-node CPU/memory/IO resources to accelerate massive data computing.

### High Availability Capability Enhancement

- Full Database Flashback Enhancement, Standby Database/Standby Cluster Can Enable Full Database Flashback Capability

  On business systems with strict performance requirements, users want to enable full database flashback without affecting primary database performance. This version implements standby database full database flashback capability. After the standby database performs flashback, it allows normal data query and export. After obtaining historical data, it can easily restore to a normal physical standby database, reducing data validation and data recovery costs.

- YAC High Availability Capability Improvement

  - YAC Auto Failover Support: Supports automatic Failover switching in one-primary/multi-standby deployment scenarios, ensuring automatic Failover when all instances of the primary cluster fail, reducing system failure time and RTO recovery time.

  - Cluster RTO Optimization: After targeted optimization, in scenarios such as database node failure, YCS node failure, and network failure, the intra-cluster fault RTO can be less than 10 seconds and the inter-cluster primary-standby RTO can be less than 30 seconds under tpmC: 540K pressure, meeting financial-level high availability requirements.


### Security Capability Enhancement

- Login Alert Function

  When users successfully log in, writes login time, IP address, login method and other information to audit log. When user logs in next time, compares current login information with previous login information. When key information changes, alerts or prompts user to pay attention to possible abnormal account access risks.

- Data Masking Enhancement

  - Supports email address prefix masking, retaining email domain part and masking username part.

  - Supports shuffling masking, keeping character set of email username unchanged while randomly rearranging character order.

  - Supports random character replacement masking, replacing email username part with randomly generated equal-length characters (letter, number combination).

  - Supports regular expression masking, supporting user-defined regular expression rules to flexibly match specific patterns in email for masking.

### Operations Capability & Usability Enhancement

- ASH Support

  This version samples active database sessions periodically, continuously recording key performance data such as session state, wait events, and SQL execution information, implementing V$ACTIVE_SESSION_HISTORY view while providing built-in advanced package DBMS_WORKLOAD_REPOSITORY to generate ASH reports, helping DBAs efficiently locate performance bottlenecks and significantly improving database operations efficiency.

- AWR Segment Statistics Support

  Added V$SEGMENT_STATISTICS related views for real-time statistics of physical I/O, logical I/O, full table scans, lock waits, cache hits and other performance metrics for all tables, indexes, partitions, and LOB segments, enhanced AWR report with new Segment Statistics statistics, helping DBAs precisely locate I/O hotspots and storage bottlenecks at object granularity.

- Patch and Version Upgrade View Support

  Added DBA_REGISTRY_HISTORY system view to completely record all patch installation and version upgrade historical operation information, helping DBAs clearly trace database component change trajectories, ensuring change processes are auditable and traceable.

- JDBC CallableStatement Named Parameter Binding Support

  Added named parameter binding capability, solving pain points such as parameter order dependency, poor readability, and difficult maintenance caused by positional binding, improving flexibility and maintainability of stored procedure/function calls.
