## Version Positioning

YashanDB v23.4.12 enriches new features and continues performance optimization based on v23.4.10, serving as a version available for long-term service support.

## Version Information

**Version Number**: v23.4.12.100

**Release Date**: June 15, 2026

## New Features

YashanDB v23.4.12 inherits all functionalities released in YashanDB v23.4.10 and adds the following key features:

### SQL Engine Enhancements

#### System Packages

- Added the DBMS_PROFILER system package: supports line-level performance analysis for PL programs, including information such as code execution count, execution time, code coverage, and time consumption ratio.

- Added the DBMS_LOCK system package: supports user-defined locks for concurrent control of shared resources. It supports creating, acquiring, and releasing locks, as well as setting lock wait times.

- Added the DBMS_SYSTEM system package: implements the KSDWRT function to support writing user-defined information to trace files or runtime logs.

#### Built-in Functions

- Added the CORR built-in function: calculates the linear correlation coefficient between two numeric variables to measure the strength and direction of variable correlation (the result ranges from -1 to 1).

- Expanded and optimized the LEAD and LAG window functions:

    - Supports window frame definitions containing ROWS BETWEEN and RANGES BETWEEN.

    - Supports batch and parallel execution.

- Expanded specifications for some numeric functions: added the MATH_FUNC_RETURN_DECIMAL parameter to control whether the return types of logarithmic, exponential, and trigonometric functions on numeric types (INT, NUMBER, etc.) are fully compatible with Oracle. When set to TRUE, functions whose input parameters do not include FLOAT/DOUBLE return the NUMBER type and validate invalid input values. When set to FALSE (default), functions return the DOUBLE type and retain the original behavior.

#### Syntax Features

- Enhanced user-defined aggregate functions: user-defined aggregate functions support the DISTINCT keyword to deduplicate parameters, improving the usability of user-defined aggregate functions.

- Expanded and optimized expressions in the GROUP BY clause:

    - If a column is equivalent to a scalar, it can still be used as a grouping column even if it is not declared after GROUP BY.

    - If a subquery contains a column equivalent to a non-GROUP BY column in the projection list, it is allowed to be returned in the projection list.

    - If a subquery contains a column equivalent to a non-ORDER BY column in the projection list, it is allowed to be returned in the projection list.

#### Performance Optimization

- Filter sort optimization: optimized the Filter sorting algorithm, improved cost calculation logic, and replaced quicksort with stable and better-performing merge sort to improve the accuracy of CBO execution plan selection.

- Static SQL optimization in loops: introduced a session-level cursor cache mechanism that caches frequently executed static SQL in PL using an LRU strategy, reducing repeated parsing and context loading overhead and improving execution performance.

- Shared CTE optimization: optimized shared CTE execution in views and DBLink scenarios, allowing CTEs defined in views and CTEs containing DBLinks to use the shared reuse mechanism and achieve performance aligned with direct CTE execution.

- UDF execution optimization: when PL code contains loops (FOR/WHILE/LOOP) and functions are called within them, function preparation results are cached during the first execution and directly reused in subsequent iterations, significantly improving performance.

- INSERT … ON DUPLICATE KEY UPDATE optimization: supports pre-checking conflicting rows through primary key indexes, quickly separating data into INSERT rows and UPDATE rows, avoiding rollback overhead caused by failed INSERT operations due to conflicts. Batch insertion of INSERT rows reduces the overhead of repeatedly searching for free space.
