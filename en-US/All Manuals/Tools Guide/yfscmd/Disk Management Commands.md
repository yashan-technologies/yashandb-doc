*yfscmd* manages data disks through the `exec` subcommand, and YFS defines disk management statements in a DDL format similar to SQL.

>**Note**:
>
> After the YAC/Distributed Cluster deployment is completed, configurations related to the system disk group (systemdg) cannot be modified. Please adjust the relevant settings in the [group.systemdiskgroup] section of the {cluster_name}.toml file during installation as needed.

In interactive mode of *yfscmd*, please execute `exec create diskgroup …;`. In interactive mode, the `exec` subcommand supports multi-line input until a `;` is encountered to end.

In non-interactive mode of *yfscmd*, disk management statements must be surrounded by quotes and passed as a single independent parameter, please execute `yfscmd exec "create diskgroup …"`, and the `;` at the end of the disk management statement is optional in non-interactive mode.

## CREATE DISKGROUP

This statement is used to create a new disk group.

>**Note**:
>
> If YAC is configured with [SCSI Persistent Reservations for IO Fencing](../../Database Administration/Cluster Management/IO Fencing/SCSI IO Fencing), please call the [fenceScsiCheck script](../../Database Administration/Cluster Management/IO Fencing/SCSI IO Fencing.html#fenceScsiCheck_usage) to perform capability checks on the disk specified by diskpath before executing `create diskgroup`, otherwise this operation may fail due to reasons such as unsupported hardware protocols.

**CREATE DISKGROUP::=**

```ebnf+diagram
CREATE_DISKGROUP::= CREATE DISKGROUP dgname [(EXTERNAL|NORMAL|HIGH) REDUNDANCY] (fg_clause) {" " (fg_clause)} [attribute_clause]
```

**fg_clause::=**

```ebnf+diagram
FG_CLAUSE::= [[REGULAR|QUORUM] FAILGROUP fgname] DISK (disk_clause) {"," (disk_clause)}
```

**disk_clause::=**

```ebnf+diagram
DISK_CLAUSE::= "'" diskpath "'" [NAME diskname] [SIZE size] [FORCE|NOFORCE]
```

**attribute_clause::=**

```ebnf+diagram
ATTRIBUTE_CLAUSE::= ATTRIBUTE "'"au_size"'" "=" ("'1M'" | "'4M'" | "'8M'" | "'16M'" | "'32M'")
```

### dgname

The name of the disk group to be created, which must be globally unique in YFS, cannot be omitted, and must comply with YashanDB's [object naming conventions](../../Development Guide/SQL Reference Manual/Basic SQL Elements/Identifiers).

### REDUNDANCY

Specifies the redundancy of the disk group, with optional values EXTERNAL, NORMAL, or HIGH, defaulting to NORMAL.

### fg\_clause

This statement is used to create failure groups, and this statement can be specified multiple times, separated by spaces, indicating the creation of multiple failure groups.

The number of failure groups that can be created is related to the disk group redundancy; the number of failure groups must be greater than or equal to the number of replicas, otherwise an error will be returned.

`QUORUM` and `REGULAR` are used only for syntax compatibility and have no actual meaning.

#### FAILGROUP fgname

The name of the created failure group, which must be unique within the disk group, must comply with YashanDB's [object naming conventions](../../Development Guide/SQL Reference Manual/Basic SQL Elements/Identifiers), and cannot be omitted in the fg_def_clause.

If it is omitted, the names of the FailureGroups will be automatically generated by the system based on the disk group name and the sequential number of the FailureGroups (starting from 0). For example, if the disk group name is DG1, the automatically generated FailureGroup names will be DG1_0 and DG1_1.

#### disk\_clause

This statement is used to specify the quantity and attributes of disks under the failure group, with multiple disks separated by `,`.

The number of disks under all failure groups within a disk group must be consistent, otherwise an error will be returned.

A disk can only belong to one failure group and one disk group and cannot be specified repeatedly.

##### diskpath

Specifies the YFS path where the disk is located, and the maximum length of the path supported by this statement is 31.

>**Caution**:
>
> Please ensure that primary/standby node disk paths are consistent and have read/write privileges, otherwise this may cause the standby process to exit.

##### diskname

Assigns a unique name within the disk group to the disk, and the naming must comply with YashanDB's [object naming conventions](../../Development Guide/SQL Reference Manual/Basic SQL Elements/Identifiers). If the disk name is omitted, the system will automatically generate a default name.

##### size

Specifies the size of the disk that the disk group can manage; it is optional and defaults to the total size of the disk.

This statement must specify the size for all disks under all failure groups within a disk group simultaneously, and the size value must remain consistent, otherwise an error will be returned.

If the specified size is greater than the total size of the disk, an error will be returned.

**FORCE|NOFORCE**

`FORCE` is used to force format the disk. For example, when YFS detects that a YFS file system exists on the disk, it will refuse to add the disk by default to avoid accidentally wiping out data on the disk, and can be forced by using `FORCE`.

`NOFORCE` is used only for syntax compatibility and has no actual meaning.

### attribute\_clause

This statement is used to specify the AU size of the disk space allocated by YFS when creating the disk group; it is optional and defaults to an AU size of 1M.

When specifying AU size, optional values are 1M, 4M, 8M, 16M, or 32M.

***Example*** for YAC Deployment

```sql
CREATE DISKGROUP DG2 NORMAL REDUNDANCY 
DISK '/dev/DISK_NAME5' SIZE 700M 
FAILGROUP FG_1 DISK '/dev/DISK_NAME10' NAME disk4 SIZE 700M 
FAILGROUP FG_2 DISK '/dev/DISK_NAME4' SIZE 700M 
ATTRIBUTE 'au_size'='4M';

DROP DISKGROUP DG2;

CREATE DISKGROUP DG2 NORMAL REDUNDANCY 
FAILGROUP FG_1 DISK '/dev/DISK_NAME10' NAME disk4,'/dev/DISK_NAME12' 
FAILGROUP FG_2 DISK '/dev/DISK_NAME4','/dev/DISK_NAME11';
```

## ALTER DISKGROUP

This statement is used to modify the properties of an existing disk group, including unmounting, mounting the disk group, adding disks, deleting disks, renaming disks, etc.

**alter diskgroup::=**

```ebnf+diagram
ALTER_DISKGROUP::= ALTER DISKGROUP dgname (DISMOUNT [FORCE] | MOUNT | ADD (fg_clause) {" " (fg_clause)} | DROP drop_disk_clause | RENAME rename_disk_clause | OFFLINE offline_disk_clause)
```

>**Note**:
>
> If YAC is configured with [SCSI Persistent Reservations for IO Fencing](../../Database Administration/Cluster Management/IO Fencing/SCSI IO Fencing), please call the [fenceScsiCheck script](../../Database Administration/Cluster Management/IO Fencing/SCSI IO Fencing.html#fenceScsiCheck_usage) for capability checking the disks specified by diskpath before executing ADD, otherwise this operation may fail due to unsupported hardware protocols.

### dgname

Specifies the name of an existing disk group.

### DISMOUNT|MOUNT

This statement is used to perform mount or unmount operations on the disk group.

>**Caution**:
>
> During the mount operation, please ensure that the disk names are consistent and possess read/write privileges between primary/standby nodes; otherwise, the standby process may exit during the mount.

### FORCE

If files in the disk group are already open and not yet closed, the disk group cannot be DISMOUNTED; `FORCE` must be explicitly specified to force execution.

>**Caution**:
>
> Forcefully DISMOUNTING a disk group may cause database anomalies and data loss, **please exercise caution with this operation**.

### ADD fg\_clause

This statement is used to add disks to the failure group within the disk group.

- If the specified failure group name already exists, disks are added to the existing failure group.

- If the specified failure group name does not exist, or no failure group name is specified, a new failure group is created, and disks are added to it.

Other details are consistent with those described in CREATE DISKGROUP.

### drop\_disk\_clause

This statement is used to delete one or more disks from the disk group. It can also delete one or more failure groups from the disk group.

>**Caution**:
>
> - **Only empty disks are allowed to be deleted**; disks containing YFS metadata, such as BOOT_DISK, cannot be deleted.
> - After deleting disks, the remaining number of failure groups must meet the disk group redundancy requirements, and the number of disks in each remaining failure group must be consistent.
> - Deleted disks will immediately break the relationship with their partner disks, which may cause some disks to lack available partner disks for creating data copies, failing to meet the redundancy requirements; the space from that disk will be unavailable. At this time, sufficient disks can be added to the disk group (the relationship of the disks can be queried through the [V\$YFS_DISK](../../Reference Manual/System Views/Dynamic Performance Views/V$YFS_DISK) view), and the system will automatically assign new partner disks for that type of disk after adding new disks.

```ebnf+diagram
drop_disk_clause::= ([REGULAR|QUORUM] DISK (disk_name [FORCE|NOFORCE]) {"," (disk_name [FORCE|NOFORCE])})|(DISKS IN [REGULAR|QUORUM] FAILGROUP (failuregroup_name [FORCE|NOFORCE]) {"," (failuregroup_name [FORCE|NOFORCE])})
```

`QUORUM`, `REGULAR`, `FORCE`, and `NOFORCE` are used only for syntax compatibility and have no actual meaning.

### rename\_disk\_clause

This statement is used to rename disks within the disk group, allowing multiple disks to be renamed (by manually specifying new names) or automatically renaming all disks in the disk group (where names are specified by the system in the format `DGNAME_DISKID`).

The disk naming specifications are as follows:

- The disk name can be up to 31 characters long.
- The new disk name must be unique within the disk group.

```ebnf+diagram
rename_disk_clause::= (DISKS ALL) | (DISK (old_disk_name TO new_disk_name) {"," (old_disk_name TO new_disk_name)})
```

### offline\_disk\_clause

This statement is used to take one or more disks within the disk group offline. It may also take one or more failure groups within the disk group offline.

>**Caution**:
>
> - After taking disks offline, the remaining number of failure groups must meet the disk group redundancy requirements.
> - Disk offline operations should be carried out with caution - this action is currently irreversible (i.e., the disk cannot be brought back online). After taking the disk offline, the redundancy of existing files in the disk group may be degraded.


```ebnf+diagram
offline_disk_clause::= ([REGULAR|QUORUM] DISK (disk_name) {"," (disk_name)})|(DISKS IN [REGULAR|QUORUM] FAILGROUP (failuregroup_name) {"," (failuregroup_name)})
```

`QUORUM` and `REGULAR` are used only for syntax compatibility and have no actual meaning.

***Example*** for YAC Deployment

```sql
-- Unmount disk group
ALTER DISKGROUP DG2 DISMOUNT;
-- Mount disk group
ALTER DISKGROUP DG2 MOUNT;
-- Add disks
ALTER DISKGROUP DG2 ADD FAILGROUP FG_3 DISK '/dev/DISK_NAME13' NAME DISK13,'/dev/DISK_NAME14' NAME DISK14 FAILGROUP FG_4 DISK '/dev/DISK_NAME15' NAME DISK15,'/dev/DISK_NAME16' NAME DISK16;
-- Delete all disks from failure group
ALTER DISKGROUP DG2 DROP DISKS IN  FG_3, FG_4;
-- Delete specified disks
ALTER DISKGROUP DG2 DROP DISK DISK13, DISK14;
-- Rename specified disks
ALTER DISKGROUP DG2 RENAME DISK DISK13 TO DISK13NEW, DISK14 TO DISK14NEW;
ALTER DISKGROUP DG2 RENAME DISKS ALL;
-- Take disks offline
ALTER DISKGROUP DG2 OFFLINE DISK DISK13, DISK14;
ALTER DISKGROUP DG2 OFFLINE DISKS IN FAILGROUP FG_3, FG_4;
```

## DROP DISKGROUP

This statement is used to delete a disk group.

The disk group to be deleted must be in the MOUNT state; otherwise, the deletion will fail, and the state of the disk group can be changed using the ALTER DISKGROUP statement.

**drop diskgroup::=**

```ebnf+diagram
DROP_DISKGROUP::= DROP DISKGROUP dgname [INCLUDING CONTENTS] [FORCE]
```

### dgname

Specifies the name of an existing DG.

### INCLUDING CONTENTS

If there are files or directories in the disk group, `INCLUDING CONTENTS` must be explicitly specified to force deletion, otherwise, the deletion will fail.

### FORCE

If files in the disk group are open but not closed, the disk group cannot be dropped; `FORCE` must be explicitly specified to force execution. Note that forcefully dropping a disk group may cause database anomalies; please exercise caution with this operation.

***Example*** for YAC Deployment

```sql
DROP DISKGROUP DG2;

DROP DISKGROUP DG2 INCLUDING CONTENTS;
```
