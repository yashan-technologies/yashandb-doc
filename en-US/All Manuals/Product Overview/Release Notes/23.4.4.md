## Version Positioning

YashanDB v23.4.4 enriches the new features and continues to optimize performance based on v23.4.3, serving as a version available for long-term service support.

## Version Information

**Version Number**: v23.4.4.100

**Release Date**: September 30, 2025

## New Functionality

YashanDB v23.4.4 inherits all functionalities released in YashanDB v23.4.3 and adds the following key features:

### SQL Engine Enhancements

#### SQL Functionality Enhancements

- XML Capability Enhancement

    - Added XML Built-in Functions

        - Supports EXTRACTVALUE built-in function, which can locate nodes in XML documents based on a specified XPath expression and return the value of that node, used for extracting text information from XML data.

        - Supports EXISTSNODE built-in function, which searches for nodes in XML documents based on the provided XPath expression. Returns 1 if matching nodes are found, and 0 if not found. Used to determine whether XML data contains specific information.
        - Supports XMLSEQUENCE built-in function, which takes an XMLType instance as input and returns a variable array of top-level nodes in that XMLType.
        - Supports XMLEXTRACT built-in function, which locates specific content (such as elements, attributes, text values, etc.) in XML documents through XPath expressions, and returns the corresponding XMLType instance or string result, achieving precise parsing of XML data.
        - XMLTABLE function supports FOR ORDINALITY clause, specifying this column as the generated row number column. There can be at most one FOR ORDINALITY clause.

    - Supports xmltype constructor and corresponding member methods

        - Supports xmltype constructor, converting strings in XML format (VARCHAR or CLOB type) into XMLType objects, achieving typed processing of XML data.
        
        - Supports extract member function, using XMLType instances and XPath, applying XPath expressions and returning results in XMLType form. The function extracts XMLType fragments and returns XMLType instances containing result nodes.
        - Supports getClobVal member function, returning the value of XMLType instances in CLOB form.
        - Supports getStringVal member function, returning the value of XMLType instances in string form.
        - Supports createXML member function, a static function used to create and return XMLType instances.
        - Supports existsNode member function, used to check whether nodes exist.

    - Adds DBMS_XMLDOM system package, providing over 10 procedures and functions for the main processes of handling XML data, used to access XMLType objects, create, manipulate, and parse node structures of XML documents in PL, implementing Document Object Model (DOM).

    - Adds DBMS_XMLPARSER system package, providing newParser, getDocument, parseBuffer, freeParser, and parseClob procedures and functions, used to parse and process XML documents, parsing XML-formatted text (strings or large objects) into structured XML document objects for querying, modification, validation, and other operations.

- PL Capability Enhancements

    - Supports UTL_HTTP advanced package and corresponding functions: Adds support for UTL_HTTP system package, supporting stored procedures and functions for major processes related to sending and receiving HTTP requests in PL, breaking through the closed nature of databases, allowing PL programs to directly call external HTTP resources or provide HTTP service responses, achieving HTTP communication between databases and external systems.

    - Supports PROCEDURE, FUNCTION, PACKAGE object-level permissions: Adds EXECUTE object permissions for PROCEDURE, FUNCTION, and PACKAGE procedure bodies, implementing execution permission management for PL, enhancing security capabilities, and also increasing Oracle compatibility.
    - DBMS_STATS system package supports no_invalidate parameter: Through the addition of the no_invalidate parameter, used to control whether execution plans of objects dependent on currently collected statistics are invalidated during the statistics collection process. The default is FALSE, representing that all existing plans dependent on these statistics will be invalidated. TRUE and AUTO are syntax-compatible in this version.
    - Adds syntax branch range for triggers. UPDATE trigger events support placing the OF column clause after DELETE and INSERT, improving Oracle compatibility.
    - In PL functionality, adds support for cursor null checking in IF judgment clauses, including IS NULL or IS NOT NULL, improving Oracle compatibility.
    - In PL functionality, adds support for collection (nested table) null checking in IF judgment clauses, including support for empty checking IS EMPTY or IS NOT EMPTY, improving Oracle compatibility.

- Other Features

    - Supports json_table function, parsing JSON-formatted strings or documents into relational data of rows and columns, and outputting JSON values in the object as separate SQL column values, enabling querying, filtering, and joining operations using traditional SQL statements.

    - Supports chartorowid function: Converts text of string type (CHAR or VARCHAR type) to ROWID type, enabling conversion of recorded or stored strings to ROWID for problem locating.
    - Supports current_date function, used to return the current date in the session time zone, with its value being the Gregorian calendar value of DATE data type.
    - Supports reverse function to reverse strings: In query statements, implements reversal arrangement of a string of characters through the reverse keyword, simplifying implementation in specific scenarios and improving Oracle compatibility.
    - In timestamp definition and conversion scenarios, adds support for XFF keyword to display the fractional seconds part of time, increasing usage flexibility and improving Oracle compatibility.
    - To enrich business usage scenarios, this version adds wm_concat and listagg function input parameter support for nvarchar/NCHAR/NCLOB types, which can be used to solve multi-language Unicode character aggregation needs, avoiding conversion errors and garbled characters, ensuring the correctness of character concatenation.
    - Supports external references in ORDER BY subqueries: In ORDER BY clauses, projection column positions, column names, column aliases, simple subqueries, etc. are already supported. This version adds subquery support with external references, improving compatibility.
    - Adds support for pivot syntax functionality in CTE, used to simplify row-column transformations in complex scenarios and improve flexibility.
    - This version enhances the MAX_SESSIONS maximum limit specification, supporting expansion from 16384 to 50000, allowing more concurrent users or applications to connect to the database simultaneously to adapt to high-concurrency access scenarios.
    - This version supports creating materialized views through DBLink remote tables, achieving synchronization of remote data to local. It expands the means of synchronizing source data to local and improves flexibility. Meanwhile, through the addition of the DBLINK_CURSOR_COUNT parameter, it improves the specification for the number of tables that DBLink can open simultaneously, with a maximum limit of 16384.


#### SQL Performance Enhancements

- Parallel Capability Enhancements

    - Batch architecture capability continues to enhance, set operators including UNION/UNION ALL operators, MINUS/MINUS ALL/INTERSECT/INTERSECT ALL operators support batch and parallel execution.

    - Temporary tables support batch and parallel execution when performing join, delete, insert, and other operations.
    - When COUNT execution operators are needed during execution, such as count operators generated in commonly used rownum < n scenarios, support for batch parallel execution is provided.
    - In UPDATE/MERGE scenarios with complex queries and large data volumes, the optimizer supports choosing batch and parallel execution plans to improve DML performance.
    - When using HASH DISTINCT operators in duplicate result elimination scenarios, support for batch parallel execution is provided to speed up deduplication efficiency.
    - In version v23.4.1, YashanDB already supported CTE subquery materialization sharing, reducing CTE execution times. This version implements shared CTE support for batching and parallelization, further improving CTE computing performance.


- Optimizer Enhancements

    - Filter pushdown specification supports subqueries, etc.: In scenarios with subqueries with external references, correlated subqueries, subqueries with rownum and other conditions, Filter pushdown is supported to reduce subsequent processing data volume and improve overall SQL execution efficiency.

    - Scalar subquery to Join: In SQL scenarios where scalar subqueries exist in projections or filters, the optimizer supports rewriting as join correlation methods, reducing subquery execution times, effectively utilizing indexes, and improving efficiency.
    - Supports constant parameterization to implement shared execution plans: Before version v23.4.4, when using string concatenation to generate various different SQLs, the optimizer treated each as a new SQL statement, generating a large number of hard parses, affecting execution efficiency. This version implements parsing similar constant SQLs into the same variable SQL through the addition of the CURSOR_SHARING parameter, reducing hard parsing, saving memory resources, and improving performance.
    - When SQL needs to perform MIN/MAX calculations, and in conditional scenarios, adds support for index RANGE SCAN, which can effectively reduce data scanning and improve execution efficiency.

- PL Performance Improvement

    - This version improves the access performance of VARRAY/TABLE variables, enhancing the performance of reading, participating in expression calculations, and assignment actions of VARRAY/TABLE variables in loops.

    - UDF deterministic performance optimization: Through optimization of deterministic attribute UDFs, caching of output results for identical input parameters is implemented, reusing cached results during identical SQL execution without repeatedly executing UDFs, thereby improving execution efficiency.
    - When simple UDF internal composition consists of only one SQL statement, the optimizer can directly inline it, converting it to a subquery in the external SQL statement, participating in the generation of the overall SQL statement optimization plan to achieve optimization effects.
    - Performance improvement for Insert scenarios with forall and udt variables, such as supporting batch insertion capabilities: In scenarios with forall plus insert with udt variables, bulk collect into, performance improvement is achieved through supporting batch insertion capabilities.
    - When UDFs exist in SQL, supports parallel execution of SQL itself, which can significantly improve efficiency when complex UDF SQL processes large-scale data.

### Storage Engine Enhancements

- Storage Function Enhancement

    - Through the addition of [exchange_partition_clause](../../开发手册/SQL参考手册/SQL语句/ALTER TABLE.html#exchangeclause) clause, implements the capability for online conversion between ordinary tables and partitioned tables, enabling rapid data migration between the two table structures with minimal impact on business continuity. Can be used for scenarios such as rapid creation of partitioned tables and efficient extraction of historical data.

    - RAW data type supports index creation: RAW type is commonly used to store unique identifier binary data (such as binary form of UUID, hardware device unique codes, etc.), usually requiring precise queries. Supporting index creation can accelerate such precise matching performance.

- Storage Performance Enhancement

    - Before version v23.4.4, undo blocks could only be used by one transaction. In scenarios with many small transactions, undo block contention was significant. This version optimizes undo blocks by supporting cross-transaction usage, effectively reducing undo block allocation contention and consumption, improving transaction performance.

    - This version optimizes the data buffer elimination strategy for bulk insert temporary table scenarios by adjusting temporary table eviction logic to directly eliminate upon reaching the proportion, enabling significantly fewer buffer swaps when executing temporary tables with large DATA_BUFFER, improving bulk insert performance for temporary tables.

### YAC Capability

- High Availability

    - YAC Deployment supports SCAN: Before version v23.4.4, if node scaling was required in business, due to changes in cluster instances, application connections needed to synchronously adapt to perceive cluster node changes, resulting in significantly reduced system usability and stability. Therefore, version v23.4.4 cluster supports SCAN capability. Applications access the database through SCAN domain names. When database instances scale, applications do not need to modify connection strings or perceive cluster node changes. The SCAN service automatically migrates sessions and achieves load balancing, improving business system stability and usability.

    - YAC Deployment supports flashback database: Based on flashback log snapshot point (Marker) technology, through FLASHBACK DATABASE syntax clauses, implements full-database second-level rollback to any point in time. Mainly used for system upgrade/migration rollback, security incident response, test environment reset, data auditing and analysis, data cleaning rollback, logical error repair, and other fault scenarios.

- YFS Usability

    Before version v23.4.4, querying DG-related information through views was already supported. However, in actual business operations, if situations such as disk full or database instance startup failure occur, it may not be possible to query YFS disk information through views. Based on this, version v23.4.4 provides querying YFS disk-related information through yfscmd commands, such as DG usage, IO, and other information, improving the usability of YFS disk information querying and positioning.

### Usability

- YashanDB requires temporary backup during upgrades. Before version v23.4.4, whether backup space was sufficient depended on manual confirmation, and there was a risk of disk filling during the upgrade process. v23.4.4 adds backup space checking, enabling risk prediction in advance during upgrades and improving usability.

- This version optimizes *yasboot* for operations scenarios involving node damage or failure offline. By adding *yasboot* support for forced removal of faulty nodes and incorporating manually added/deleted nodes into management, it achieves rapid recovery of *yasboot* tool availability issues when nodes are damaged or go offline, making operations more convenient for administrators and improving usability.

### Driver

- Adds .NET driver support for YashanDB SQLSugar framework, supporting transactions and DML and other major functional processes, which can simplify developers' development processes for YashanDB, simplify database interaction code, and improve development efficiency.

- Python driver enhancements

    - Through supporting batch binding parameter functionality, performance improvement of over 10 times in simple insert and read scenarios.

    - Through supporting connection pool creation, connection acquisition, and connection return capabilities, along with connection pool parameter management, implements caching and reuse of database connections, avoiding performance loss from frequent connection creation and closure. Can reduce connection overhead, improve performance, control concurrent connection numbers, and reduce database connection storms.

- Go driver enhancements

    - Adds NumInput interface, returning the number of current SQL placeholder parameters.

    - Stmt.Close interface supports asynchronous operation, effectively improving closing performance.
    - Adds direct insert mode interface, effectively improving insert performance.
