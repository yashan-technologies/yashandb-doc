## Version Positioning

YashanDB v23.4.6 enriches the new features and continues to optimize performance based on v23.4.4, serving as a version available for long-term service support.

## Version Information

**Version Number**: v23.4.6.100

**Release Date**: December 15, 2025

## New Functionality

YashanDB v23.4.6 inherits all functionalities released in YashanDB v23.4.4 and adds the following key features:

### SQL Engine Enhancements

#### SQL Functionality Enhancements

- Functionality Enhancement

    - Newly added VALUE built-in function: Primarily used for operations on object-relational data (similar to nested tables). It takes an associated variable (table alias) linked to a row in an object table as a parameter and returns an object instance stored in that object table. The type of the returned object instance matches the type of the object table. The VALUE function provides a convenient way to access object attributes and invoke object methods, serving as a key interface for operating on custom object-type data.

    - Newly added TO_BLOB built-in function: Converts BFILE or RAW type data into BLOB data, enabling compatibility between different binary data types and meeting requirements for binary data storage, manipulation, and transmission.

- PL Capability Enhancements

    - Support for UDF indexes: This version introduces support for creating indexes based on UDFs. The computed results of the UDF applied to columns are pre-stored in the index, accelerating queries that depend on these function calculations. This not only inherits the advantages of function indexes but also enables efficient querying of complex business rules. It simplifies SQL writing during code development by eliminating the need to repeatedly write complex computational logic in queries.

    - Support for advanced package debugging features: Prior to version v23.4.6, debugging support was limited to stored procedures. This version extends debugging capabilities to support advanced package subprograms. By invoking JDBC debugger interfaces, developers can now add breakpoints, display global variables, and trace the execution flow of code within packages, monitor variable states, and pinpoint the root causes of exceptions. This ensures the correctness, logical integrity, and performance efficiency of advanced packages, significantly improving code development efficiency.

    - Simplified declaration/definition of advanced package subprograms: Prior to v23.4.6, YashanDB required subprogram declarations/definitions (functions/procedures) to be declared/defined in the package header before the package body could initialize or implement them. In this version, subprograms can now be directly declared/defined in the package body, eliminating the need for header declarations. This enhances code flexibility, improves usability, and strengthens compatibility with Oracle.

    - Support for the DBMS_XSLPROCESSOR advanced package: This version introduces the DBMS_XSLPROCESSOR advanced package along with XML node operation functions (valueof, selectsinglenode, selectnodes), meeting enterprise-level requirements for XML data parsing and transformation.

- GIS Capability Enhancement

    - Support for direct query and insertion of geometry data: Prior to version v23.4.6, YashanDB required GIS functions to convert geometry data before querying or inserting. This version enables direct geometry data operations — that is, during queries, users can use SELECT * or return specific fields in EWKB format; during inserts, EWKB and WKT format data can be directly inserted into geometry fields, improving usability.

    - Newly added ST_Translate function: Used to translate spatial objects by moving a specified spatial geometry (e.g., point, line, polygon, multipolygon) a specified distance along the X, Y (and Z axis for 3D objects) directions, while preserving the object's shape, size, and orientation — only its spatial position changes.

    - Newly added ST_Scale function: Used to scale spatial objects by enlarging or reducing spatial geometry (points, lines, polygons, etc.) according to a specified scale factor, altering the object's size while preserving its shape and relative proportions (unless non-uniform scaling is applied).

    - Newly added ST_XMin, ST_XMax, ST_YMin, ST_YMax, ST_ZMin, ST_ZMax functions: Functions to retrieve the extreme boundary values of spatial objects, primarily targeting 2D or 3D spatial data, extracting the minimum and maximum values along the X, Y, and Z axes to quickly determine the spatial object's position range and boundaries.

    - Newly added ST_DUMPPOINTS function: Used to extract all vertices from spatial objects, breaking down complex spatial geometries (e.g., lines, polygons, point collections) into their constituent raw vertices and returning the coordinates of these points in a structured format, facilitating independent analysis or processing of spatial object vertices.

#### SQL Performance Enhancements

- Optimizer support for removing redundant grouping/deduplication operations: When the database needs to perform grouping or deduplication operations and the target data contains no duplicates, the optimizer can eliminate the corresponding grouping/deduplication operations from the execution plan. For example, in `SQL SELECT c1 FROM (SELECT c1 FROM t1 UNION SELECT c1 FROM t1) GROUP BY c1;`, only one `UNION` operation is needed, and the outer `GROUP BY` operation can be removed — reducing operation count and improving computational efficiency.   

- Support for automatic index usage in flashback queries: If applicable indexes exist, the database automatically uses those indexes for flashback queries, improving query efficiency. 

- Optimizer now performs partition pruning before cost model evaluation: In scenarios where data distribution across multiple partitions is uneven and the SQL query includes clearly defined partition conditions, the optimizer can first perform partition pruning before evaluating the cost model. This reduces metadata scanning, simplifies cost calculation complexity, and avoids generating invalid execution plans — thereby improving query execution efficiency.

### YAC Capability

- *yasboot* supports [rolling upgrade](../../安装和升级/升级/升级操作/滚动升级) in Primary/Standby YAC Deployment:

    In version v23.4.4, the YAC kernel already supported rolling upgrades, but due to the lack of yasboot tool compatibility, the operation was relatively complex and less user-friendly. The rolling upgrade process included: 1. Switching the standby cluster to a logical standby cluster; 2. Upgrading the logical standby cluster; 3. Performing a primary/standby switch to convert the original master cluster into a physical standby cluster; 4. Optionally, revert the primary/standby relationship if needed. 
    
    In version v23.4.6, yasboot now supports one-click rolling upgrades for Primary/Standby YAC Deployment, automatically completing the entire workflow — significantly reducing maintenance time and improving usability. Rolling upgrades are supported from version v23.4.4.0 and above to all newer versions.

### Usability

- Support for importing/exporting XMLTYPE data: Prior to version v23.4.6, YashanDB already supported the XMLTYPE data type and related computations. To enhance functional completeness, this version adds support for the imp/exp tool to import and export XMLTYPE data, including exporting XML data, exporting to CSV, and importing. This enables capabilities for backing up, migrating, integrating, and archiving XML data, flexibly meeting various transmission requirements for XMLTYPE data across different scenarios, and supporting efficient operation and compliance management of business systems.

- Backup item selection and backup path customization during database upgrades: Prior to v23.4.6, YashanDB always performed a full backup during upgrades, which posed a risk of disk full in scenarios with limited disk space. This version introduces the ability to selectively choose backup items and customize backup paths during upgrades, allowing adaptation to actual environmental configurations and supporting a broader range of disk setup scenarios — thereby enhancing flexibility.

- Support for enabling/disabling listener without stopping the database: By introducing the new syntax ALTER SYSTEM LISTENER START/STOP, the listener's functionality can be controlled. START indicates normal operation mode, accepting all connections; STOP indicates maintenance mode, preserving existing connections while blocking new ones — but still allowing UDS local connections initiated by the sys user. This enables flexible management of client connection access without interrupting database service, balancing operational needs with business continuity.

### Driver

- JDBC driver enhancements

    - JDBC now supports for standard escape syntax: Enabling SQL statements to be written in a database-agnostic manner. Escaped code fragments can run normally in YashanDB. This version supports date escape {d 'yyyy-mm-dd'}, time escape {t 'hh:mm:ss'}, and timestamp escape {ts 'yyyy-mm-dd hh:mm:ss[.f...]'}é, expanding usage scenarios and improving usability.

    - JDBC now supports XMLTYPE data type: Providing a standardized interface to enable Java applications to interact with XML data in the database (read, write, parse, modify).

###  MySQL Compatibility

- Newly added support for BIT_AND(), BIT_OR(), and BIT_XOR() functions: These functions perform bitwise AND, OR, and XOR operations on values within a group, returning the aggregated result.

- Newly added support for the INTERVAL function: This function compares a numeric value against an ordered set of values and returns the "position index" of the first value in the set that is greater than the given value — effectively indicating its relative position.

- Newly added support for the ONLY_FULL_GROUP_BY SQL mode, improving MySQL compatibility.
  
    - When enabled, it enforces that all projection columns in the query result must either be grouping columns from the GROUP BY clause or columns that have been processed by aggregate functions (e.g., SUM(), AVG(), MAX(), etc.).
    
    - When disabled, projection columns may include non-grouping columns.

###  Security

- Prior to version v23.4.6, clients using the C driver could only establish SSL connections to a single server. In this version, the C driver now supports configuration at the local environment variable level, enabling simultaneous connection to multiple servers — each with its own distinct SSL configuration — thereby achieving one-to-many secure connections and improving flexibility.

- Prior to version v23.4.6, SSL connections required configuring the ssl_cert_file parameter to validate the server's root certificate, which imposed high operational overhead and limited flexibility in low-security-demand scenarios. This version optimizes the ssl_cert_file policy: by default, SSL connections no longer require the ssl_cert_file parameter, indicating that server-side CA root certificate verification is disabled. This eliminates the complexity of certificate updates and replacements, enriches usage scenarios, and satisfies diverse security requirement levels with multiple configurable options.

- Newly added system and object privileges: 

    - CREATE JOB: Grants permission to create scheduled jobs within the user's own schema (i.e., to invoke DBMS_SCHEDULER.CREATE_JOB or DBMS_JOB.SUBMIT).

    - MANAGE SCHEDULER: Syntax-compatible only, no actual functionality.

    - LOCK ANY TABLE: Grants permission to lock any table in the database (excluding sys schema tables).

    - SELECT ANY DICTIONARY: Grants permission to query/access any object within the sys schema.

    - DEBUG ANY PROCEDURE: Grants permission to debug any procedure or function (excluding sys schema objects).

    - DEBUG CONNECT SESSION: Syntax-compatible only, no actual functionality.

    - SELECT ON SEQUENCE: Grants permission to query sequences.
