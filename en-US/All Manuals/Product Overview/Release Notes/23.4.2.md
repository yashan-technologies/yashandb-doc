## Version Positioning

YashanDB v23.4.2 enriches the new features and continues to optimize performance based on v23.4.1, serving as a version available for long-term service support.

## Version Information

**Version Number**: v23.4.2.100

**Release Date**: July 18, 2025

## New Functionality

YashanDB v23.4.2 inherits all functionalities released in YashanDB v23.4.1 and adds the following key features:

### SQL Engine Enhancements

#### SQL Functionality Enhancements

- Functionality enhancements

    - XML functions 

        - Supports xmlagg function: Used to aggregate multiple rows of data into a single XML document, making it very useful in scenarios where multiple records need to be combined into a single XML structure.

        - Supports xmlparse function: Used to parse text strings into XML data types and allows the specification of the wellformed keyword to skip format checks on the input XML.

        - Supports xmltable function: Used to parse XML data into relational data, extracting data from XML documents and converting it into rows and columns for easier use in SQL queries.

        - Supports getclobval function: Used to convert XMLType data into CLOB type.

    - String functions 

        - Supports asciistr function: Used to convert strings containing non-ASCII characters to ASCII characters.

        - Supports convert function: Converts strings from one character set to another.

        - Supports nls_lower function: Converts strings to lowercase based on character set-specific conversion rules.

        - Supports to_clob function: Used to convert other data types to large object types, suitable for storing long texts, JSON data, etc.

        - Supports to_single_byte function: Converts multi-byte characters (e.g., full-width characters) in a string to equivalent single-byte characters (e.g., half-width characters). This is useful in handling character sets like Chinese, Japanese, and Korean and is significant in scenarios requiring compatibility with single-byte character sets.

        - Supports to_multi_byte function: Converts single-byte characters (e.g., half-width characters) in a string to equivalent multi-byte characters (e.g., full-width characters). This is the opposite of the to_single_byte function.

        - chr function supports returning multi-byte characters: In previous versions, YashanDB's chr function only supported characters corresponding to ASCII, i.e., decimal 0-127. This version adds support for multi-byte characters, where valid characters corresponding to equivalent binary values can be returned normally.

        - Supports N'String' functionality, which is a special syntax representing national character set string constants, used for handling Unicode data and string operations in multilingual environments.

        - replace function supports CLOB type: The replace function replaces all occurrences of a source string in the source string expr with a target string, returning a new string of type VARCHAR. In version v23.4.1, it failed to handle cases where the source string expr exceeded 32000 bytes. To expand the usage scenarios, this version supports processing of CLOB/NCLOB data, enabling larger processing sizes.

        - trim function trims leading or trailing characters (or both) from a string and adds support for handling full-width characters.

    - Time functions 

        - Supports at time zone function: Used for handling expressions involving timezone conversions, capable of converting SCN values from one timezone to another.

        - Supports from_tz function: Used to handle timezone conversion, combining a normal SCN (TIMESTAMP) with specified timezone information to create a timezone-aware SCN (TIMESTAMP WITH TIME ZONE).

        - Supports to_timestamp_tz function: Used to convert strings to TIMESTAMP WITH TIME ZONE data types.

        - Supports tz_offset function: Used to obtain the function for the offset between a specified timezone and UTC (Coordinated Universal Time).
    
    - Other functions 
        
        - Supports rawtohex function: Converts RAW type data into a hexadecimal string representation, turning unreadable binary data into a readable hexadecimal format for easier debugging and analysis.
        
        - Supports ratio_to_report function: This analytical function computes the ratio of a certain value relative to the sum of all values within a group, allowing an intuitive understanding of data distribution characteristics by calculating the proportion of each value within the group.
    
        - Supports unpivot function: Used to merge multiple column data into two columns, one for storing the original column names and the other for storing the values from the original columns.

        - Supports nested aggregate functions: Allows the expression of another aggregate function to be included within one aggregate function, providing flexible means for multi-level aggregation calculations in SQL queries for complex data analysis.

        - Supports dump function: Used to return detailed storage information about data values, including data type codes, length (in bytes), and the internal representation of expr. The returned results are always in database character set.

        - to_char/to_number functions support FM modifier: Adds "Fill Mode" (FM) to control space and zero padding in formatted output within the format.
    
        - Supports ora_hash function: Generates hashes of data, commonly used for data partitioning, sampling, and fast data comparisons.

- Syntax functionality enhancements

    - Supports BFILE data type: Used to store references to files external to the database, with the files themselves stored in the operating system's file system. This version mainly implements the table definition for BFILE types, bfilename function, and certain dbms_lob interface adaptations.

    - Supports MERGE INTO with subquery for single table functionality, simplifying SQL logic and semantics.

    - Supports INSERT using VALUES to reference fields or variables from subqueries while introducing a new conditional_insert_clause syntax for assessing whether to insert based on specific conditions. However, conditional_insert_clause does not support referencing fields or variables from subqueries. In previous versions, YashanDB only implemented INSERT ALL for inserting multi-table/multi-row data using either INSERT ALL VALUES or INSERT ALL SELECT subquery insertion. This version allows using VALUES to reference fields or variables from subqueries while inserting.

    - The table_reference clause supports subqueries and multi-table joins, meaning DELETE/UPDATE operations can be based on query results from other tables as conditions, ensuring that operations only affect records meeting specific relational conditions, which is commonly used for bulk processing and data cleansing.

    - SQL statement parsing supports full-width characters: Prior to v23.4.2, YashanDB did not support full-width characters in SQL or PL statements. To accommodate more usage scenarios, this version adds parsing for common full-width characters (including `+`, `-`, `，`, `！`, `>`, `<`, `=`, `(`, `)` and spaces), allowing for more flexible usage and better support for SQL involving character conversions.

    - Aggregate functions now support the KEEP keyword functionality: Aggregate functions like MIN, MAX, SUM, AVG, COUNT, VARIANCE, and STDDEV support the KEEP keyword, which can be used in conjunction with FIRST or LAST functions, allowing for complex aggregation effects by sorting data first and then performing aggregation on the first/last N records. This simplifies SQL logic by avoiding lengthy subqueries and allows for flexible use with multiple aggregate functions.

- PL Capability Enhancements

    - Supports INSTEAD OF DML triggers: By supporting the instead_of_dml_trigger clause, it allows interception and replacement of operations on non-editable views with a developer-defined operation logic, achieving complex data operation rules and business logic encapsulation at the database level.

    - UDT function overloading support: YashanDB v23.4.1 supported overloading of procedures and package procedures. This version implements function overloading within UDTs, improving compatibility for varied usage scenarios.

    - Support for custom aggregate functions: By implementing the AGGREGATE USING clause, UDFs can be marked as aggregate functions, allowing complex aggregation logic to be encapsulated in a custom aggregate function, simplifying code logic.

    - Supports returning functionality for updates: By supporting the returning clause, it enables returning modified row information while updating data, simplifying common "update then query" logic. When used with the BULK COLLECT clause, it can enhance the performance of returning modified row information.

    - Supports SUBTYPE functionality: In PL, SUBTYPE definition can be implemented to create new data types with specific constraints or semantics based on existing data types, including PL or SQL data types, simplifying code and enhancing code readability.

    - UDFs support DETERMINISTIC attribute: When creating UDFs, the new DETERMINISTIC keyword allows declaring the function as deterministic, meaning the same input parameters always return the same result. DETERMINISTIC functions perform better during queries and calls.

    - Cast function supports MULTISET keyword: Used to convert the subquery result of an expression into a collection type value, facilitating complex data type conversions.

    - Supports passing sets returned by window functions as UDF parameters for processing, typically used in scenarios for complex analysis at the dataset level rather than at the single-row level, achieving real-time analysis and simplifying code.

    - Supports CREATE CONTEXT functionality: This version supports CREATE CONTEXT functionality to store and access properties specific to applications or sessions. Additionally, the DBMS_SESSION system package supports management of CONTEXT through functions like CLEAR_ALL_CONTEXT, CLEAR_CONTEXT, and SET_CONTEXT.

    - New DBMS_ASSERT system package provides an enquote_literal function to add quotes to the input string and escape quotes within the string, ensuring it can be used as a valid literal constant in SQL statements, enhancing database application security and effectively preventing SQL injection attacks, directory traversal attacks, and other security issues.

    - The UTL_RAW system package implements cast_to_nvarchar2 function, which converts RAW values represented by a certain number of data bytes into NVARCHAR2 values of that same number of data bytes.

    - The DBMS_STATS system package supports AUTO_SAMPLE_SIZE and AUTO_DEGREE constants: AUTO_SAMPLE_SIZE indicates the sampling rate for collecting statistics determined automatically by the database, while AUTO_DEGREE indicates the parallelism level for statistics collection determined automatically by the database, enhancing compatibility and usability.

#### SQL Performance Enhancements

- Parallel Capability Enhancements

    - In the case of using NESTLOOP JOIN in the table join optimizer without choosing index scanning, batch and parallel execution support is enabled.

    - When performing full partition scans or partition pruning optimization on partitioned tables, the execution phase's partition scan operator supports batch and parallelization.

    - In INSERT INTO SELECT scenarios involving large volumes of data, batch and parallel execution support enhances insertion performance.

    - The RESULT operator supports batching and parallelization, effectively improving performance in large data operations and result set scenarios.

    - When SQL involves simple aggregation (i.e., aggregation that does not require grouping first), batch execution support is enabled.

    - In SQL scenarios existing with subqueries or views and requiring result set scans, batch and parallel execution support is enabled.

    - Common function performance optimizations are added, such as for NVL, LNNVL, CONCAT, ROUND, COALESCE, supporting batch execution.

    - PL supports enabling SQL parallelism: YashanDB continuously optimizes PL performance; this version supports enabling SQL parallelism within PL, allowing for parallel processing in large volume full table scans, JOINs, and DML scenarios to enhance efficiency.

    - PIPELINED functions support RECORD types and multiple PIPELINED executions: Version 23.4.1 implemented PIPELINED functions, and this version enhances its capabilities by adding support for RECORD types as parameters while allowing multiple PIPELINE functions to execute and compute within a single SQL statement.

- Operator Optimizations

    - Significant optimizations for specific operators such as HASH JOIN INNER and HASH JOIN LEFT OUTER, with performance improvements of up to 100% compared to previous versions.

    - By optimizing the algorithms for like and instr functions when handling NVARCHAR characters, this version achieves a 50% performance improvement relative to previous optimizations.

    - Implementation of the TOP N heap sort algorithm enhances TOP N operator performance. In scenarios returning relatively small result sets, the use of pure memory heap sort can significantly enhance performance with less memory usage.

- Optimizer Enhancements

    - When SQL has correlated subqueries, the optimizer evaluates the number of distinct values (NDV) in subqueries. This version optimizes the algorithm for generating plans in this scenario, enabling more accurate NDV assessment to determine whether to reduce subquery execution frequency, thereby improving adaptability.

    - Type conversion is increased for filters on different types: In scenarios involving filters on different type groups, implicit conversion typically occurs during execution. However, this can lead to not utilizing indexes. YashanDB improves the optimizer in this version by explicitly adding a type conversion function, allowing for the use of indexes in specific scenarios to enhance query efficiency.

    - Removal of unnecessary sorting in set operations: In scenarios where subordinate queries do not utilize limit/rownum but do have ORDER BY or other sorting operations within set operations, the optimizer supports the equivalent rewriting to eliminate unnecessary sorting based on set types, improving the efficiency of set operations. This can effectively enhance performance.

    - Optimization of filter constants and parameters: When filter any/all represents constant lists, it can be optimized to corresponding comparisons, such as transforming any/all into an equivalent in. When the in list contains a large number of constants and parameters, YashanDB also optimizes assessment and rewriting rules, reducing computational complexity and the volume of returned result sets.

    - Nestloop join supports right table as view: In scenarios where SQL involves joins between normal tables and views, the optimizer can choose NESTLOOP joins with the non-driving table being a view, concurrently supporting predicate pushdown to utilize base table indexes, thereby enhancing query performance.

    - New database parameter to control the maximum number of tables supported by DP: In multi-table associated scenarios, the join order is one of the primary factors determining performance. Plans generated by the optimizer using dynamic programming algorithms are generally better than those generated by genetic algorithms, but consume more resources. To better adapt the number of tables supported by the dynamic programming algorithm, the new database parameter MAX_DP_JOIN_TABLES is introduced, enhancing flexibility.

### Storage Engine Enhancements

- Functionality Enhancements

    - Supports GENERATED BY DEFAULT/ALWAYS AS IDENTITY functionality: Prior to this version, to define an auto-increment column in a table, one had to create a sequence and associate it with the corresponding column's default value. This version supports the identity_clause clause, allowing for automatic creation of auto-increment columns, improving usability and streamlining the creation process.

    - Index KEY supports the maximum size aligned with Oracle: Before this version, YashanDB's index KEY supported a maximum of 6000 bytes, thus limited in application. This version extends the index KEY, making the maximum specifications change along with the block size, aligning with Oracle specifications.

    - Primary key constraints support non-matching order with primary key indexes: YashanDB supports using the ALTER TABLE USING INDEX syntax to create constraints by specifying existing indexes, requiring that the number and columns of the constraint match the specified index and the order must be consistent for successful creation. This version extends usability scenarios, allowing for constraints to be created where the number of columns matches and the columns are the same but the order differs, including primary keys and unique keys. Compatibility is also enhanced.

    - Archive log files support backup count statistics and backup/delete functionality based on count conditions: To meet various backup strategy demands across business scenarios, this version adds the ability to cumulatively count the backups of archive log files, viewable in the V$ARCHIVED_LOG view in the BACKUP_COUNT field. New backup functionality based on the number of archive log files backed up and automated deletion strategies are introduced, specifying existing backup counts for deletion or not backing up archive files that have reached or exceeded specified backup counts.

    - CREATE INDEX supports COMPUTE STATISTICS syntax: ALTER/CREATE INDEX enhances compatibility with a new COMPUTE STATISTICS clause, but functionality remains unsupported at this time.

- Performance Optimizations

    - Single-column index creation performance optimization: Added support for parallel creation of function indexes, along with optimizations during the parallel index creation process, allowing multiple shards to simultaneously scan data and sort, greatly reducing creation time. This version achieves a performance enhancement of 100% compared to previous optimizations.

### YAC Capability

- High Availability

    - Supports VIP capability: In previous versions, YACs only supported direct access through physical IP for business access, but in practical scenarios, using physical IP for access presents substantial security and maintenance costs. Additionally, when node failover or recovery occurs, IP needs to be switched, increasing the time cost of outage and affecting application perception. Therefore, to address IP management issues related to physical nodes due to failures, YACs in v23.4.2 introduce VIP capability, allowing this instance's VIP to automatically switch to a surviving node after a node failure, maintaining DB accessibility for read and write business. When the failed node recovers, the VIP will switch back to the original node, and normal access to DB services can resume.

    - Supports specifying instance priorities for connections and switches: In some YAC scenarios, certain businesses are assigned to run on one or more specific cluster instances. In the event of failure, prioritizing the switch order of specified instances realizes business operations while ensuring that interconnected instances serve as primary/standby, enhancing system fault tolerance and availability. In version v23.4.2, priority specification and switching have been implemented at the JDBC and C driver levels to meet business separation and high availability management capabilities in YAC usage.

    - Supports automatic failover in YACs: In v23.2, YACs already supported manual failover in primary/standby scenarios, but in many actual business scenarios, fault switching and management were demanding. Manual switching and management required additional operational support, hence, v23.4.2 supports automatic failover switching to ensure that in scenarios where all instances in the primary cluster are down, automatic failover occurs, reducing system downtime and minimizing RTO recovery time.

    - Supports offline upgrades of primary/standby clusters: In version v23.2, YACs already supported offline upgrades with primary/standby configurations, but without integration of the *yasboot* tool, the operational difficulty of primary/standby upgrades was significantly high. Therefore, in version v23.4.2, the *yasboot* integrated with all operational commands for offline upgrades, enabling a one-click completion of the entire offline upgrade process, greatly enhancing operational ease and usability.

- YFS Reliability

    Prior to this version, if any replica in a DG with Normal or High redundancy failed, YFS would mount the DG to ensure data consistency (thus making the whole DG unavailable), significantly impacting business availability. In version v23.4.2, optimizations for reliability under scenarios with multiple replicas are executed, supporting the DG to remain available and reliable with data whenever any replica remains operational, ensuring continuous service availability for YAC while improving overall product usability.

### Usability

- Operational Capability Enhancements

    - Supports SQL statement tracing functionality (10046 event): By supporting the setting of the 10046 event to implement SQL TRACE capability, such as '10046 TRACE NAME CONTEXT FOREVER, LEVEL 12', SQL execution statistics are recorded, including parsing, execution, extraction, commit, rollback, response time, service time, the number of rows processed, and the number of physical reads and writes, execution plans, and other additional information. This can be used for SQL tracing to analyze the distribution of resource consumption during SQL execution and additional performance data, effectively assisting users in identifying issues and optimizing SQL execution plans.

    - SLOWLOG supports printing complete SQL and bound variables: In high concurrency environments with large SQL queries, when the SQL pool size is insufficient, many SQL statements can be quickly flushed out of the buffer. As a result, the output from SLOWLOG, which is limited to 2000 bytes, often leads to incomplete SQL, making issue identification difficult. This version enhances SLOWLOG printing to support outputting the full SQL text in logs while adding support for printing bound variables, providing more effective information and increasing diagnostic efficiency.

- Deployment Operation Enhancements:

    - Installation deployment process optimization: Supports pre-checking and validating database parameters, environmental information, and server resources during deployment, avoiding failures arising from unmet dependencies and exceptions post-initiation, enhancing usability.

    - yasom self-recovery: In earlier versions, after yasom automatically switched masters upon encountering discrepancies, previously reported database information could be lacking for the failed node, requiring manual updates. This version implements automatic recovery, allowing the self-retrieval of each node's information and displaying all database information, thus enhancing usability.

    - Pre-check for operations like rebuilding standby databases and backups: Prior to v23.4.2, during operations to rebuild standby databases or backups, failures prompted by unmet preconditions often resulted in long execution times. This version supports pre-checking dependencies and exceptions so that error messages are issued in scenarios involving backup path errors, recovery path errors, and un-cleared datafiles when carrying out backup and standby database reconstruction using *yasrman* and *yasboot*, thus saving user time and improving usability.

- Performance Reports Capability Enhancements:

    - The performance report includes new statistics displaying the database buffer hit rate and SWAP utilization over specified time periods, offering a more intuitive and rapid means to obtain effective information.

    - The performance reports add lock statistics for spinlocks, primarily adding records for the number of attempts to acquire locks and the number of lock waits. This enables finer monitoring of memory states and assists in performance issue diagnosis and bottleneck analysis.

- Import/Export Capability Enhancements:

    - Before version v23.4.2, YashanDB's tools did not allow multi-character combinations as delimiters when importing and exporting CSV files. This version adds tool parameters to allow users to configure custom delimiters and supports multi-character delimiters, enhancing adaptability for diverse use cases and habits.

    - While exporting CSV files, character data types previously required the designation of enclosing symbols or defaulted to using double quotes; this version allows exports of character types without enclosing symbols, thereby supporting a wider range of CSV file formats.

    - When using yasldr with embedded mode for imports, all data must be partitioned before parsing, resulting in prolonged prepare times. This version leverages new file reading threads to accelerate file reading and chunking for improved prepare efficiency, with an approximately 30% performance improvement over the previous version.

- yasql Functionality Enhancements:

    - New functionality introduces the use of & placeholders or SET define ON variables to achieve interactive connections to the database during connect commands, enhancing security and usability.

    - Supports the ACCEPT command functionality, allowing input values to be assigned to specific substitute variables, enabling *yasql* to receive user input from the command line interface.

### Driver

- In this version, YashanDB enhances and optimizes the capabilities of the ODBC driver by enabling configuration of multiple target database IP ports in the URL column within the odbc.ini file, thus supporting automatic connection to the primary database post-failover in primary/standby clusters.

- The ODBC driver supports scalar functions:

  - IFNULL: Used to check whether an expression is NULL; if so, it returns the specified alternative value; otherwise, it returns the expression itself.

  - CONCAT: Used to concatenate multiple strings into a single string, accepting multiple strings as parameters and sequentially combining them.

  - SUBSTRING: Allows specifying a starting position and length to extract part of a string.

  - LEFT: Extracts a substring of n characters from the left of string_exp.
