YCS provides operational logs for monitoring and analysis of the server it resides on. The log files are located in the /log/run folder under the YCS HOME directory, and the path and name cannot be changed.

Operational logs are controlled by the log level, which regulates the recording switch and strategy. When the level is set to OFF, operational logs are not recorded.

## Set Log File Retention Count

The retention count of operational logs can be modified by setting the LOG_NUMBER parameter. When the number of logs reaches the value set by this parameter (default is 10), the system will automatically delete the oldest logs.

Value range/format: [2,10000]

Command to modify the log file retention count:

```shell
$ ycsctl set log_number 10
```

The command to check the current log file retention count is as follows:

```shell
$ ycsctl get log_number
YCS LOG_NUMBER = 10
```

You can observe the retention count of files in the log file storage location:

```shell
$ ls -l $YASCS_HOME/log/run
total 1168
-rw-r----- 1 yashan yashan 1193430 Jul 19 10:09 run.log
```

## Set Log File Maximum Size

The maximum size of the operational logs can be modified by setting the LOG_SIZE parameter. When the log file reaches the value set by this parameter (default is 20M), it will be automatically archived.

Value range/format: [1M,4G]

Command to modify the maximum size of logs:

```shell
$ ycsctl set log_size 20M
```

The command to check the current maximum size of logs is as follows:

```shell
$ ycsctl get log_size
YCS LOG_SIZE = 20MB
```

## Manage Log Level

When the operation level is set to OFF, operational logs are not recorded.

The ordering of other operational log levels is as follows:

ERROR < WARN < INFO < DEBUG < TRACE < ALL

From left to right, the log level increases, with higher log levels including lower ones.

The command to check the current operational log level is as follows:

```shell
$ ycsctl get log_level
YCS LOG_LEVEL = DEBUG
```

You can change the operational log level by modifying the LOG_LEVEL parameter (effective after restart), or by executing the following command (effective immediately):

```shell
$ ycsctl set log_level info

$ ycsctl get log_level
YCS LOG_LEVEL = info
```

### ERROR Level

An ERROR log will be output when a critical error that can be processed occurs in YAC instance. These errors generally cannot be returned to the client, such as errors generated by background threads.

The command to set the log level to ERROR is as follows:

```shell
ycsctl set LOG_LEVEL "ERROR"
```

***Example***

```verilog
// When YCS fails to process messages due to a server disconnection, the run.log prints as follows:
2023-07-05 18:49:49.331 4334 [ERROR][errno=00406]: [YCS] failed to process yascs client message: connection is closed
```

### INFO Level

The default log level used by YAC instance is INFO.

The INFO level records critical events that occur during the normal operation of YAC instance, mainly including:

- Status changes of YAC instance: such as start, stop, promote, and demote.
- Operational actions of YAC execution tools: such as starting and ending tools.
- Key activities of YAC: such as topology status changes.
- Changes in YAC parameters: modifying system configuration parameters.

The command to set the log level to INFO is as follows:

```shell
ycsctl set LOG_LEVEL "INFO"
```

### DEBUG Level

The DEBUG level is used to log key information that may be needed for troubleshooting.

The command to set the log level to DEBUG is as follows:

```shell
ycsctl set LOG_LEVEL "DEBUG"
```

***Example***

```verilog
// When the last YAC instance stops, quitting without switch over, run.log prints as follows:
2023-06-30 15:21:07.028 91394 [DEBUG] Self is last node, quit without switch over
2023-06-30 15:21:07.028 91394 [DEBUG] Stop inspect, exception triggered will not be processed any more.
2023-06-30 15:21:07.028 91394 [DEBUG] Try close all channels
```

### ALL Level

The ALL level records all log information and is the highest log level mode.

The command to set the log level to ALL is as follows:

```shell
ycsctl set LOG_LEVEL "ALL"
```
