This view displays information about all redo files.

In a YAC, it shows (number of online instances * all instance redo files) information.

|Column Name |Type |Description |
| --- | --- | --- |
| GROUP_ID | NUMBER | Group ID |
| GROUP_NODE_ID | NUMBER | Node ID within the group |
| INST_ID | NUMBER  | Instance ID |
| THREAD# | TINYINT | Instance Number |
| ID  | INTEGER | Redo File ID |
| NAME | VARCHAR(255) | Redo File Path |
| BLOCK_SIZE | INTEGER | Page size of the redo file (unit: bytes) |
| BLOCK_COUNT | BIGINT | Total number of pages in the redo file |
| USED_BLOCKS | BIGINT | Number of used pages in the redo file |
| SEQUENCE# | INTEGER | Sequence number of the redo file, this sequence number increments |
| STATUS | VARCHAR(8) | Status of the redo file<br>\*   NEW: This file has not written any redo logs, it is a newly created redo file or the file has been initialized<br>\*   INACTIVE: The redo pages contained in this status have all been written to disk. Redo files in this status can be reused<br>\*   ACTIVE: The redo pages contained in this status have some that have not been written to disk, or this redo has not yet been archived. Files in this status cannot be reused<br>\*   CURRENT: The redo file currently in use |
| TYPE | VARCHAR(8) | Type of the redo file<br>\*   ONLINE: Represents ONLINE files, used to store redo generated by the primary database<br>\*   STANDBY: Represents STANDBY files, used to store redo generated by the logical standby database |
| ARCHIVED  | VARCHAR(3) | Whether the redo file has been archived<br>\*   YES: The redo file has been archived<br>\*   NO: The redo file has not been archived |
| HEALTH | VARCHAR(32) | Health of the redo file when the database loads<br>\*   NORMAL: The redo file is normal<br>\*   MISSING: The redo file is missing<br>\*   HEAD_CURRUPTED: The header of the redo file is corrupted |
