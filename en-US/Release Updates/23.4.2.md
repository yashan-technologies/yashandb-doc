## 23.4.2.100

The following lists the major and notable changes in version 23.4.2.100 of YashanDB compared to version 23.4.1.100. If you discover any changes during your use that are not listed in this document but impact your company's business, please consult our technical support for detailed explanations.

### Upgrade Notes

The following table shows the range of old versions that support offline upgrades to the current version.

|Deployment Type |Old Version Range |
|--------------------|---------------------|
| Standalone Deployment      | 22.2.16 and earlier<br/>23.1.5 and earlier<br/>23.2.12 and earlier<br/>23.3.3 and earlier<br/>23.4.1   |
| YAC Deployment             | 23.1.5 and earlier<br/>23.2.12 and earlier<br/>23.3.3 and earlier<br/>23.4.1 |
| ISC Distributed Cluster Deployment     | 23.1.5 and earlier<br/>23.2.12 and earlier<br/>23.3.3 and earlier<br/>23.4.1 |

### Installation and Upgrade

|Change Item |Change |Content |
|--------|------------|---------------------|
| Command-line Interactive Deployment | Scope Expansion     | Supports using the interactive installation command yasboot init to deploy YACs, involving the following parameters:<br/>* -t, --yas-type: Specifies the deployment form of the database, optional values [SE|CE].<br/>* --ce-data: Specifies the data disk for YAC.<br/>* --disk-found-path: Specifies the disk discovery path for YAC.<br/>* --system-data: Specifies the system data disk for YAC.<br/>* --group: Specifies the number of groups in YAC, such as deploying primary/standby clusters.<br/>* --standby-node: Specifies the deployment scale of the standby nodes in YAC.<br/>* -fg,--failgroup: Specifies the number of failure groups in YAC disk group.<br/>* --yfs-force-create: Specifies YFS to force create the disk group. |
| Rolling Upgrade            | Scope Expansion       | YAC Deployment supports online rolling upgrades between compatible versions (versions with the same first three digits but different fourth digits) starting from v23.4.2.x. |
| Deploy YAC      | Support for VIP       | If you need to specify a VIP for YAC nodes directly during deployment (it can also be configured separately after deployment), the manual deployment method must be adopted using command-line installation, involving the following changes:<br/>* During the preparation phase before installation, plan an additional IP address for each server as the node VIP.<br/>* During the installation process, the yasboot package ce gen command adds the --vips parameter to specify VIP configuration information. If deploying a primary/standby cluster, the VIP of the standby cluster must be manually edited in the {cluster_name}.toml file for configuration. |
