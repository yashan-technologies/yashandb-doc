## 23.4.4.100

The following lists the major and notable changes in version 23.4.4.100 of YashanDB compared to version 23.4.3.100. If you discover any changes during your use that are not listed in this document but impact your company's business, please consult our technical support for detailed explanations.

### Upgrade Notes

The following table shows the range of old versions that support offline upgrades to the current version.

|Deployment Type       |Old Version Range                             |
| ---------------------------------- | ------------------------------------------------------------ |
| Standalone Deployment              | 22.2.16 and earlier<br/>23.1.5 and earlier<br/>23.2.12 and earlier<br/>23.3.3 and earlier<br/>23.4.3 and earlier |
| YAC Deployment                     | 23.1.5 and earlier<br/>23.2.12 and earlier<br/>23.3.3 and earlier<br/>23.4.3 and earlier |
| ISC Distributed Cluster Deployment | 23.1.5 and earlier<br/>23.2.12 and earlier<br/>23.3.3 and earlier<br/>23.4.3 and earlier |

### Installation and Upgrade

|Change Item |Change |Content                                             |
| ---------------------- | --------------- | ------------------------------------------------------------ |
| YAC Deployment           | Network Configuration Changes    | 1. Added SCAN support: To directly specify SCAN for YAC nodes during deployment (SCAN can also be configured separately after deployment completion), the following changes are involved:<br/>* During pre-installation preparation, you need to plan the SCAN domain name and 1-3 IP addresses as SCAN VIPs, and configure SCAN resolution rules on the DNS server.<br/>* During installation and deployment, new parameters --public-network and --scanname are added, used to specify the public subnet and SCAN domain name respectively. These two parameters must be used together. For primary-standby cluster deployment, the public subnet (--public-network) and SCAN configuration (--scanname) of the standby cluster need to be manually edited in the {cluster_name}.toml file for configuration.<br/><br/>2. VIP function adds new constraints: The public subnet (--public-network parameter) must be configured before configuring VIPs. |
| YAC Deployment (Interactive)       | Applicable Scope Expansion    | Supports specifying VIP or SCAN for YAC during deployment, involving the following parameters:<br/>* --public-network: Specifies the public subnet for the YAC.<br/>* --vips: Specifies the virtual IP address set for the YAC.<br/>* --scanname: Specifies the SCAN domain name for the YAC. |
