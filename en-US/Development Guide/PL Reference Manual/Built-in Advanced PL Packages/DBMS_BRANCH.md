The DBMS_BRANCH package provides a set of stored procedures/functions for the lifecycle management of database branches, supporting branch creation, switching, deletion, reset, restore, freeze, activation, rename, expiration setting, and resource management.

> **Note**:
>
> - Only applicable to branch database deployment (Configuration parameter ENABLE_BRANCH=TRUE).
> - Only the SYS user can call the stored procedures/functions of this advanced package.

<span id="CREATE" name="CREATE"></span>

## CREATE

```plsql
DBMS_BRANCH.CREATE (
    name      IN    VARCHAR DEFAULT NULL,
    parent    IN    VARCHAR DEFAULT NULL,
    checkout  IN    BOOLEAN DEFAULT FALSE,
    default   IN    BOOLEAN DEFAULT FALSE);
```

This procedure creates a branch, supporting the following three creation methods:

- Create a default branch: The branch data is empty and does not inherit data from any existing branch. To create this type of branch, set default to TRUE and parent to NULL.
- Clone from the current branch: The branch data inherits from the current session's branch. To create this type of branch, set default to FALSE and parent to NULL.
- Clone from a specified branch: The branch data inherits from the specified parent branch. To create this type of branch, set default to FALSE and parent to the specified branch.

| Parameter | Description |
| :--- | :--- |
| name | Branch name. If not specified, it is automatically generated by the system. The name must be unique and comply with YashanDB [object naming conventions](../../SQL Reference Manual/Basic SQL Elements/Identifiers) |
| parent | Parent branch name. If not specified, clones from the current branch; if specified, clones from the specified branch |
| checkout | Whether to switch to the new branch immediately after creation. The default value is FALSE. When set to TRUE, the current session will automatically switch to the new branch after successful creation |
| default | Whether to create a default branch (empty branch). The default value is FALSE. When set to TRUE, the created branch has empty data. This parameter is invalid when parent is not NULL |


Example (Standalone Deployment)

```plsql
-- Clone from the current branch, branch name automatically generated by the system
EXEC DBMS_BRANCH.CREATE();

-- Create a default branch test1
EXEC DBMS_BRANCH.CREATE(name => 'test1', default => TRUE);

-- Clone a test2 branch from test1, and immediately switch to test2
EXEC DBMS_BRANCH.CREATE('test2', 'test1', TRUE);

-- Create a branch with named parameters
EXEC DBMS_BRANCH.CREATE(
    name => 'test3',
    parent => 'test1',
    checkout => FALSE,
    default => FALSE);
```

<span id="CURRENT" name="CURRENT"></span>

## CURRENT

```plsql
DBMS_BRANCH.CURRENT();
```

This function returns the name of the branch where the current session is located.

Example (Standalone Deployment)

```sql
-- Get the current branch name
SELECT DBMS_BRANCH.CURRENT() FROM DUAL;
DBMS_BRANCH.CURRENT()
----------------------------------------------------------------
BRANCH1
-- You can also execute the following command to query the current branch name
show branch;
BRANCH
----------------------------------------------------------------
BRANCH1
```

<span id="LIST" name="LIST"></span>

## LIST

```plsql
DBMS_BRANCH.LIST();
```

This function lists all branch information in the current database, including branch name (BRANCH_NAME), branch status (STATUS), parent branch name (PARENT_NAME), creation time (CREATED_AT), and expiration time (EXPIRED_AT).

Example (Standalone Deployment)

```sql
-- List all branch information
SELECT DBMS_BRANCH.LIST() FROM DUAL;
```

<span id="CHECKOUT" name="CHECKOUT"></span>

## CHECKOUT

```plsql
DBMS_BRANCH.CHECKOUT(
    name IN VARCHAR);
```

This procedure switches the current session to the target branch.

| Parameter | Description |
| :--- | :--- |
| name | Target branch name, must be specified as an already created branch |

Example (Standalone Deployment)

```plsql
-- Switch from the current branch to test2
EXEC DBMS_BRANCH.CHECKOUT('test2');
```

<span id="FREEZE" name="FREEZE"></span>

## FREEZE

```plsql
DBMS_BRANCH.FREEZE(
    name IN VARCHAR);
```

This procedure freezes a custom-created branch. To freeze the branch currently in use by the session, you need to first call the CHECKOUT subprogram to switch to another branch.

The built-in BRANCH$ADMIN branch cannot be frozen.

| Parameter | Description |
| :--- | :--- |
| name | Name of the branch to be frozen, must be specified as an existing branch |


Example (Standalone Deployment)

```sql
-- Freeze the test branch
EXEC DBMS_BRANCH.FREEZE('test');
```

```plsql
DBMS_BRANCH.ACTIVATE(
```

This procedure reactivates a frozen branch.

| Parameter | Description |
| :--- | :--- |
| name | Name of the branch to be activated, must be specified as an existing branch |

```sql
-- Activate the test branch
```

<span id="RENAME" name="RENAME"></span>

## RENAME

```plsql
DBMS_BRANCH.RENAME(
    name    IN VARCHAR,
    newname IN VARCHAR);
```

This procedure renames a branch.
Before renaming, you need to call the FREEZE subprogram to freeze the target branch.

| Parameter | Description |
| :--- | :--- |
| name | Original branch name, must be specified as an existing branch |
| newname | New branch name, must comply with [object naming conventions](../../SQL Reference Manual/Basic SQL Elements/Identifiers) and must not duplicate existing branch names |

Example (Standalone Deployment)

```plsql
-- Rename branch test to test2
EXEC DBMS_BRANCH.RENAME('test', 'test2');
```

<span id="SET_RESOURCE" name="SET_RESOURCE"></span>

## SET_RESOURCE

```plsql
DBMS_BRANCH.SET_RESOURCE(
    name       IN VARCHAR,
    UTIL_LIMIT IN NUMBER DEFAULT NULL,
    MEMORY     IN VARCHAR DEFAULT NULL);
```

This procedure sets the resource management plan for a branch, including CPU and memory resource quotas.

Usage notes:

- By default, the resource management plan is not enabled, and this function does not take effect. To enable resource management, execute the following statements:
```plsql
EXEC DBMS_BRANCH.CHECKOUT('branch$admin');
alter system set RESOURCE_MANAGER_PLAN='DEFAULT_CDB_PLAN' scope=both;
```
- The plan configuration can be queried through the DBA_BRANCH_RSRC_PLAN_DIRECTIVES view.
- The UTIL_LIMIT and MEMORY parameters can be specified individually or simultaneously.
- When a parameter is not specified or set to NULL, no limit is applied to that resource item.

| Parameter | Description |
| :--- | :--- |
| name | Branch name, must be specified as an existing branch |
| UTIL_LIMIT | CPU utilization percentage upper limit. The value range is an integer from [1,100], in percent |
| MEMORY | Memory utilization upper limit. Supports string format with units, such as '5G', '1024M', etc. |

Example (Standalone Deployment)

```plsql
-- Set the CPU utilization upper limit of branch test to 20%
EXEC DBMS_BRANCH.SET_RESOURCE('test', UTIL_LIMIT => 20);

-- Set the memory utilization upper limit of branch test to 5G
EXEC DBMS_BRANCH.SET_RESOURCE('test', MEMORY => '5G');

-- Set the CPU utilization upper limit of branch test to 30% and memory to 10G
EXEC DBMS_BRANCH.SET_RESOURCE('test', 30, '10G');
```

<span id="SET_EXPIRATION" name="SET_EXPIRATION"></span>

## SET_EXPIRATION

```plsql
DBMS_BRANCH.SET_EXPIRATION(
    name      IN VARCHAR,
    timestamp IN VARCHAR);
```

This procedure sets the expiration time for a branch. After the expiration time is reached, the branch will be automatically cleaned up.

| Parameter | Description |
| :--- | :--- |
| name | Branch name, must be specified as an existing branch |
| timestamp | Expiration time, in the format 'YYYY-MM-DD HH24:MI:SS' |

Example (Standalone Deployment)

```plsql
-- Set the test branch to expire at 00:00:00 on January 1, 2027
EXEC DBMS_BRANCH.SET_EXPIRATION('test', '2027-01-01 00:00:00');
-- Query the expiration time of all branches
SELECT DBMS_BRANCH.LIST() FROM DUAL;
```

<span id="RESET" name="RESET"></span>

## RESET

```plsql
DBMS_BRANCH.RESET();
```

This function resets the data of the current branch to the state at the time of branch creation.

>**Caution**:
>- The reset operation discards all data changes made after branch creation and cannot be recovered. **Please use with caution**.
>- If the data files that the branch had at creation time are lost, this operation will not recover these data files, and the related data will be lost.

Example (Standalone Deployment)

```sql
-- Confirm that the current branch is the branch you want to recover
SELECT DBMS_BRANCH.CURRENT() FROM DUAL;
DBMS_BRANCH.CURRENT()
----------------------------------------------------------------
BRANCH1

-- Reset the current branch to its initial state
EXEC DBMS_BRANCH.RESET();
```

<span id="RESTORE" name="RESTORE"></span>

## RESTORE

```plsql
DBMS_BRANCH.RESTORE(
    timestamp IN VARCHAR);
```

This procedure restores the data of the current branch to a specified point in time after the branch creation.

>**Caution**:
>- The restore operation discards all data changes after the specified point in time and cannot be recovered. **Please use with caution**.
>- If the data files that the branch had at the target time point are lost, this operation will not recover these data files, and the related data will be lost.

| Parameter | Description |
| :--- | :--- |
| timestamp | Target restore point in time, supporting timestamp format or SCN value<br/>Must be later than the creation time of the branch |

Example (Standalone Deployment)

```sql
-- Confirm that the current branch is the branch you want to recover
SELECT DBMS_BRANCH.CURRENT() FROM DUAL;
DBMS_BRANCH.CURRENT()
----------------------------------------------------------------
BRANCH1

-- Query the creation time of the branch
SELECT DBMS_BRANCH.LIST() FROM DUAL;
DBMS_BRANCH.LIST()
----------------------------------------------------------------
+------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
|                           BRANCH_NAME                            | STATUS |                           PARENT_NAME                            |      CREATED_AT     |      EXPIRED_AT     |
+------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| BRANCH$TEMPLATE                                                  | FROZEN |                                                                  | 2026-07-08 20:34:33 |                     |
| MASTER                                                           | ACTIVE | BRANCH$TEMPLATE                                                  | 2026-07-08 20:34:47 |                     |
| BRANCH1                                                          | ACTIVE | MASTER                                                           | 2026-07-08 20:37:29 |                     |
+------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
3 branches found.

-- Query the current SCN
SELECT CURRENT_SCN FROM V$DATABASE;

          CURRENT_SCN
---------------------
   842457321918119936

-- Restore the current branch to the specified point in time
EXEC DBMS_BRANCH.RESTORE('2026-07-08 21:00:00');

-- Restore the current branch to the specified SCN
EXEC DBMS_BRANCH.RESTORE(842457321918119936);
```

## DELETE

```plsql
DBMS_BRANCH.DELETE(
    name IN VARCHAR);
```

This procedure deletes a custom-created branch. To delete the branch currently in use by the session, you need to first call the CHECKOUT subprogram to switch to another branch.

The built-in BRANCH$ADMIN and BRANCH$TEMPLATE branches cannot be deleted.

| Parameter | Description |
| :--- | :--- |
| name | Name of the branch to be deleted, must be specified as an existing branch |

Example (Standalone Deployment)

```plsql
-- Delete the test2 branch
EXEC DBMS_BRANCH.DELETE('test2');
```
