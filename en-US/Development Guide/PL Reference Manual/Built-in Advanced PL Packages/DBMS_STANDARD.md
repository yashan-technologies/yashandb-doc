The DBMS_STANDARD package provides a set of built-in stored procedures/functions, primarily used for exception handling, transaction processing, and controlling external Java functions in PL.

When calling the subprograms of the DBMS_STANDARD package, you can omit DBMS_STANDARD and directly use the subprogram name.

## RAISE_APPLICATION_ERROR

***Example***

```plsql
DBMS_STANDARD.RAISE_APPLICATION_ERROR(
    errCode         IN INTEGER,
    errMsg          IN VARCHAR,
    reserveErrStack IN BOOLEAN DEFAULT FALSE);
```

The RAISE_APPLICATION_ERROR stored procedure is used to manually raise exceptions in PL programs.

|Parameter |Description |
| :------ |:-----------------------|
| errCode           | Error number, ranging from [30000,99999]. |
| errMsg            | Error message, not exceeding 1024 bytes in length. The trailing whitespace of the error message string will be removed. |
| reserveErrStack   | Reserved field, only for syntax compatibility. |

***Example***
```plsql
CREATE or replace PROCEDURE account_status (
    due_date DATE,
    today DATE) IS
BEGIN
    IF due_date < today THEN -- explicitly raise exception
      DBMS_STANDARD.RAISE_APPLICATION_ERROR(29999+1, 'Account past due.');
    END IF;
END;
/

DECLARE
    past_due EXCEPTION; -- declare exception
    PRAGMA EXCEPTION_INIT (past_due, 30000); 
BEGIN
    account_status (TO_DATE('01-JUL-2010', 'DD-MON-YYYY'),
    TO_DATE('09-JUL-2010', 'DD-MON-YYYY')); 
EXCEPTION
    WHEN past_due THEN -- handle exception
        DBMS_OUTPUT.PUT_LINE('SUCCESS!');
END;
/

--result
SUCCESS!
```

## LOADJAVA

***Example***

```plsql
DBMS_STANDARD.LOADJAVA(
    javaPath IN VARCHAR);
```

The LOADJAVA stored procedure is used to load a Java file, used in external UDF scenarios.

YashanDB will automatically create a custom library object under the current user, with the object name generated by the input path according to certain rules, case-sensitive, and compliant with YashanDB's [object naming conventions](../../SQL Reference Manual/Basic SQL Elements/Identifiers).

YashanDB has provided functionality for directly creating custom libraries, and this method is no longer recommended.

|Parameter |Description |
| :------- | :-------------------------------------------------- |
| javaPath     | Path of the class file or jar to be loaded, not exceeding 255 bytes in length. |

***Example***

```plsql
call DBMS_STANDARD.LOADJAVA('/mnt/d/com/test/Hello.class');
```

## DROPJAVA

```plsql
DBMS_STANDARD.DROPJAVA(
    javaPath IN VARCHAR);
```

The DROPJAVA stored procedure is used to unload a Java file, used in external UDF scenarios.

|Parameter |Description |
| :------- | :-------------------------------------------------- |
| javaPath     | Path of the class file or jar to be unloaded, not exceeding 255 bytes in length. |

***Example***

```plsql
call DBMS_STANDARD.DROPJAVA('/mnt/d/com/test/Hello.class');
```

## INSERTING

The INSERTING function is used to return TRUE within triggers executed in INSERT statements. This function has no parameters; please refer to the examples in [triggers](../PL Objects/Triggers) for usage.

## DELETING

The DELETING function is used to return TRUE within triggers executed in DELETE statements. This function has no parameters; please refer to the examples in [triggers](../PL Objects/Triggers) for usage.

## UPDATING

***Example***

```plsql
DBMS_STANDARD.UPDATING(
    colName IN VARCHAR);
```

The UPDATING function is used to return TRUE when the column updated in an UPDATE statement matches the input parameter.

|Parameter |Description |
| :------ | :----------------------------------------------------------- |
| colName      | The name of the column updated in the UPDATE operation. Returns TRUE when the updated column matches colName. When colName is not set, returns TRUE for updating any column. |

Please refer to the examples in [triggers](../PL Objects/Triggers) for usage.
