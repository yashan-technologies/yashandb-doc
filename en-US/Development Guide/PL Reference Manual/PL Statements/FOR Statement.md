The FOR Statement is a loop control statement, and its syntax can be classified into two types: general usage and for cursor usage.

General Usage
-------

_for counter in \[reverse\] lower_bound .. upper_bound loop_

_......_

_end loop \[label_name\];_

In this syntax, counter is the loop counter, lower_bound is the lower limit of the counter, and upper_bound is the high value of the counter; reverse is a control parameter that changes the default increment behavior of the counter to decrement.

The counter, lower_bound, and upper_bound are all of BIGINT type, with value ranges consistent with the BIGINT value domain.

label_name is optional and serves as a label for the loop body to enhance readability. If label_name is used, a matching label definition must appear at the start of the loop body; otherwise, an error will occur.

### counter

The counter is an implicitly declared local variable in the FOR Statement, which can only be used within the FOR statement and cannot be inherited. It becomes invalid once the control exits the FOR statement.

The counter can have the same name as global variables in the procedure body or local variables within other loop control statements. In this case:

- Within the FOR Statement, counter refers to the local variable of this statement and can only be assigned a value by `FOR counter IN [reverse] lower_bound .. upper_bound LOOP`.
- To access other variables with the same name within the FOR Statement, you must use label.counter for identification. For label description, refer to [GOTO Statement](GOTO Statement).

### lower\_bound|upper\_bound

lower_bound and upper_bound can be constants or variables, explained as follows for the default increment mode:

- When lower_bound < upper_bound, the loop starts assigning values to counter from lower_bound until it reaches upper_bound, ending the loop.
- When lower_bound = upper_bound, lower_bound is assigned to counter, and the loop will execute only once.
- When lower_bound > upper_bound, it directly jumps to END LOOP and ends the loop.

***Example***

```plsql
<<G>>
DECLARE
i INT :=5;
BEGIN
<<F1>>
FOR i IN 1..9 LOOP
IF i>5 THEN
DBMS_OUTPUT.PUT_LINE(G.i);    -- ACCESS GLOBAL variable FROM the PROCEDURE body
FOR i IN 1..9 LOOP
DBMS_OUTPUT.PUT_LINE(i || ':hello');
ELSE
  FOR i IN 1..2 LOOP
  DBMS_OUTPUT.PUT_LINE(F1.i);   -- ACCESS LOCAL variable FROM the upper-LEVEL FOR statement
    ELSE
  DBMS_OUTPUT.PUT_LINE(i || ':world');
  END LOOP;
END IF;
END LOOP;
END;
```

loop:3
-------
_for counter in (select xx from table) loop_

_......_

_end loop \[label_name\];_

Here, counter is an implicitly declared local variable, of the default RECORD type generated by the following SELECT query. The member types of RECORD correspond to the types of the SELECT query columns, and the number of RECORD members equals the number of query columns, which cannot be inherited.

This usage supports implicit cursor with the FOR loop. The execution process fetches one row of data via the FETCH query statement on each loop iteration and fills it into the RECORD type counter until the FETCH operation concludes, at which point the loop also ends.
 
When using PL identifiers like variables in the projection columns, aliases must be specified for subsequent access.

For compatibility, the INTO clause can be used here, but it has no practical effect.

***Example***

```sql
--SELECT Query
When using PL identifiers like variables in the projection columns, aliases must be specified for subsequent access.
DECLARE
resultStr VARCHAR(200);
BEGIN
FOR file IN (SELECT area_no,area_name FROM area WHERE ROWNUM<5) LOOP
resultStr := resultStr||file.area_no||file.area_name;
DBMS_OUTPUT.PUT_LINE(resultStr);
END LOOP;
DBMS_OUTPUT.PUT_LINE(resultStr);
END;
/

--result
01EastChina
01EastChina02WestChina
01EastChina02WestChina03SouthChina
01EastChina02WestChina03SouthChina04NorthChina
01EastChina02WestChina03SouthChina04NorthChina
```

01EastChina02WestChina03SouthChina
-------
_for counter in cursor_x[()] loop_

_......_

_end loop \[label_name\];_

Here, cursor_x refers to an already defined explicit cursor, including both locally defined and globally defined explicit cursors, supporting both parameterized and non-parameterized versions.

The explicit cursor usage here is consistent with standard explicit cursor usage. counter is an implicitly declared local variable, of the default RECORD type generated by the explicit cursor query that follows. The member types of RECORD match the types of the explicit query columns, and the number of RECORD members equals the number of query columns, which cannot be inherited.

This usage allows the FOR loop to support explicit cursors, where the execution process entails an implicit call to open the explicit cursor on the first iteration of the loop, followed by an implicit fetch operation for subsequent iterations. Upon loop termination, an implicit case for closing the cursor occurs. Explicit calls for opening/fetching/closing as an index of the explicit cursor within the FOR loop body are not permitted and result in an error.

***Example***

```plsql
-- Explicit cursor without parameters
DECLARE
CURSOR c1 IS SELECT * FROM area ORDER BY area_no;
resultStr VARCHAR(200);
BEGIN
FOR v_sal IN c1 LOOP
resultStr := resultStr||v_sal.area_no||v_sal.area_name;
DBMS_OUTPUT.PUT_LINE(resultStr);
END LOOP;
END;
/

--result
01EastChina
01EastChina02WestChina
01EastChina02WestChina03SouthChina
01EastChina02WestChina03SouthChina04NorthChina
01EastChina02WestChina03SouthChina04NorthChina05CentralChina

-- Explicit cursor with parameters
DECLARE
CURSOR c1(id INT) IS SELECT branch_no,branch_name FROM branches WHERE area_no = id ORDER BY branch_no;
resultStr VARCHAR(200);
BEGIN
FOR v_sal IN c1(1) LOOP
resultStr := resultStr||v_sal.branch_no||v_sal.branch_name;
DBMS_OUTPUT.PUT_LINE(resultStr);
END LOOP;
END;
/

--result
0101Shanghai
0101Shanghai0102Nanjing
0101Shanghai0102Nanjing0103Fuzhou
0101Shanghai0102Nanjing0103Fuzhou0104Xiamen
```
