General Description
----

SET AUTOTRACE is a command implemented in *yasql* (the SQL client tool for YashanDB) for generating trace reports, obtaining execution plans for DML-type SQL statements (SELECT/INSERT/UPDATE/DELETE), as well as information on resource consumption and execution time generated by the execution plans.

When AUTOTRACE is enabled, executing DML-type SQL statements in the client will output not only the SQL results but also information from the trace report, which depends on the enabled options of AUTOTRACE.

AUTOTRACE is a common SQL tuning tool, and more information can be found in the tuning manual.

Statement Definition
----

**set autotrace::=**

```ebnf+diagram
syntax::= SET AUTOT[RACE] {ON | OFF | TRACE[ONLY]} [EXP[LAIN]] [STAT[ISTICS]]
```

### 1. SET AUTOTRACE OFF

Default mode; no trace report is generated.

***Example***

```sql
SET AUTOTRACE OFF;
```

### 2. SET AUTOTRACE ON EXPLAIN

Generates a trace report and outputs the execution results and execution plans of the statements.

With this setting enabled, subsequent DML statements will output the execution plan, which includes the following new information:

- A-ROWS: Actual number of rows executed
- A-TIME: Actual execution time in microseconds
- LOOP: Number of data retrieval iterations
- MEMORY: Memory size occupied by the operator
- DISK: Disk space size occupied by the operator
- PX RemoteInfo/PX LocalInfo: Specific information about PX execution operators for data interaction between nodes
  - total time: Activation time, i.e., the time from start to finish, in milliseconds, taking the maximum value of all sub-threads
  - send_bytes: Amount of data sent during the sampling period, in bytes
  - send_packets: Number of packets sent during the sampling period
  - send_acks: Number of acks sent during the sampling period
  - wait_space_times: Number of times waited during the sampling period due to insufficient send buffer
  - wait_space_timeout: Number of times waited during the sampling period due to insufficient send buffer timeout
  - recv_bytes: Amount of data received during the sampling period, in bytes
  - recv_packets: Number of packets received during the sampling period
  - recv_acks: Number of acks received during the sampling period
  - wait_data_times: Number of times waited during the sampling period due to data not arriving
  - wait_data_timeout: Number of times waited during the sampling period due to data not arriving timeout

The new information above is compared with the content output by the [EXPLAIN](EXPLAIN) statement before enabling the setting, and executing the [EXPLAIN](EXPLAIN) statement after enabling the setting will also include the above new information.

***Example***

```sql
SET AUTOTRACE ON EXPLAIN;
```

### 3. SET AUTOTRACE ON STATISTICS

Generates a trace report and outputs the execution results and SQL execution statistics (statistics are recorded only when the STATISTICS_LEVEL parameter is set to 'ALL').

With this setting enabled, subsequent DML statements will output resource consumption data such as the size of the redo log generated, physical reads, consistent reads, and recursive calls.

***Example***

```sql
SET AUTOTRACE ON STATISTICS;
```

### 4. SET AUTOTRACE ON

Generates a trace report and outputs the execution results, execution plans, and execution statistics.

***Example***

```sql
SET AUTOTRACE ON;
```

### 5. SET AUTOTRACE TRACEONLY

Generates a trace report without outputting the execution results of the statement, only outputting the execution plan and execution statistics.

***Example***

```sql
SET AUTOTRACE TRACEONLY;
```
