General Description
----

The ALTER TABLESPACE statement is used to change the properties of an existing tablespace.

In ISC Distributed Cluster Deployment, when executing this statement, the system checks for any abnormal unrecovered DDL statements. If any exist, an error will be reported, and execution of this statement must wait until the corresponding DDL successfully recovers.

Statement Definition
----

**alter tablespace::=**

```ebnf+diagram
syntax::= ALTER TABLESPACE tablespace_name (datafile_clause|
databucket_clause|
shrink_clause|
offline_clause|
ONLINE|
rename_clause)
```

**[datafile\_clause](#datafiletempfileclauses)::=**

```ebnf+diagram
syntax::= ADD (DATAFILE|TEMPFILE) [(file_specification) {"," (file_specification)}]
| DROP (DATAFILE|TEMPFILE) file_name
```

**[file\_specification](#filespecification)::=**

```ebnf+diagram
syntax::= "'file_name'" SIZE size_clause [AUTOEXTEND (OFF|(ON [NEXT size_clause] [MAXSIZE (UNLIMITED|size_clause)]))] [PARALLEL parallel]
```

**[databucket_clause](#databucketclause)::=**

```ebnf+diagram
syntax::= add_databucket_clause | alter_databucket_clause | drop_databucket_clause
```

**[add_databucket_clause](#adddatabucketclause)::=**

```ebnf+diagram
syntax::= ADD DATABUCKET ((bucket_clause) {"," (bucket_clause)})
```

**[bucket_clause](#bucketclause)::=**

```ebnf+diagram
syntax::= "'bucket_name'" [s3_bucket_clause] MAXSIZE size_clause
```

**[s3_bucket_clause](#s3bucketclause)::=**

```ebnf+diagram
syntax::= S3 "(" URL "'url'" ["," REGION "'region'"] "," ACCESS KEY "'access_key'" "," SECRET KEY "'secret_key'" ")"
```

**[alter_databucket_clause](#alterdatabucketclause)::=**

```ebnf+diagram
syntax::= ALTER DATABUCKET "'bucket_name'" (READONLY | READWRITE)
```

**[drop_databucket_clause](#dropdatabucketclause)::=**

```ebnf+diagram
syntax::= DROP DATABUCKET "'bucket_name'"
```

**[shrink_clause](#shrinkclause)::=**

```ebnf+diagram
syntax::= SHRINK SPACE [KEEP size_clause]
```

**[offline\_clause](#offlineclause)::=**

```ebnf+diagram
syntax::= OFFLINE [NORMAL|TEMPORARY|IMMEDIATE]
```

**[rename\_clause](#renameclause)::=**

```ebnf+diagram
syntax::= RENAME TO space_name
```

### 1. datafile\_clause

This statement is used to modify the data files of a tablespace.

In ISC Distributed Cluster Deployment, adding/removing data files is only allowed for tablespaces created by the CREATE TABLESPACE statement. If a node failure occurs when modifying a data file of a tablespace, the recovery measures can be found in the [User Tablespace Management](../../All Manuals/Database Administration/Tablespace Management/General Tablespace Management) section.

#### 1.1. add (datafile|tempfile)

Add one or more data files to the tablespace (temporary files must use the TEMPFILE keyword).

In YAC Deployment, when local temporary tablespaces or local SWAP tablespaces use local disk paths, adding one file equates to adding a group of files. The number of files in each group equals the number of cluster instances.

<span id="filespecification" name="filespecification" class="yaslink"></span>

For the description of file_specification, please refer to [CREATE TABLESPACE](CREATE TABLESPACE).

When file_specification is not specified, the system automatically creates a data file according to the following rules:

- The file name is generated by combining the tablespace name and the sequence number of the data file in the tablespace, such as: tablespace_name1, tablespace_name2..., and is uniformly converted to uppercase.
- The default size of the file is 8192 BLOCKS, with the file path being the default data file path of the system.
- For non-MEMORY MAPPED tablespaces, the default file has automatic extension enabled, with next set to 8192 blocks and maxsize set to 64MB.
- If there is no explicit specification of extent allocation, the default allocation method for extents is automatic allocation by the system.

#### 1.2. drop (datafile|tempfile)

Delete a data file from the tablespace (temporary files must use the TEMPFILE keyword).

In YAC Deployment, when local temporary tablespaces or local SWAP tablespaces use local disk paths, deleting one file equates to deleting a group of files. The number of files in each group corresponds to the number of cluster instances.

The rules for deleting tablespace files are as follows:

- Deleting the first data file specified when creating the tablespace and non-ONLINE data files is not allowed.
- Deleting a data file from the UNDO tablespace is not allowed.
- Deleting a data file from the default SWAP tablespace is not allowed.
- To delete shadow files via DROP TEMPFILE, ensure that the database where the temporary file was created is the current primary database (if not, switch to the primary database first) and execute the DROP TEMPFILE statement on that primary database. Other standby databases will clean up the shadow records only after they receive the DROP TEMPFILE redo.

> **Note**: 
>
> After the data file of a MEMORY MAPPED tablespace is deleted, the internal ID and global ID of that file in the tablespace cannot be reused until the tablespace is deleted and the database is restarted.
>
> When adding a data file causes the internal ID of the file to reach the limit of the tablespace (63), deleting existing files will also not allow adding new data files to that tablespace.
>
> If a database outage occurs during the deletion of the data file, there may be residual files on the disk after restart, which need to be manually deleted.

***Example*** for Standalone Deployment and YAC Deployment

```sql
ALTER TABLESPACE SYSTEM ADD DATAFILE 'sys1' SIZE 4M AUTOEXTEND ON NEXT 4M MAXSIZE 1G;
 
ALTER TABLESPACE yashan ADD DATAFILE 'yashan_add1' SIZE 4M AUTOEXTEND ON NEXT 4M MAXSIZE 1G;

ALTER TABLESPACE yashan ADD DATAFILE 'yashan_add2' SIZE 4M AUTOEXTEND ON NEXT 4M MAXSIZE 1G PARALLEL 4;

ALTER TABLESPACE yashan ADD DATAFILE;
 
ALTER TABLESPACE SYSTEM DROP DATAFILE 'sys1';
 
ALTER TABLESPACE yashan DROP DATAFILE 'yashan_add1';
```

### 2. databucket\_clause

This statement is used to modify the databucket (data bucket) information of the tablespace.

<span id="adddatabucketclause" name="adddatabucketclause" class="yaslink"></span>

#### 2.1. add\_databucket\_clause

Add databuckets to the tablespace, allowing multiple to be mounted at the same time, separated by commas. The description and constraints for newly created databuckets are the same as those in the [databucket_clause](CREATE TABLESPACE.html#databucketclause) of CREATE TABLESPACE.

<span id="bucketclause" name="bucketclause" class="yaslink"></span>

##### 2.1.1. bucket\_clause

Described in the [databucket_clause](CREATE TABLESPACE.html#databucketclause) of CREATE TABLESPACE.

<span id="s3bucketclause" name="s3bucketclause" class="yaslink"></span>

###### 2.1.1.1. s3\_bucket\_clause

Described in the [s3_bucket_clause](CREATE TABLESPACE.html#s3bucketclause) of CREATE TABLESPACE.

***Example*** for Standalone Deployment and ISC Distributed Cluster Deployment

```sql
ALTER TABLESPACE lsc_tb ADD DATABUCKET '?/local_fs/lscfile_add3' MAXSIZE 1G;
```

<span id="alterdatabucketclause" name="alterdatabucketclause" class="yaslink"></span>

#### 2.2. alter\_databucket\_clause

This statement is used to modify the read/write properties of the databucket. The created databuckets are by default read/write.

##### 2.2.1. bucket\_name

Described as related to bucket_name in the [bucket_clause](CREATE TABLESPACE.html#bucketclause) of CREATE TABLESPACE.

##### 2.2.2. readonly|readwrite

readonly indicates read-only, while readwrite indicates read/write.

Note that once the databucket is changed to read-only, it does not support any form of write operation, but DML statements executed by users (excluding Bulkload operations) are not affected. During a Bulkload operation, if there are no writable databuckets under the tablespace, an error will occur due to the need to generate SCOL data.

***Example*** for Standalone Deployment

```sql
ALTER TABLESPACE lsc_tb ALTER DATABUCKET '?/local_fs/lscfile_add3' READONLY;
```

<span id="dropdatabucketclause" name="dropdatabucketclause" class="yaslink"></span>

#### 2.3. drop\_databucket\_clause

Delete a particular databucket from the tablespace, only one databucket can be specified for deletion at a time.

##### 2.3.1. bucket\_name

Described in the [alter_databucket_clause](#alterdatabucketclause).

***Example*** for Standalone Deployment

```sql
ALTER TABLESPACE lsc_tb DROP DATABUCKET '?/local_fs/lscfile_add3';
```

<span id="shrinkclause" name="shrinkclause" class="yaslink"></span>

### 3. shrink\_clause

This statement is used to reclaim free space based on the space utilization of each data file, shrinking the size of the tablespace.

In YAC Deployment, execution of shrink_clause is not allowed.

> **Note**: 
>
>- The UNDO tablespace cannot execute this statement.
>- Shrinking SWAP and TEMP tablespaces on the primary database will not synchronize to the standby database.

#### 3.1. keep size\_clause

Shrink the tablespace to a specified size. If the actual usage of the tablespace exceeds this size, the shrink operation will fail and return an error.

If KEEP is not specified, the system will maximize the tablespace shrink.

***Example*** for Standalone Deployment and ISC Distributed Cluster Deployment

```sql
ALTER TABLESPACE SYSTEM SHRINK SPACE KEEP 100M;
 
ALTER TABLESPACE SYSTEM SHRINK SPACE;
```

<span id="offlineclause" name="offlineclause" class="yaslink"></span>

### 4. offline\_clause

Change the tablespace to offline status. This operation is generally applied in the following business scenarios:

- If some data in the database is no longer open for access, its corresponding tablespace can be set offline.
- When renaming or reallocating data files within the tablespace, setting the tablespace offline will take all associated data files offline.

Once a tablespace is offline, all data files within it will be non-readable and non-writable, and DDL operations such as adding or deleting data files cannot be performed on that tablespace.

Built-in tablespaces like SYSTEM/SYSAUX/UNDO/SWAP/TEMPORARY cannot be set offline.

In YAC Deployment, execution of offline_clause is not allowed.

> **Note**: 
>
> An offline tablespace and its data files are still part of the database, hence no tablespace or data file with the same name can be created.

#### 4.1. normal| temporary | immediate

The offline option can be omitted and defaults to NORMAL.

OFFLINE NORMAL: The tablespace and data files will only be taken offline if all data files are online; otherwise, an error will be raised.

OFFLINE TEMPORARY: This allows for offline data files in the tablespace, only taking online data files offline.

OFFLINE IMMEDIATE: Data files that are not offline are taken offline immediately, which may lead to inconsistent states as archive or redo logs may not have fully applied to the data files. Thus, these offline data files cannot be brought back online directly. The *yasrman* tool must be used to execute a CONSISTENCY RECOVER for that tablespace before bringing it online. Refer to the *yasrman* tool's recover command [recover](../../All Manuals/Tools Guide/yasrman/User Guide for yasrman/RECOVER). When the database is not in archiving mode, this option cannot be specified for the offline operation.

***Example*** for Standalone Deployment and ISC Distributed Cluster Deployment

```sql
ALTER TABLESPACE yashan OFFLINE;
 
ALTER TABLESPACE yashan1 OFFLINE NORMAL;

ALTER TABLESPACE yashan2 OFFLINE TEMPORARY;

ALTER TABLESPACE yashan3 OFFLINE IMMEDIATE;
```

### 5. online

Change an offline tablespace back to online status, making it available again.

The shadow state temporary files do not have physical files and cannot be taken online.

This operation will bring the tablespace and all associated data files online. If there are data files that cannot be brought online, the execution will fail and return an error.

In YAC Deployment, execution of online is not allowed.

> **Note**: 
>
> In primary/standby deployment modes, after executing OFFLINE IMMEDIATE for a tablespace, it must be brought ONLINE on the instance that executed OFFLINE, otherwise it may cause data inconsistencies or unavailability in the standby database.

***Example*** for Standalone Deployment and ISC Distributed Cluster Deployment

```sql
ALTER TABLESPACE yashan ONLINE;
```

<span id="renameclause" name="renameclause" class="yaslink"></span>

### 6. rename\_clause

This statement is used to rename a tablespace or a data file, with the following restrictions:

- It is not allowed to rename a tablespace to an existing tablespace name.
- It is not allowed to use this statement to rename built-in tablespaces.
- It is not allowed to rename an OFFLINE tablespace using this statement.
- It is not allowed to rename a SWAP tablespace that is currently in use; to rename it, first modify the DEFAULT_SWAP_TABLESPACE configuration parameter, and then perform the rename operation.
- In ISC Distributed Cluster Deployment, renaming of tablespaces or data files is not allowed.

***Example*** for Standalone Deployment and YAC Deployment

```sql
ALTER TABLESPACE yashan1 RENAME TO yashanDb;
```
