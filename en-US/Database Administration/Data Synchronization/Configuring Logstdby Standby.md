To configure a logical standby database, you need to first create the standby database (which is a physical standby database by default) and then execute related operations to convert it to a logical standby database.

## Prerequisites

- The current environment is a Standalone Deployment (primary/standby) deployment.

- The table types, data types, etc. of the primary database must meet the [logical replication scope](00Data Synchronization.html#scope).

- Ensure that the current environment and the environment after configuring the logical standby database still meet the [operating requirements for logical standby databases](00Data Synchronization.html#requirement).

## Steps

### Step 1: Create Standby Database

Please refer to the standby database preparation operations in [scalability of standby databases](../../Installation and Upgrade/Scalability/Scalability of Standalone Deployment/Standbys Scaling.html#Scalingbysql) to create the standby database. At this time, the standby database is in a physical standby database state.

### Step 2: Add Standby Log Files to the Standby Database

Standby log files are used to store redo logs generated by the logical standby database. You need to plan for the space usage, file paths, and number of standby log files before constructing the logical standby database.

Each logical standby database requires at least 3 standby log files. If standby log files have been configured in the current environment, this operation can be skipped.

Execute the following statements in the primary database to create standby log files:

```sql
ALTER DATABASE ADD STANDBY LOGFILE 'REDO11' SIZE 128M;
ALTER DATABASE ADD STANDBY LOGFILE 'REDO12' SIZE 128M;
ALTER DATABASE ADD STANDBY LOGFILE 'REDO13' SIZE 128M;
```

### Step 3: Stop Physical Apply (redoApply) on the Standby Database

Before converting the physical standby database to a logical standby database, you need to stop the redo apply on the physical standby database to avoid interference with the subsequent construction of the logical standby database.

Execute the following statement on the standby database to stop the redo apply:

```sql
ALTER DATABASE RECOVER MANAGED STANDBY DATABASE CANCEL;
```

### Step 4: Execute DBMS\_LOGSTDBY.BUILD Operation

1. Execute DBMS_LOGSTDBY.BUILD operation on the primary database:

   - You need to wait for all active transactions to complete before executing DBMS_LOGSTDBY.BUILD. Long-running transactions in the primary database can affect the execution efficiency of this command.

   - After executing DBMS_LOGSTDBY.BUILD, the primary database will automatically enable the database-level supplemental logging, and the logging mode will be PRIMARY KEY.

   ```sql
   EXECUTE DBMS_LOGSTDBY.BUILD;
   ```

2. Check to confirm that the BUILD operation has been synchronized to the standby database.

   ```sql
   -- Check the status of the standby database and synchronization status.
   SELECT DEST_ID, CONNECTION, STATUS, SYNCHRONIZED FROM V$ARCHIVE_DEST_STATUS;
   ```

   If the standby database is in a synchronized state (SYNCHRONIZED is TRUE), it indicates that the build operation has been synchronized to the standby database. Otherwise, you need to obtain the current log flush point and wait for the standby database to synchronize to that flush point.

   ```sql
   -- Get the current log flush point of the primary database
   SELECT FLUSH_POINT FROM V$DATABASE;

   -- Wait for the standby database logs to synchronize to this log point
   -- Get the current log receiving point of the standby database
   SELECT DEST_ID, CONNECTION, STATUS, RECEIVED_SEQ#, RECEIVED_LFN FROM V$ARCHIVE_DEST_STATUS;
   ```

### Step 5: Convert Standby Database Type

Restart the standby database to the mount stage and execute related statements to convert it to a logical standby database.

- Scenario 1: Build a generic logical standby database, the role of the standby database will change to LOGICAL STANDBY, and the database's DB_NAME and DBID will also change.

   ```sql
   -- Shutdown database
   SHUTDOWN IMMEDIATE;

   -- Start database
   yasdb mount &

   -- Execute switch operation
   ALTER DATABASE RECOVER TO LOGICAL STANDBY new_db_name;

   -- Open database
   ALTER DATABASE OPEN RESETLOGS;
   ```

- Scenario 2: Rolling upgrade scenario, the role of the standby database will change to LOGICAL STANDBY, and the database's DB_NAME and DBID will not change.

   ```sql
   -- Shutdown database
   SHUTDOWN IMMEDIATE;

   -- Start database
   yasdb mount &

   -- Execute switch operation
   ALTER DATABASE RECOVER TO LOGICAL STANDBY KEEP IDENTITY;

   -- Open database
   ALTER DATABASE OPEN;
   ```

### Step 6: Enable Logical Apply (SQL Apply) on the Logical Standby Database

By default, logical apply functionality is not enabled on a logical standby database. You need to execute the following statement on the standby database to enable logical apply (i.e., to apply redo data to the logical standby database).

```sql
ALTER DATABASE START LOGICAL STANDBY APPLY IMMEDIATE;
```
