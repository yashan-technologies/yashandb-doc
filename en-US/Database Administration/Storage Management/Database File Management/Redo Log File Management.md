The redo log files of YashanDB are used to record the physical logs generated by the database, which can be used for database crash recovery and primary-standby replication.

## Viewing redo log files

### Check physical files

Log into the database server using the installation user and navigate to the path where the redo log files are stored. The redo log files are stored in the $YASDB_DATA/dbfiles directory.

```shell
$ cd $YASDB_DATA/dbfiles
$ ls -lrt redo*
total 15456
-rw-r----- 1 yashan yashan 104857600 Jun 16 09:49 redo2
-rw-r----- 1 yashan yashan 104857600 Jun 16 09:49 redo3
-rw-r----- 1 yashan yashan 104857600 Jun 17 11:45 redo0
-rw-r----- 1 yashan yashan 104857600 Jun 18 15:15 redo1
```

### View through the view

The information of redo log files can be viewed through the [V$LOGFILE](../../../Reference Manual/System Views/Dynamic Performance Views/V$LOGFILE) view.



```sql
SELECT thread#,id,name,block_size,block_count,used_blocks,sequence#,status FROM V$LOGFILE;

THREAD#           ID NAME                                                               BLOCK_SIZE           BLOCK_COUNT           USED_BLOCKS    SEQUENCE# STATUS
------- ------------ ---------------------------------------- ------------ --------------------- --------------------- ------------ -----------------
      1            0 $YASDB_DATA/dbfiles/redo1                           4096                 32768                  7482            1 INACTIVE
      1            1 $YASDB_DATA/dbfiles/redo2                           4096                 32768                 32768            2 INACTIVE
      1            2 $YASDB_DATA/dbfiles/redo3                           4096                 32768                  8200            3 CURRENT
```


The status of the redo log files includes NEW, CURRENT, ACTIVE, and INACTIVE, which are described in detail in the table below.

|Status |Description |
|--------------------|---------------------|
| NEW                  | A new file that has not been used.  |
| CURRENT              | The file currently being written to. <br/>When the file is full (i.e., automatic switching) or switched manually, a NEW or INACTIVE file will be selected as the next CURRENT file, and the original CURRENT file will become ACTIVE. <br/>If no NEW or INACTIVE files exist, a checkpoint will be triggered.  |
| ACTIVE               | A file that has just switched from CURRENT status, which may contain some content that has not yet been written to disk, or has not yet been archived (if archiving mode is enabled). <br/>After executing the checkpoint and waiting for archiving to complete (if archiving mode is enabled), it will become INACTIVE.  |
| INACTIVE             | The file content has been fully written to disk and has been archived (if archiving mode is enabled).  |

## Managing redo log files

YashanDB requires at least three redo log files to coexist, and by default, creates three named redo1/redo2/redo3, each with a size of 128M and a BLOCKSIZE of 4K.

The redo log files are cyclically reused, and their quantity and size are related to the database performance. The size of redo logs cannot be directly expanded (it needs to be achieved by adding new large files and deleting the original small files). Reasonable planning should be made according to business needs. For more details, please refer to [Database Configuration Tuning](../../../Performance Tuning/Database Performance Fundamentals/Database Configuration Tuning).

In YAC/Distributed Cluster Deployment, the redo log files are exclusive to each instance. When adding or deleting redo log files, you need to connect to the corresponding instance to operate on its exclusive files.

### Adding redo log files

If the initial configuration cannot meet business/performance requirements, you can customize the addition of redo log files using the [ALTER DATABASE](../../../Development Guide/SQL Reference Manual/SQL Statements/ALTER DATABASE.md#add_logfile) statement.

#### Preconditions

- Adding redo log files requires the database to be in the OPEN state.

- The configuration of redo log files should be planned as needed:

    - filename: The file name, which can be incrementally numbered according to existing files.

    - SIZE: The minimum size of the redo log file is influenced by the parameters DB_BLOCK_SIZE, MAX_SESSIONS, and REDO_BUFFER_SIZE. The minimum value can be referenced with the formula: `DB_BLOCK_SIZE * MAX_SESSIONS * 8 + REDO_BUFFER_SIZE / 2`. Please evaluate and determine an appropriate size based on actual business requirements and the calculated value derived from expected parameter settings.

    - BLOCKSIZE: The block size of the file, which can be omitted (defaulting to 4096), and must be specified as an integer multiple of 512 (if not an integer multiple, it will automatically round up upon creation).

#### Operational Steps

1. Connect and log in to the database as a DBA user.
    ```shell
    $ yasql sales/********@192.168.1.2:1688
    YashanDB SQL Enterprise Edition Release {version_number} x86_64

    Connected to:
    YashanDB Server Enterprise Edition Release {version_number} x86_64 - Linux

    SQL> 
    ```


2. Check existing redo log files.

    
  
  ```sql
  SELECT thread#,id,name,block_size,block_count,used_blocks,sequence#,status FROM V$LOGFILE;
  
  THREAD#           ID NAME                                                               BLOCK_SIZE           BLOCK_COUNT           USED_BLOCKS    SEQUENCE# STATUS
  ------- ------------ ---------------------------------------- ------------ --------------------- --------------------- ------------ -----------------
        1            0 $YASDB_DATA/dbfiles/redo1                           4096                 32768                  7482            1 INACTIVE
        1            1 $YASDB_DATA/dbfiles/redo2                           4096                 32768                 32768            2 INACTIVE
        1            2 $YASDB_DATA/dbfiles/redo3                           4096                 32768                  8200            3 CURRENT
  ```
  

3. Execute the ALTER DATABASE ADD LOGFILE statement to add new redo log files.

    ```sql
    ALTER DATABASE ADD LOGFILE ('redo4' SIZE 200M,'redo5' SIZE 64G BLOCKSIZE 4k,'redo6' SIZE 64G PARALLEL 8);

    SELECT thread#,id,name,block_size,block_count,used_blocks,sequence#,status FROM V$LOGFILE;

    THREAD#           ID NAME                                                               BLOCK_SIZE           BLOCK_COUNT           USED_BLOCKS    SEQUENCE# STATUS
    ------- ------------ ---------------------------------------- ------------ --------------------- --------------------- ------------ -----------------
          1            0 $YASDB_DATA/dbfiles/redo1                           4096                 32768                  7482            1 INACTIVE
          1            1 $YASDB_DATA/dbfiles/redo2                           4096                 32768                 32768            2 ACTIVE
          1            2 $YASDB_DATA/dbfiles/redo3                           4096                 32768                  8200            3 CURRENT
          1            3 $YASDB_DATA/dbfiles/redo4                          4096                 51200                     0            0 NEW
          1            4 $YASDB_DATA/dbfiles/redo5                           4096              16777216                     0            0 NEW
          1            5 $YASDB_DATA/dbfiles/redo6                           4096              16777216                     0            0 NEW
    ```

### Switching redo log files

The switching of redo log files is classified into:

- Automatic switching: When the CURRENT status of the redo log file is full, the database will automatically select a file in the NEW or INACTIVE status for switching. If no NEW or INACTIVE files exist, a checkpoint will be triggered.

- Manual switching:

    - Single switching: Execute the [ALTER SYSTEM SWITCH LOGFILE](../../../Development Guide/SQL Reference Manual/SQL Statements/ALTER SYSTEM.md#switch_logfile) statement to force the switching of the redo log file; even if the database is in archiving mode, this operation will not automatically archive.

    - Archive + switch: When the database is in archiving mode, execute the [ALTER SYSTEM ARCHIVE LOG CURRENT](../../../Development Guide/SQL Reference Manual/SQL Statements/ALTER SYSTEM.md#archive_logfile) statement to archive the currently CURRENT status redo log file while switching the redo log file.

```sql
-- Method 1: Force switch
ALTER SYSTEM SWITCH LOGFILE;

-- Method 2: In archiving mode, archive + switch
-- Check the current database's archiving mode 
SELECT database_name,log_mode FROM V$DATABASE;

DATABASE_NAME    LOG_MODE          
---------------- -----------------
yashandb            ARCHIVELOG      
-- Ensure LOG_MODE = ARCHIVELOG before executing subsequent operations
ALTER SYSTEM ARCHIVE LOG CURRENT;

-- Check redo log file information
SELECT thread#,id,name,block_size,block_count,used_blocks,sequence#,status FROM V$LOGFILE;

THREAD#           ID NAME                                                               BLOCK_SIZE           BLOCK_COUNT           USED_BLOCKS    SEQUENCE# STATUS
------- ------------ ---------------------------------------- ------------ --------------------- --------------------- ------------ -----------------
      1            0 $YASDB_DATA/dbfiles/redo1                           4096                 32768                  7482            1 INACTIVE
      1            1 $YASDB_DATA/dbfiles/redo2                           4096                 32768                 32768            2 INACTIVE
      1            2 $YASDB_DATA/dbfiles/redo3                           4096                 32768                  8200            3 ACTIVE
      1            3 $YASDB_DATA/dbfiles/redo4                          4096                 51200                     2            4 CURRENT
      1            4 $YASDB_DATA/dbfiles/redo5                           4096              16777216                     0            0 NEW
      1            5 $YASDB_DATA/dbfiles/redo6                           4096              16777216                     0            0 NEW
```

### Deleting redo log files

If the following situations occur, you can use the [ALTER DATABASE](../../../Development Guide/SQL Reference Manual/SQL Statements/ALTER DATABASE.md#drop_logfile) statement to delete redo logs:

- When a disk failure occurs, deleting the redo log files on the faulty disk can prevent writing to inaccessible files.

- When the redo log files are stored in inappropriate locations.

- By increasing larger redo log files + deleting existing smaller files to expand the capacity of redo files.

> **Caution**: 
>
> To ensure the normal operation of the database and data security, only NEW or INACTIVE status redo log files can be directly deleted.

#### Preconditions

Deleting redo log files requires the database to be in the OPEN state.

#### Operational Steps

1. Connect and log in to the database as a DBA user.
    ```shell
    $ yasql sales/********@192.168.1.2:1688
    YashanDB SQL Enterprise Edition Release {version_number} x86_64

    Connected to:
    YashanDB Server Enterprise Edition Release {version_number} x86_64 - Linux

    SQL> 
    ```


2. Check existing redo log files.

    ```sql
    SELECT thread#,id,name,block_size,block_count,used_blocks,sequence#,status FROM V$LOGFILE;

    THREAD#           ID NAME                                                               BLOCK_SIZE           BLOCK_COUNT           USED_BLOCKS    SEQUENCE# STATUS
    ------- ------------ ---------------------------------------- ------------ --------------------- --------------------- ------------ -----------------
          1            0 $YASDB_DATA/dbfiles/redo1                           4096                 32768                  7482            1 INACTIVE
          1            1 $YASDB_DATA/dbfiles/redo2                           4096                 32768                 32768            2 INACTIVE
          1            2 $YASDB_DATA/dbfiles/redo3                           4096                 32768                  8200            3 ACTIVE
          1            3 $YASDB_DATA/dbfiles/redo4                          4096                 51200                     2            4 CURRENT
          1            4 $YASDB_DATA/dbfiles/redo5                           4096              16777216                     0            0 NEW
          1            5 $YASDB_DATA/dbfiles/redo6                           4096              16777216                     0            0 NEW
    ```
