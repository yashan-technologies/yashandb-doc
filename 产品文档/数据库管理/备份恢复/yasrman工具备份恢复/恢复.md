通过[yasrman](../../../工具手册/yasrman/00yasrman)工具可以执行如下恢复操作：

- 恢复整库：适用于所有部署形态，单机部署和共享集群部署的命令/用法完全一致。根据具体操作细节又可分为完整恢复整库和基于时间点恢复整库。

- 恢复表空间：适用于单机部署，若为主备高可用环境则只能连接主库执行相关操作。

- 恢复归档日志：适用于单机部署和共享集群部署，且命令/用法完全一致。

执行恢复操作的数据库版本和部署状态（节点个数、节点监听地址、路径等信息）需与生成备份集的数据库完全一致。

当需恢复的数据量大或希望提升恢复效率时，可适当增大并发度，并发度默认为2。

恢复过程中，可以通过$YASDB_DATA/log/run/run.log运行日志查看恢复过程的详细日志。

> **Caution**:
> 
> 在双复制组主备部署环境中，执行数据库恢复操作后的实例均会成为主库，若目标实例为备库且原主库存活则不可对该实例执行恢复操作，否则会出现双主导致部署状态或数据异常。如需重建备库请执行备库BUILD操作。

## 恢复整库

完整恢复整库：指将全库备份集中的备份文件，解压、解密恢复到数据库目录，然后回放备份集中的归档日志将数据库恢复到一致性状态，可将数据库完整恢复到备份时刻。

基于时间点的恢复（PITR）：指基于数据库备份集还原的数据库文件和归档日志文件将数据库恢复到备份时间点至最新时间点期间某一时刻的状态。

### 操作说明

- 整库恢复仅SYS用户才可执行。

- 如果数据库备份集采用加密备份，恢复时需指定解密关键字及其解密密码。

- 共享集群部署中，只能在主实例（V$INSTANCE视图中INSTANCE_ROLE字段为MASTER_ROLE的实例）上执行数据库恢复操作。

- 如果LSC表在备份集后生成了slice文件，在以下场景基于时间点恢复整库时可能导致恢复后该LSC表存在数据不一致现象：

  - 数据库原来的slice文件全部存在，但是使用老的时间点恢复，此时该LSC表会多出部分slice文件。

  - 数据库原来的slice文件被清理，使用基于时间点的恢复，LSC表可能丢失存储在slice文件中的数据。

- 恢复前数据库环境准备：

  - 数据库实例处于NOMOUNT阶段。

  - 需清空所有节点上实例的数据文件目录、归档文件目录以及bucket目录。

  - 如果备份集中存在加密对象，需先打开对应的密钥钱包文件，再进行恢复操作。

### 完整恢复整库

示例（单机、共享集群部署）

```shell
$ yasrman sys/sys@192.168.1.2:1688 -c "restore database from tag 'full_1'" -D /home/yashan/catalog
```

示例（分布式部署）

```shell
$ yasrman sys/sys@192.168.1.2:1688 -c "restore cluster from tag 'full_1'" -D /home/yashan/catalog
```

### 基于时间点恢复整库

如果归档日志不够或指定的时间点（或SCN）过大，回放完毕后也将无法达到指定的时间点，数据库会报错，可以查询V$DATABASE视图的current_scn字段查看实际回放进度。如果有可用的归档日志副本，可以注册归档，重新执行restore操作。如果没有多余的归档，当前时间点是唯一的选择，继续执行resetlogs操作。

示例（单机、共享集群部署）

```shell
# 指定时间戳和数据库备份集
$ yasrman sys/sys@192.168.1.2:1688 -c "restore database from tag 'full_1' until time '2023-11-13'" -D /home/yashan/catalog

# 指定时间戳和数据库ID
$ yasrman sys/sys@192.168.1.2:1688 -c "restore database dbid 12573483 until time '2023-11-13 18:55:00'" -D /home/yashan/catalog

# 指定SCN和数据库备份集
$ yasrman sys/sys@192.168.1.2:1688 -c "restore database from tag 'full_1' until scn 499833430256541696" -D /home/yashan/catalog
```

## 表空间恢复

表空间恢复是指将对应表空间备份集中的备份文件，解压、解密恢复到数据库目录，然后回放备份集中的归档日志将表空间恢复到一致性状态，可将表空间完整恢复到备份时刻。

表空间恢复操作仅适用于单机部署，若为主备高可用环境则只能连接主库执行相关操作。

### 操作说明

- 表空间恢复仅SYS超级用户或拥有SYSDBA、SYSBACKUP权限的用户才可执行。

- 如果数据库备份集采用加密备份，恢复时需指定解密关键字及其解密密码。

- 恢复前数据库环境准备：

  - 数据库已启动至MOUNT或OPEN阶段。
  
  - 目标表空间必须处于OFFLINE状态，该表空间下的所有数据文件需处于OFFLINE或RECOVER状态。

  - 如果备份集中存在加密对象，需先打开对应的密钥钱包文件，再进行恢复操作。

### 操作步骤

1. 执行RESTORE TABLESPACE基于指定的表空间备份集还原出相应文件。

2. 执行RECOVER TABLESPACE对表空间相关文件执行一致性恢复。

示例（单机部署）

```shell
-- 1. 执行RESTORE TABLESPACE
$ yasrman sys/sys@192.168.1.2:1688 -c "restore tablespace spc_test from tag 'spc_test_bak' " -D /home/yashan/catalog
 
-- 2. 执行RECOVER TABLESPACE
$ yasrman sys/sys@192.168.1.2:1688 -c "recover tablespace spc_test maxsize 1280M " -D /home/yashan/catalog
```

## 归档恢复

归档恢复是指在数据库完整恢复（RESTORE DATABASE）后但暂未进行日志恢复（RECOVER DATABASE）时，将归档备份集中的文件恢复到数据库的归档目录并注册到数据库中，尽可能补充数据库备份集中缺失的归档日志，使数据库恢复更多的数据。

恢复范围指定方式以及压缩、加密等通用备份属性与使用SQL语句备份一致。

### 操作说明

- 共享集群部署中，只能在主实例（V$INSTANCE视图中INSTANCE_ROLE字段为MASTER_ROLE的实例）上执行归档恢复操作。

- 归档日志只能恢复成现有归档备份集的全集或子集，且指定恢复范围的方式（SCN、SEQUENCE或时间）不受备份范围指定方式约束。

- 如果归档备份集采用加密备份，恢复时需指定DECRYPTION关键字及解密密码。
- 恢复前数据库环境准备：

  - 数据库已完成RESTORE DATABASE且启动至MOUNT阶段，但暂未执行RECOVER DATABASE。

  - 确保恢复归档日志文件的目标路径存在，省略TO destpath时默认恢复至ARCHIVE_LOCAL_DEST参数所配置的路径（默认值为$YASDB_DATA/archive）。

### 操作示例

示例（单机、共享集群部署）

```shell
$ yasrman sys/sys@192.168.1.2:1688 -c "restore archivelog all" -D /home/yashan/catalog

$ yasrman sys/sys@192.168.1.2:1688 -c "restore archivelog sequence between 10 and 20" -D /home/yashan/catalog
```
